## 链路总览

```
din(RGB888 112×103) ──► 高斯滤波（去高斯噪声）
   ──► 中值滤波（去椒盐脉冲，逐通道取中）
   ──► CSC（RGB→YCbCr，BT.601 ×256 定点；i_h/i_v_sync 接 0 仅透传）
   ──► 打包 24bit = {Y, Cb, Cr} ──► axis_fifo（速率匹配，2^14 深度）
   ──► 双线性放大 2 倍（Y/Cb/Cr 独立插值）──► YUV + o_valid + o_done
```

**两种尺寸链（`iverilog -DPAD` 切换）**：

| | crop 链（默认） | pad 链（-DPAD） |
|---|---|---|
| 行缓存 | line_buffer_3x3（crop） | **line_buffer_3x3_pad（replicate 全尺寸）** |
| 尺寸链 | 112×103→110×101→108×99→**216×198** | 112×103→112×103→112×103→**224×206（不缩水）** |
| 级间格式 | 直接级联（连续流兼容） | 级间需 **frame_sync_adapter**（见下） |
| 边缘 | 丢掉一圈 | 全尺寸参与滤波 |

**pad 版级联的关键（本次新增的工程点）**：pad 版行缓存**依赖输入带 blanking**（h-blank≥1、v-blank≥W+8），但 pad 版模块的输出是连续流（无行末/帧末空拍）——直接级联到下一个 pad 版模块时，下一级插不了 rflush/bflush。解法：级间插 `frame_sync_adapter`（带 512 深度小 FIFO 的 blanking 重生成器）：输入连续流先进 FIFO，读侧按行结构调度——每行读 W 个有效 → 停 HBLANK 拍 → 下一行，读完 H 行 → 停 VBLANK 拍 → 等下一帧。

- **溢出证明（为什么 512 深度就够）**：读侧只比写侧多"插空拍"的额外拍（≈ HBLANK×H = 206），帧末 VBLANK 在输入停止后发生不增加占用——最大占用 ≈206 < 512，远小于缩放模块需要的整帧缓冲（那是 4 倍速差）
- **调试血泪（v1 → v2）**：初版"零缓冲插空拍"在连续输入下必丢数据（插空拍期间输入照来）→ 必须带缓冲；用 axis_fifo 又踩"挂起 valid 与调度互等死锁"→ 最终用**组合读小 FIFO**（数据=mem[rptr]、valid=count>0）根治
- **参考模型坐标陷阱**：pad 版窗口是**中心模型**（w22 为中心，行 wr-1..wr+1），与 crop 版的右下角模型（wr-2..wr）不同——verify_chain 的 pad 参考必须切换窗口偏移，否则差 1 行（实测 19dB FAIL → 中心模型后 inf）

**面试表述**："crop 版级联会逐级缩水（每级 -2），多级滤波要用 pad 版；但 pad 版级联需要 blanking——上一级输出的连续流要经过 blanking 重生成（行末插 h-blank、帧末插 v-blank）才能喂下一级，这是 pad 版复用的隐藏成本。"

**设计意图**：两级滤波各司其职——高斯灭高斯噪声（强项 22.50dB 级）、中值灭椒盐脉冲（强项 26.18dB 级），混合噪声图经双滤波后显著净化，再转 YUV、放大 2 倍，全链路一次跑通。

## 工程要点（面试价值问题记录）

### 1. 为什么需要速率匹配 FIFO（本链路核心）

**问题**：高斯/中值/CSC 都是"每拍进 1 像素、每拍出 1 像素"的**无背压流水**（内部流水线无法暂停）；而缩放模块放大 2 倍时读侧消费慢（输出像素 = 输入×4），`in_ready` 必然周期性拉低反压。直接级联 → 前级照常输出、后级不收 → **数据丢失**。

**解法**：中间插同步 FIFO（深度 2^14 = 16384 > 一帧像素 10692）。不溢出证明：**任意时刻 FIFO 占用 ≤ 累计写入 ≤ 整帧像素数 < 深度**（读侧哪怕完全不消费也不丢）。

**面试表述**："流式级联里，无背压流水和带反压模块之间必须有速率匹配缓冲（FIFO/帧缓冲）——这是 AXI-Stream 生态的本质：tvalid/tready 握手 + 缓冲吸收速率差。深度取'写入方一帧的量'即可保证不溢出。"

### 2. FIFO valid 保持语义（实测踩坑，95 像素丢失）

**现象**：链路输出差 95 像素（42768→41904），缓存停在第 98 行，FIFO 已空（出队 10692 次 vs 缓存接收 10597 次）。

**根因**：初版 `m_tvalid <= rd_en`（valid 只打 1 拍）——当数据呈现拍恰好遇到消费者反压（tready=0），下一拍 valid 被清 0，**数据在 FIFO 与消费者之间悬空丢失**。95 = "FIFO 空→非空"转变次数（输入侧气泡打断流时出现）。

**修复**：valid 保持到"交付完成"：

```verilog
if (rd_en)        begin rdata_reg <= mem[rptr]; rvalid_reg <= 1'b1; end
else if (m_tready)     rvalid_reg <= 1'b0;   // 空闲且消费端就绪才清
```

**面试表述**："AXIS 的 tvalid 必须保持到 tvalid&&tready 同拍握手成功，不能只打一拍——反压时 valid 被清，数据就悬空丢了。"（这是 AXI-Stream 握手协议的经典考点。）

### 3. 多顶层复用的 include 管理

三个顶层（top_gaussian/top_median/bilinear_lb_top）内各自 `include 底层 → 级联时 line_buffer_3x3.v 重复声明编译报错。**解法**：链路目录内三个顶层副本去掉 include，底层由 top_chain.v **统一各 include 一次**（谁用了什么一目了然）。

**面试表述**："多模块复用时 include 要集中管理——顶层不要各自 include 底层，由集成层统一声明，避免重复定义。"

### 4. RGB 中值 = 逐通道中值（参考模型必须与 RTL 同构）

**现象**：中值级 PSNR 31.5dB FAIL，85% 像素不同；但单站 TB 全等 PASS。

**根因**：verify_chain.py 参考对 **24bit 像素整体排序取第 5**；而 RTL 是 3 个单通道 8bit 核，**R/G/B 分别独立取中值**再合成（RGB 中值滤波的标准做法！）——逐像素手算：R 中值来自像素 A、G 中值来自像素 B、B 中值来自像素 C。

**修复**：参考逐通道排序。教训：**参考模型的通道粒度必须与 RTL 结构一致**——这也是为什么"参考必须独立实现但与实现同构于同一算法语义"。

### 5. 尺寸链与 crop 收缩

```
112×103 → 高斯(110×101) → 中值(108×99) → ×2 = 216×198
```

高斯/中值各 -2 边缘（crop 版行缓存）——**多级滤波尺寸逐级收缩**，也是面试易错点："级联里 crop 会累积，全尺寸需求要用 pad 版（replicate）"（MeanFilter 已做 pad 变体）。

### 5b. pad 版行缓存到底在等什么：空拍的意义（刨根问底）

**疑问**：frame_sync_adapter 在行末/帧末强制把 valid 拉低几个周期——"不给下游输出数据"有啥用？空拍不是白等，它是给 pad 行缓存**执行内部动作的时间窗**。

**两个必须"借空拍"的内部动作**（line_buffer_3x3_pad 源码）：

```
rflush（行末右边缘）：触发条件 rflush_fire = rflush_pend && !valid_d2 && !bflush_dv
  —— 明确要求"这一拍没有新像素"。
  为什么：行末第 W 列窗口不是等数据来的，而是内部"再移一位"产生：
  把最右列像素重复移入移位寄存器，得到 (W-2, W-1, W-1) 窗口。
  这一步移位需要一个空闲拍——空闲拍 = 它做这次额外移位的"窗口期"。

bflush（帧末下边缘）：帧末要补一整行窗口（第 H 行），只读 BRAM 不接收输入，
  fcol 扫 0..W-1，需要帧末后一段"输入停止"的时间。
```

**没空拍的后果（具体到像素）**：输入是连续流时，`rflush_pend` 在行末置位后等 `!valid_d2` ——永远等不到 → 行末窗口永远产生不了 → **每行缺第 W 列** → 输出错位/少像素（这就是链路 D1 的现象）。

**那 pad 版自己的输出为什么是连续流？** 因为它把**输入的空拍"消化"成了输出窗口**：输入行末空拍那一拍，pad 内部正好做 rflush 动作，同时把产生的窗口从输出端送出去（matrix_valid 在那一拍也拉高）——从输出端看每拍都有一个窗口（行内 W-1 个 + 空拍那拍的 1 个 = 每行 W 个，连续）。**一句话：pad 版输入的空拍是"养料"，输出端看全是果实。**

**级联场景**：高斯 pad 输出是连续流（无空拍）→ 中值 pad 拿到"没有养料的连续流" → 它的 rflush/bflush 没时间窗 → 做不了。frame_sync_adapter 把连续流**重新切成**下一级需要的节奏：

```
高斯输出（连续 11536 窗口）
   ↓ 适配器（缓冲 + 行结构调度）
每行：W 个有效 → 2 拍空拍（给中值的 rflush 用）
帧末：再补 120 拍空拍（给中值的 bflush 用）
   ↓
中值 pad 拿到"带休息时间"的流 → rflush/bflush 正常执行
```

**大白话类比**：pad 行缓存 = 需要"中场休息"的球员——每踢完一行/一帧必须休息几个拍子，才能做那个特殊动作（重复最右列、补最后一行）。空拍 = 休息时间窗。连续流级联 = 不给休息直接上强度，特殊动作做不出来。适配器 = 中间的节奏教练，把前一棒的连续输出切成"行 + 休息 + 帧 + 大休息"。

**面试表述**："pad 版行缓存的 rflush/bflush 只能在输入空闲的拍执行（它借用空拍做额外的窗口移位），所以 pad 版**输入必须带 blanking**；而 pad 版输出把空拍消化成了输出窗口、是连续流——级联时下一级没有空拍可用，必须用适配器重新插入行末/帧末空拍，这是 pad 版复用的隐藏成本。"

### 6. YUV 域插值的数学等价性

双线性（及绝大多数插值）对 3 个通道**独立运算**，Y/Cb/Cr 打包成 24bit 与 RGB 完全等价——直接复用 v4 的 3 核，无需改缩放模块。**注意**：这是"通道独立插值"层面；真正的高级色度处理（如 4:2:0 色度重采样）是另一议题，本链路输入为 4:4:4 无此问题。

### 7. done 是脉冲：TB 用"出现过"判定

`o_done`（coord_gen done）是**1 拍脉冲**，TB 尾拍后再看电平已回落 → PASS 判定误判。**解法**：posedge 采样记录 `done_seen` 寄存器，判定用它。

**面试表述**：TB 里"脉冲完成信号"要么同步采样成寄存器、要么在脉冲期内判定——这是 FSM/TB 的常见疏漏。

| ② 中值滤波后 | **20.66 dB**（+0.9） | **20.72 dB**（+1.0） |
| ③ CSC 后（YUV→RGB 回看） | 18.23 dB | 18.19 dB |
| ④ 放大 2 倍后 | **18.69 dB（216×198）** | **18.63 dB（224×206 全尺寸）** |

**crop vs pad 结论**：内部区域恢复度基本一致（相差 ≤0.06dB，算法相同）；**pad 链的收益是输出全尺寸 224×206**——边缘一圈（replicate 填充）也参与滤波并被放大，不再逐级丢失，多级滤波/级联场景不缩水。

**两个 PSNR 的区别（面试常被问）**：
- 实现精度 = "设备自检"——证明 RTL 与理想算法位级一致（现在全 inf，任何改动让它掉出 inf 就是回归信号）
- 恢复度才是"图像质量"——13.59 → 20.66 dB 说明**两级滤波把混合噪声图拉回接近原图 21dB**；最终 18.7dB 的缺口主要来自 CSC 系数近似，而非滤波/放大
- 即便两者都是"PSNR"，比较对象不同（理想参考 vs 原图），语义完全不同——报告数字必须先说清参考是谁

**显示对比**：[chain_compare.png](chain_compare.png)（原图放大2倍 | 混合噪声图 | 链路结果 YUV→RGB，216×198）。

### 滤波顺序实验：中值→高斯 vs 高斯→中值（ORDER 参数实测）

两级滤波的组合顺序对混合噪声的恢复度影响显著（top_chain 的 `ORDER` 参数 + `iverilog -DSWAP` 跑出，verify_chain.py `--swap` 评估）：

| 链路位置 | ① 高斯→中值（默认） | ② 中值→高斯（实验） |
|---|---|---|
| 混合噪声图 | 13.59 dB | 13.59 dB |
| 第一级后 | 高斯 **19.74** | 中值 **23.92** |
| 第二级后 | 中值 20.66 | 高斯 23.51（−0.4） |
| CSC 后（转RGB） | 18.23 | 20.76 |
| **链路最终（放大2倍）** | **18.69** | **21.45（+2.76 dB）** |

**结论：先中值后高斯更优（+2.76 dB）**，理论依据两条：

1. **椒盐必须在"极值形态"时处理**：中值对 0/255 脉冲最强（窗口内 <5 个极值即精确剔除，+10dB 跃升）；若先被高斯抹成灰斑（中等偏差），中值无法识别，残留半死不活
2. **高斯噪声在未被处理时收益最大**：ORDER=1 里第二级高斯反而微降 0.4dB（23.97→23.58）——残留噪声已弱，温和高斯核（中心权重 0.25）的细节损失 > 噪声收益；但整体链路仍大幅领先

**面试表述**："混合噪声的去噪顺序有讲究：脉冲噪声先中值（趁它还是极值）、高斯噪声后加权滤波；顺序反了，中值的能力会被高斯先"毁掉"。这个用 ORDER 参数实测复现过——差 2.6dB。"

复现：`iverilog -DSWAP -I . -o tb_swap.vvp tb_chain.v; vvp tb_swap.vvp` → `python verify_chain.py --swap`

对比图（各自独立，不互相覆盖）：[chain_compare.png](chain_compare.png)（高斯→中值）· [chain_compare_swap.png](chain_compare_swap.png)（中值→高斯）——两图并排看，第二种的噪声残留明显更少。

## 审查发现与调试经验（三轮 review 沉淀）

### A. 数据可信度类（已修复）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| A1 | **实现精度 63/51/56dB 全是"参考模型的错"** | Python `round()` 是银行家舍入（half-even），RTL 是 half-up（(x+128)>>8）；csc_ref 用截断 `>>8` 而 RTL 加 bit7 进位 | 参考全部改为与 RTL 同构的舍入 → **四级 PSNR 全部 inf（位级全等）** |
| A2 | **噪底不可复现** | noise_add.py 无 `random.seed`，重跑生成不同噪声图 | 加 `--seed`（默认 20260819 固定），README 数据与噪底绑定 |
| A3 | **归档 COE 顺序漂移** | -DSWAP 运行会覆盖 gaussian_out/median_out.coe（内容互换），README 默认流程与归档态不符 | 纪律：最后一次仿真决定 COE 归属；`vvp tb.vvp` 重跑默认态再归档；verify 前确认尺寸 |

**调试经验**：**"实现精度"必须位级全等才算通过**——任何非 inf 的 PSNR 先怀疑参考模型自身的舍入/截断写法，而不是硬件（本轮四级 inf 实证：坐标、crop、系数、饱和全部早已正确，唯一错的是参考的舍入）。PSNR 数值报告必须写明"参考是谁、舍入规则是什么"。

### B. 边界语义类（已确认无实际影响，记录防踩）

| # | 现象 | 分析 | 结论 |
|---|---|---|---|
| B1 | axis_fifo 末字边界 | count==1 且挂起 valid 时 tready 拉高会"交付+预取"，末字不会重复（rdata_reg 内容为新预取项） | 本链路被下游 `wr_ready` 门控吸收，计数全对；换 TB 直连消费者需用标准 FWFT 写法（rd_en 含"有挂起先交付"条件） |
| B2 | o_done 超前最后 o_valid 约 9 拍 | coord done 组合直通，数据还有 LAT=8+1 流水 | TB 用 done_seen + repeat(20) 覆盖；若接"done=输出完成"的消费端需沿 valid 链延迟 done |
| B3 | TB 只数像素不断言数值 | 数量对、数据错的回归能骗过 TB | 数值验证在 verify_chain.py（现全 inf）；链路 TB 保留计数断言，数值自检依赖脚本——已记录此分工 |
| B4 | bilinear_interp_8b 注释写"LAT=9" | 注释错误，实际 LAT=8（位级全等实证） | 已记录，改源目录注释时顺带修正 |
| B5 | 非整除缩放的 STEP 参考 | scale_ref 用 floor、RTL 四舍五入——本 2x 恰好相等 | 公式已统一为 RTL 同构（(IN<<FB+OUT/2)/OUT），非整除倍数安全 |

### C. 可改进/受限点（"可以更好但没实现"——面试聊深度时用）

1. **整帧 FIFO 资源大**：2^14×24bit ≈ 22 块 BRAM18K。更好：前级补 tready 全握手链去掉大 FIFO，或缩成几行滑窗。受限：下级是零改动复用的无背压流水。
2. **crop 逐级收缩**：两级各 −2。更好：pad(replicate) 行缓存保全尺寸（MeanFilter 已有 pad 变体）。受限：本次复用 crop 权威版。
3. **CSC 系数非标准**：(0.183+0.614+0.062)=0.859<1，YUV→RGB 往返 −2.4dB。更好：标准 BT.601 整型量化矩阵。受限：核为外部复用，改系数需回归 CSC 单站。
4. **两级行缓存可共享**：高斯/中值各带 1 份 line_buffer（4 块 BRAM），串行同速率时可共享 1 份 + 两套核（省一半）。受限：窗口相位/valid 对齐耦合，改动大。
5. **缩放仅双线性**：更好：bicubic（bilinear_v4 目录已有学习材料）。受限：插值核复用、2x 场景双线性够用。
6. **4:4:4 无色度重采样**：YUV 域处理深度止于通道独立插值；4:2:0 存储/显示需另做色度重采样。
7. **无背压→全握手改造**：现状靠大 FIFO 吸收速差；全链 tvalid/tready 是 AXI-Stream 标准答案，但需改全部下级。
8. **多帧流不可直接复用**：单帧设计，frame_start 不排空 FIFO；连续帧需"FIFO empty 才允许下一帧 start"的帧闸。
9. **验证自动化/顺序纪律**：两 ORDER 产物相互覆盖，需要脚本一键跑或分目录归档（A3 的工程化）。
10. **噪声 seed 进文档**：所有去噪实验应记录 seed（A2 已落地），对比实验的同噪底契约同理。

### D. pad 版级联专项（crop 收缩修复过程中踩的坑，结构化记录）

| # | 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| D1 | **pad 版级联缺 blanking** | 下一级 pad 输出错误（rflush/bflush 插不进） | pad 行缓存**依赖输入带 h/v-blank**（行末/帧末空拍用于插右/下边缘 flush），但 pad 版模块输出是**连续流**（无空拍）——直接级联等于把"插空拍的时机"喂没了 | 级间插 `frame_sync_adapter`（read 侧按行结构调度：每行 W 有效 → HBLANK 拍空 → 下一行；帧末 VBLANK 拍空） |
| D2 | **零缓冲插空拍 = 必丢数据**（v1 血泪） | 输出少 288 像素（11248 vs 11536）、适配器 FIFO 填满后停摆 | 插空拍期间输入连续照来，状态机不在接收态（S_HBLANK/S_VBLANK 吞像素） | 改带缓冲 v2：512 深度小 FIFO；**溢出证明**：多出的拍只来自插空拍（≈HBLANK×H=206），帧末 VBLANK 在输入停止后发生不增加占用 → 206 < 512（对比缩放整帧 16384 是 4 倍速差，完全不同量级） |
| D3 | **axis_fifo 挂起 valid 互等死锁** | 适配器 FIFO 满（512/512）、state 永远停在 S_ROW、一行都没读出 | axis_fifo 的读侧"挂起 valid"由 rd_en 打拍产生，而调度判断"是否有数据"恰恰需要 valid——首拍互等 | 内置**组合读小 FIFO**（dout = mem[rptr] 组合输出、valid = count>0、消费即 rptr+1）：无挂起延迟，行结构精确，死锁根治 |
| D4 | **参考模型窗口模型错位** | pad 高斯/中值实现精度 19.22/21.91 dB FAIL | pad 版窗口是**中心模型**（w22 为中心，行 wr-1..wr+1）；crop 版是右下角模型（wr-2..wr）——参考沿用 crop 的偏移差 1 行 | verify_chain 的 --pad 分支切换窗口偏移 dr∈(-1,0,1) + 越界钳位 → 修复后 **inf（位级全等）** |

**教训小结**：
- pad 版"全尺寸"的代价是**格式敏感**（依赖 blanking），复用它的隐藏成本 = 级联时的 blanking 重生成（面试可直接讲）
- "插空拍"这类格式转换**必须带缓冲**——零缓冲转换 = 数据丢失；缓冲深度只覆盖"插入量"（几百拍），不是速率差（整帧）——两个量级的区分本身就是面试点
- 调度器与 FIFO 的 valid 语义要"谁驱动谁"想清楚：**组合读 FIFO（valid=count>0）是调度友好的最小实现**
- 参考模型的坐标模型必须与 RTL 的窗口定义一致（中心 vs 右下角）——本项目第二次踩"窗口坐标模型"的坑（第一次是 crop 链的 dr∈-2..0）

## 使用方式

```powershell
# 1. 生成混合噪声图（先高斯后椒盐，seed 固定可复现）
python noise_add.py --mix 20 0.10 --out-hex noise_mix.hex

iverilog -I . -o tb.vvp tb_chain.v; vvp tb.vvp > sim_log.txt

python verify_chain.py

# --- 滤波顺序实验：-DSWAP + --swap ---
iverilog -DSWAP -I . -o tb_swap.vvp tb_chain.v; vvp tb_swap.vvp > sim_swap.txt
python verify_chain.py --swap
```
