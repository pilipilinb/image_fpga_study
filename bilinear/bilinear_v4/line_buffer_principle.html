行缓存（Line Buffer）原理图解

为什么需要行缓存 · 3 个格子怎么"环形" · 写侧和读侧怎么协调 · 工程里模块怎么连 ｜ 配套工程：bilinear/bilinear_v4（行缓存版双线性缩放）

一、为什么需要行缓存：存整张图会爆

整图 ROM（v3 的做法）

把整张图的像素全存进 BRAM，想读哪个像素就读哪个。

存储 = 整帧像素 × 4 份

1920×1080 的图 ≈ 5500 块 BRAM——一块中端 FPGA 全器件才几百到一千块，直接爆。

行缓存（v4 的做法）

只存 3 行，像素一边进来一边用，用不完的就丢掉。

存储 = 3 行 × 行宽

1920×1080 的图 ≈ 3 块 BRAM——和图像高度没关系，只跟行宽有关。

一句话：整图 ROM 用"存储换简单"，行缓存用"协调换存储"——只存 3 行，但写侧和读侧必须配合好。

二、3 个格子怎么"环形"

为什么正好 3 个格子

双线性插值一次要用 2 行（第 sy 行和第 sy+1 行）。同时输入侧还在往缓存里填当前的第 w 行。 写 1 行 + 读 2 行 = 3 行，所以缓存 3 个格子，每个格子存一整行。

格子 0
存第 0、3、6…行
格子 1
存第 1、4、7…行
格子 2
存第 2、5、8…行

"环形"到底是什么意思

1
第 0 行来了 → 放格子 0；第 1 行 → 格子 1；第 2 行 → 格子 2。
2
第 3 行来了，格子 0 里还躺着第 0 行——但第 0 行早就被读侧用完了，直接覆盖它。
3
第 4、5、6 行同理：格子用完了就绕回第一个，像绕圈圈，所以叫"环形"。

"第 r 行放哪个格子"用一句话算：r 除以 3 的余数（代码里写 line[r % 3]）：

第几行01234567
÷3 的余数01201201
放哪个格子格0格1格2格0格1格2格0格1
输入像素一行一行进来 → 填进格子（写侧）
输出侧按源坐标从格子里读 2 行 × 2 列（读侧）→ 送去插值

三、写侧和读侧怎么协调（反压）

写侧（输入）

按顺序收像素，收满一整行就换下一个格子。

写之前要检查：我要覆盖的格子里，旧的那行（3 行前写的）读侧还用不用？

还用 → 不能写，让输入暂停；已用完 → 放心写。

读侧（输出）

coord_gen 给出源坐标 (sy, sx)，需要第 sy 行和第 sy+1 行的像素。

读之前要检查：这两行写完了没有？

没写完 → 输出暂停，等写侧写完；写完了 → 取 4 个邻居去插值。

代码里的两条规则（对应 line_cache2.v）

规则一 · 写侧什么时候才允许写（wr_ready = 1 的条件）：

我要写的格子是 (w % 3)，里面放着 3 行前写的旧行 (w-3)。

只有当读侧已经用完旧行（读侧最低用到 sy00，且 sy00 已经越过 w-3）时，才允许覆盖。

assign wr_ready = ((w < 3) || (sy00 > w - 3)) && (w < IN_HEIGHT);

前 3 行（w<3）格子从来没写过，随便写。帧末读侧停住也不怕：那时要覆盖的旧行早就用完了。

规则二 · 读侧什么时候才允许读（rd_ready = 1 的条件）：

要用的第 sy+1 行已经写完（写侧 w 已经越过它）。

assign rd_ready = (sy01 < w);

只要顶行写完了，两行就都齐了（写侧是从上往下顺序写的）。

四、放大和缩小时，谁等谁

放大 N 倍：写快读慢

输出像素多，读侧消耗行慢；写侧很快就把格子填满了。

写侧等读侧：wr_ready 拉低，输入暂停，等读侧把旧行用完腾出格子。

缩小 N 倍：写慢读快

输出像素少，读侧消耗行快；等着用第 sy+1 行，但它还没写完。

读侧等写侧：rd_ready 拉低，输出暂停，等写侧写完那一行。

一句话：谁落后谁等谁——写侧不覆盖读侧还在用的行，读侧不等还没写完的行。两条规则管住所有缩放比。

注意：行缓存是组合读（地址一到数据立刻出），所以坐标、权重、4 邻居 同一拍齐活，直接喂插值核，顶层不需要打拍对齐（v3 用 ROM 同步读才需要）。

③ 控制流（反压管住谁）

→

→

两条反压线见第三节的规则一、规则二：写侧被挡 → 输入等；读侧被挡 → 坐标等。

六、与整图 ROM 版（bilinear_v3）对比

维度整图 ROM（v3）行缓存（v4）
存储整帧 × 4 份（随图像尺寸膨胀）3 行 × 行宽（恒定）
输入方式整帧先就绪，再随机读流式输入，边进边出
读侧随便读，零等待行没写完要等（rd_ready）
写侧无（只读）旧行没用完要等（wr_ready）
实现难度简单多一套协调逻辑
适用小图、整帧可用大图、实时视频流

七、一句话总结

  • 行缓存 = 只存 3 行的"滑动窗口"：写侧填 1 行 + 读侧用 2 行 = 3 个格子，行号 ÷3 的余数决定放哪个格子（环形）。
  • 写侧是生产者，读侧是消费者，两者速度不同，靠反压协调：写侧不覆盖还在用的行，读侧不等没写完的行。
  • 和卷积的 line_buffer 不一样：卷积是"输入 1 像素出 1 窗口"，读写 1:1 同步；缩放是"按源坐标随机读"，必须用环形 + 反压。
  • 插值核、坐标生成、钳位逻辑和 v3 完全复用——只把"4 份整图 ROM"换成了"3 个格子 + 协调逻辑"。
