## 项目简介

传感器上个别感光点会坏：**亮点**（永远输出接近全白）或**死点**（永远输出接近全黑）。它们会在图像上留下固定位置的白点/黑点，去马赛克之后还会变成刺眼的彩色斑点——所以必须在 Demosaic **之前**修掉，这就是 DPC（Defect Pixel Correction）。

本工程按用户给定伪代码实现**包络检测法**：

```
输入：邻域 N（同色邻居，不含中心）、中心 P、阈值 thr；输出 P'
    mn = min(N); mx = max(N)
    if   P > mx + thr:  P' = mx    # 亮点 → 抄最亮的同色邻居
    elif P < mn - thr:  P' = mn    # 死点 → 抄最暗的同色邻居
    else:               P' = P     # 正常 → 原样通过
```

- **0 乘法器**：只有比较、取极值、加法
- **Bayer 进 Bayer 出**：输出仍是 8bit 单通道原始格式，直接喂给 Demosaic
- **位级可验证**：与 Python 参考（用绝对坐标独立实现）逐像素 0 误差

## 原理：包络检测 + 同色邻居

### 为什么必须只看"同色邻居"

Bayer 图上中心可能是 R / G / B，邻居里有别的颜色。拿绿去比红（亮度本来就差很多）会误判，所以只在**同色邻居**里取 min/max 形成"包络"。

### 同色邻居怎么定（本工程最容易错的地方）

窗口中心固定占 (2,2)。窗口内相对位置 (i,j) 的**绝对颜色**要从中心相位 + 偏移量算：

```
绝对相位 = 中心相位 XOR (i%2, j%2)      ← 别漏了 XOR 中心相位！
```

于是（25 点里，中心自己不算）：

| 中心相位 | 同色邻居（相对位置） | 个数 |
|---|---|---|
| **R**（绝对 偶,偶） | i,j 都偶：W00,W02,W04,W20,W24,W40,W42,W44 | **8** |
| **B**（绝对 奇,奇） | 同上（i,j 都偶） | **8** |
| **Gr / Gb**（G 合并） | i,j 同奇偶：上面 8 个 + W11,W13,W31,W33 | **12** |

注意 **R 和 B 的邻居集合是一样的**（都是"相对 i,j 都偶"）——硬件上 even8 一组极值可以共用。

### 阈值比较用加法避开负数

原公式 `P < mn − thr` 里 `mn − thr` 可能是负数，所以改写成 **`P + thr < mn`**——两边都是非负数，无符号比较就够了（同工程 CSC"正负分开"的思路）。

## 实测效果

测试图：真图派生的 Bayer（112×103），固定 seed=20260916 注入 **60 个坏点**（亮点/死点各半）：

| 指标 | 数值 |
|---|---|
| 坏点图 vs 干净图 | 26.43 dB（坏点的伤害） |
| **校正后 vs 干净图** | **31.91 dB（+5.48 dB，修回来了）** |
| 修复率 | 36/60 = **60.0%**（被改掉的坏点比例） |
| 误伤率 | 25/10632 = **0.235%**（干净区被误改的像素） |

**为什么修复率只有 60%？**（重要认知，面试可讲）
这张图偏亮（大量像素 ~248）。**亮部的"亮点"注入 255 后，与同色邻居极值只差 7 < thr=32 → 包络判定不出来 → 漏检**。反过来暗部的死点也一样。包络法的检出力天然受"周围邻居的亮度分布"限制：坏点与正常像素必须**拉得开**才检得出。

**为什么有 0.235% 误伤？**
图像本身的**强边缘**处，中心与同色邻居极值差也可能超过 32 → 被误判成坏点。这是单阈值包络法的固有副作用（工程上会加多方向判定/双阈值/仅在孤立极值时替换来缓解）。

## 架构与流水

```
din[7:0] ──► line_buffer_nxn（N=5，攒出 5×5 窗口）──► win_flat（25×8bit 打包）
                                                        │
行/列计数器 ──► 相位（看行列奇偶）──► 打 5 拍 ──────────►├─► dpc_envelope（取同色极值 + 双阈值替换）
                                                        ▼
                                              o_dout[7:0] + o_valid（Bayer 数据）
```

**相位为什么要打 5 拍**：与 Demosaic 工程实测一致（`line_buffer_nxn` 的 adly 对齐链 4 拍 + matrix_valid 自身寄存 1 拍）；相位链必须**每拍都移**（与窗口链同构），否则输入有气泡时会错位。

## 调试记录（踩过的坑）

| # | 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | **同色邻居推导漏 XOR 中心相位**（最深刻的坑） | verify 报 RTL vs Python 差 476 像素；误伤率虚高到 4.185% | 把"相对奇奇"当成"绝对奇奇"→ B 相位错取 4 个对角、G 相位取错 12 个异奇偶位置。**RTL 和 TB 参考同时写错，TB 自检反而 PASS** | 回到"绝对相位 = 中心相位 XOR (i%2,j%2)"重新推：R/B = i,j 都偶（各 8 个）、G = i,j 同奇偶（12 个）；**靠 Python 参考（绝对坐标独立实现）交叉校验才抓出来** |
| 2 | **行计数器帧末不回绕** | 三帧仿真第 2 帧起大量 MISMATCH（537 个） | `row_cnt` 到 IMG_H-1 后继续加 → 第二帧行号奇偶全反 → 相位错 → 边缘处判定错 | 行号到最后一帧末回绕到 0；**Demosaic 的 top 有同一个 bug**（被纯色帧掩盖），已同步修复并回归 PASS |
| 3 | 阈值比较的负数 | —（设计期规避） | `mn − thr` 可能为负 | 改写成 `P + thr < mn`，全程无符号比较 |
| 4 | 坏点位置不可复现 | —（设计期规避） | 随机注入坏点 | `make_dpc_data.py` 固定 seed=20260916 + 输出 defect_pos.txt 位置清单 |

**经验小结**：
- **同源双参考会一起错**：TB 参考和 RTL 若是同一套推导写的错，自检会"一起错、一起 PASS"；必须有**另一套用不同思路实现**的参考（这里是 Python 用绝对坐标）才能抓出来
- **相对位置 ↔ 绝对坐标的奇偶转换必须显式过一遍 XOR**（中心相位），这是 Bayer 类工程的通用陷阱
- 多帧测试能暴露单帧测试掩盖的 bug（行号回绕）

## 面试要点

1. **DPC 的位置**："坏点必须在去马赛克之前修——否则一个坏点会被插值扩散成彩色斑点。"
2. **包络检测的本质**："用同色邻居的 min/max 画一个'包络'，中心跑出包络 ± 阈值就认为是坏点，直接抄最近的极值。只有比较和加法，0 乘法器。"
3. **同色邻居的推导**："绝对相位 = 中心相位 XOR 相对位置奇偶——所以 R/B 相位取'相对 i,j 都偶'的 8 个，G 相位取'同奇偶'的 12 个。这个 XOR 很容易漏，我就漏过一次。"
4. **包络法的局限（实测数据支撑）**："亮区的亮点、暗区的死点会因为'和邻居拉不开差距'而漏检（本工程修复率 60%）；强边缘又可能被误判（误伤 0.235%）。工程上会用多方向判定/双阈值来改进。"
5. **验证方法论**："TB 参考和 RTL 用同一套推导，错了会一起 PASS——所以我另外写了用绝对坐标实现的 Python 参考，正是它抓出了 476 个差异。"

## 使用方式

```powershell
# 1. 生成坏点数据 + Python 参考 + 对比图（固定 seed，可复现）
python make_dpc_data.py

# 2. 跑 RTL 仿真（三帧：坏点图 / 干净图 / 纯色）
iverilog -I . -o tb.vvp tb_dpc.v; vvp tb.vvp > sim_log.txt

# 3. 独立校验（全等 + 修复率/误伤率）+ 对比图
python verify_dpc.py

# 阈值可调（改 TB/top 的 THR 参数，默认 32）：
#   阈值小 → 更敏感（检出更多，误伤也更多）；阈值大 → 更保守
```

## 已知限制与后续

- **输出裁掉两圈**：(W-4)×(H-4)；与 Demosaic 串联后累计裁 4 圈（`112×103 → DPC 108×99 → Demosaic 104×95`），全尺寸链需两站都换 pad 版
- **包络法固有局限**：亮区亮点/暗区死点漏检（实测修复率 60%）、强边缘误伤（0.235%）——改进方向：双阈值、多方向一致性、与邻居均值比较、孤立极值判定
- **单帧不重置**：当前依赖"帧末行号回绕"，若输入帧间隔不规整需要加显式的帧同步信号
- **副本说明**：`line_buffer_nxn.v` / `tb_nxn_n5.v` 是从 line_buffer / Demosaic 复制的副本，源目录为权威版
- **后续串联**：DPC → Demosaic（已验证两站各自 0 误差），可继续接降噪/CSC 组成完整 ISP 前端链
