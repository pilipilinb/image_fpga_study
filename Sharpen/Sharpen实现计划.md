# Sharpen 锐化实现计划（M5.1）

> 定位：8 级 ISP 链路**最后一级**（感知域：Gamma → 锐化）。输入 = Gamma 出的 **RGB888 24bit 简流**，输出同为 24bit。
> 上游计划：[fifo行缓存与8级ISP链路实施计划.md](../fifo行缓存与8级ISP链路实施计划.md) §八（M5）。
> 本文只覆盖 **M5.1 = 锐化 + 出端 AXIS 适配**；整链串联留给 **M5.2**（单开一节）。

## 一、算法与定点化推导

### 1.1 USM（Unsharp Mask）

```
blur = 3×3 高斯模糊(orig)
out  = clip( orig + k·(orig − blur) )          k = 锐化强度
```

- `orig − blur` 是**高频分量**（细节 + 噪声）；乘 k 后加回原图 = 增强高频 = 锐化。
- k 越大越锐，`k=0` 退化为恒等直通（可作为一条独立判据）。
- 这是标准 USM。3×3 是硬件效率的标准选择。

### 1.2 3×3 高斯模糊（复用降噪的空间核，零乘法器）

核 `[1 2 1; 2 4 2; 1 2 1]`（Σ=16）。按"角×1 / 边×2 / 心×4"归并：

```
sum  = (p00+p02+p20+p22) + 2·(p01+p10+p12+p21) + 4·p11          // 纯移位/加法
blur = (sum + 8) >> 4          // Σ=16 → 右移 4；+8 = round-half-up
```

**位宽推导**：`p ∈ [0,255]` ⇒ `sum ≤ 16×255 = 4080 < 2^12`（12bit，`+8` 后 4088 仍 < 4096）⇒ `blur ∈ [0,255]`。**无乘法器**——全部是加法 + 常数移位。

### 1.3 锐化强度 k 的定点化

k 用 **Q(K_FRAC) 无符号定点**：`k = k_gain / 2^{K_FRAC}`。

| 参数 | 默认 | 含义 |
|---|---|---|
| `KW` | 10 | `k_gain` 端口位宽 |
| `K_FRAC` | 8 | 小数位数 ⇒ k = k_gain/256 ∈ [0, 3.996] |
| `k_gain` | 128 | 默认 k = 0.5 |

**修正量用"符号–幅值"两路写，而不是有符号乘法**——这是本模块**故意**的定点技巧：

```
d = |orig − blur|                                  // 无符号，∈[0,255]
adj = (d·k_gain + 2^(K_FRAC−1)) >> K_FRAC          // round-half-up
out = (orig >= blur) ? orig + adj : orig − adj     // 再饱和到 [0,255]
```

**为什么不用有符号 `diff·k >>> K_FRAC`**：Verilog 里 `signed + 无符号常量` 会把整个表达式翻成无符号（经典坑），且负数算术右移的"舍入方向"是 floor 而非就近——RTL 与 Python golden 若一处 floor、一处幅值四舍五入就会**对不上**。改成幅值两路后：
- 位宽/符号全程无歧义（无 signed 运算）；
- 舍入语义唯一（幅值就近取整 → 等价于"远离零"取整）；
- Python golden 一模一样重写即可位级同构。

**位宽**：`d ≤ 255`，`k_gain ≤ 1023` ⇒ `d·k_gain ≤ 260,865 < 2^18`；`+128` 后 19bit 足够；`>>8` ⇒ `adj ≤ 1018`。`out = orig ± adj ∈ [−1018, 1273]`，需 **11bit 有符号**即可容纳，最后饱和到 `[0,255]`。

### 1.4 与 ISP 分域的关系

链路分域：RAW（BLC/DPC）→ 线性 RGB（Demosaic/降噪/CCM）→ **感知域（Gamma/锐化）**。
锐化放在 **Gamma 之后**：① 感知域做锐化符合"细节增强在显示域"的主流；② 锐化在高频放大，放在位宽缩减（Gamma 10→8）之后、用最终 8bit 值做，避免把 Gamma 的量化台阶一起放大。

## 二b、时序收敛（M5.1 追加，2026-10-09）

**OOC 实测发现原设计（LAT=1、行缓存 pad mux 直连核）严重超时**：`sharpen_stage` **35 逻辑级 / WNS −1.930 ns @150 MHz**（隐含上限 ≈116 MHz）。对照实验：`ccm_stage`（**无行缓存**、LAT=2）只有 **8 级 / WNS +4.748 ns** ⇒ 病因定位为"**行缓存 pad mux + 吃窗口的核**压进同一拍"，与是否用 function 无关。

**修复三步**（每一步都是纯 retiming，输出值不变）：
1. **步 0 显式定位宽**：`gsum` 里 `2*(...)`/`4*p4` → 移位 + 12bit 定宽中间量；`1<<(K_FRAC-1)` → 定宽 `localparam RND`；饱和比较改成"高位是否非零"（避免与 32bit 常量比较产生宽比较器）。**根因**：未定宽常量按 Verilog 上下文位宽规则把表达式抬到 32 位 → 加法器被撑宽。
2. **步 1 窗口寄存器**：在 `sharpen_stage` 里对 `lb_win` 插一级寄存器（**不动共用的 `line_buffer_fifo_nxn`**，保护 M1/M3 的 FIFO 占用不变式），把 pad mux 单独关进一拍。
3. **步 2 核内拆流水**：核 LAT 1→2（T1 寄存 `{orig,blur}`，T2 做差/乘/round/饱和）。

**结果**：**15 级 / WNS +2.583 ns @150 MHz ✅**（路径 4.074ns）。处理路径总延迟 = 窗口 1 + 核 2 = **3**，`sharpen_stage` 的 sof/eol 对齐链深度必须 = 3。三模式 TB 重跑仍位级 0 误差。

**仍未做（留给后续）**：新关键路径已变成核 T2（差 → DSP 乘法 → round → 饱和，4.074ns）。若目标频率升到 200 MHz+，需把 DSP 输出寄存单独拆一级（即"步 3"）。

## 三、架构（照抄 denoise_stage 框架，只换核与位宽）

```
in ──┬─► line_buffer_fifo_nxn(DW=24,N=3) ─► sharpen_core ─┐
     │        (pad 全尺寸 + 反压)                          ├─► mux ─► out
     └─► axis_stream_fifo(DEPTH=4) ────────────────────────┘
            (bypass 直通延迟线)
```

| 差异点 | denoise_stage | sharpen_stage |
|---|---|---|
| 像素位宽 | DW=10（3 通道 30bit） | **DW=8（3 通道 24bit）** |
| 核 LAT | 3 | **2**（拆流水后；处理路径总延迟 3 = 窗口 1 + 核 2） |
| bypass 方式 | 排空点切换 | **排空点切换（同）** |
| 额外端口 | — | **`k_gain` 强度输入** |

**bypass 为什么必须"排空点切换"**：处理路径含行缓存，延迟 ≈ `K·W+K + 1`（上千拍）；bypass 走 `axis_stream_fifo`（几拍）。两路延迟差 W+1 像素量级 ⇒ 帧中间热切换必然错位 ⇒ 只能"停源 → 排空 → 切 → 再发"。这是与 CCM/Gamma（等延迟旁路、可热切换）的架构对比点。

**反压冻结**：`ostall = (bypass ? byp_v : core_dv) && !out_ready` → 冻结核 + 行缓存 + bypass FIFO 读 → `in_ready=0` 上传。行缓存占用恒 `IMG_W` 的不变式由"bypass 期整体冻结（`in_valid=0`）"保住。

## 四、验证方案

### 4.1 TB 期望（Python 位级同构）

`make_sharpen_data.py` 生成 `src_small.hex`（24bit 输入）+ 两套期望：

| 模式 | 编译宏 | `k_gain` | 期望文件 | 用途 |
|---|---|---|---|---|
| small | （无） | 128（k=0.5） | `exp_small.hex` | 协议四场景 + bypass 三段 |
| small-K64 | `-DK64` | 64（k=0.25） | `exp_small_k64.hex` | **独立覆盖"强度 k 参数化"这条需求** |
| img | `-DIMG` | 128 | `exp_img.hex` | 真图四级串联（M3→CCM→Gamma→锐化） |

**为什么 k 用"整轮常量 + 单独编译模式"，而不是运行中改**：修正量在核里生效，而像素到达核时已晚于进入行缓存 `K·W+K` 拍 ⇒ **帧边界附近改 k 会让帧头/帧尾串用两个值**（同一约束也适用于 bypass）。所以 k 是**帧级参数、改动必须在排空点**；用独立编译模式覆盖非默认 k 是最干净的验证方式。

### 4.2 TB 判据

1. 逐拍位级比对（`out_data` vs golden，路径由当拍 bypass 选）
2. `out_sof` / `out_eol` 位置正确
3. 反压期输出稳定性断言（用**上一拍**的 `ready`）
4. 收发计数一致（反压零丢数）

### 4.3 独立第二判据（`verify_sharpen.py`）

1. **位级全等**：RTL 落盘 vs Python golden 逐像素
2. **锐度量化**：Tenengrad（平均梯度幅值）/ 平均 |Laplacian| —— 锐化后应**显著上升**
3. **PSNR**：原图（Gamma 出）vs 锐化图 —— 作为"改动强度"指标（锐化本就会降低与原图的 PSNR，这是预期）
4. **对比图**：原图 | 锐化图 + 局部放大（看 halo/边缘）

### 4.4 边界与范围

- AWB 仍为 **1.0 增益直通占位**（M6 做），本节不涉及 Bayer 域。
- 出端 AXIS 适配 + 弹性 FIFO 的**CDC**（像素时钟 vs 系统时钟）留集成阶段；单级仿真用同频。
- 整链串联（RAW10 进 → RGB888 出，全链 PSNR）留 **M5.2**。
