## 1. 为什么是这 8 级、这个顺序

链路：`BLC → DPC → AWB → Demosaic → 降噪 → CCM → Gamma → 锐化`，按 **ISP 分域**组织：

| 域 | 级 | 为什么在这一域 |
|---|---|---|
| **RAW 域** | BLC | 黑电平必须在一切之先减：它是唯一的"零点锚"。若放到 DPC 之后，Gr/Gb 的黑电平差（本工程 116 LSB）会变成混进缺陷判据的"假台阶"——见 [BLC_DPC](../BLC_DPC/README.md) 的分相位实验 |
| | DPC | 坏点必须在去马赛克之前修：去马赛克会把一个坏点**插值扩散到邻域 9 个像素**，越早修代价越低 |
| **Bayer 域增益** | AWB | 增益必须在去马赛克**之前**按相位施加：此时 R/Gr/Gb/B 各自独立；一旦插值进同一像素，就再也无法逐通道校正 |
| **线性 RGB 域** | Demosaic | 把 Bayer 补成三通道——注意**保持 10bit 直通**，位宽缩减统一推迟到 Gamma 出口 |
| | 降噪 | **必须在 CCM 之前**：降噪是非线性（值域权重依赖像素值），CCM 是线性矩阵乘。顺序不可交换，且"降噪在前"实测优 **1.51 dB**（CCM 的负系数/对角>1 会把通道独立噪声放大并**染成色噪声**）——见 [Denoise_CCM_Gamma](../Denoise_CCM_Gamma/README.md) |
| | CCM | 色彩校正矩阵，**全链唯一用 DSP** 的一级 |
| **感知域** | Gamma | **全链唯一换位宽的一级**（30bit→24bit）。感知域压缩动态范围，下游才是 RGB888 |
| | 锐化 | 感知域做 USM：人眼对 gamma 后的亮度差异更敏感 |

> 全链**位宽只有两处变化**：入口 AXIS 剥位（12→10）、Gamma 出口（30→24）。其余全程 10bit 直通
> ——"位宽缩减集中在一处"让每一级的 golden 都能与单模块 TB 的指标对齐比较。

## 2. AWB 为什么用"1 拍 1.0 增益占位"，而不是直接空着

AWB 的完整实现（分相位统计 + 软件闭环算增益）留 M6。本阶段只做三件事，目的是**让 M6 替换时零返工**：

1. **位置占好**：`awb_stub` 插在 DPC 与 Demosaic 之间（Bayer 域），受力后即最终位置。
2. **延迟对齐**：占位**延迟 = 1 拍**。数据通路上 AWB 只有"乘增益"一级（统计是旁路），
   所以 M6 的真 AWB 在这条通路上也应是 1 拍 ⇒ **替换前后整链总延迟不变 ⇒ 端到端 golden 不用重算**。
3. **接口预留**：顶层把 `awb_gain_00/01/10/11`（Q2.8，1.0=256）与 `awb_stat_00/01/10/11`（32bit）
   端口一次设计到位 ⇒ M6 接入真 AWB **不需要再改顶层端口**。

`awb_stub` 本身是**功能正确**的增益应用（不只是连线）：按相位选增益 → 乘 → round-half-up → **上饱和**
（`gain>1` 时如 R 增益 2.0 会把 800 抬到 1600，直接截位会回绕成暗像素）。四路给 256 时**位级恒等**，
所以 golden 就是不接 AWB 的结果——这一点由 TB 与 verify 双向把关（级 3 与级 2 输出位级相同）。

## 3. 级间为什么先不加弹性 FIFO（"先量后加"方法论）

直觉上"8 级串联，中间肯定要塞一堆 FIFO 兜反压"。本项目**刻意不这么做**，而是：

1. 级间先用**纯组合 ready 穿透**（`out_ready → in_ready` 逐级上传）把链跑通；
2. 用 TB 的 **stall 测量**量出真实的 stall 模式（哪一级、多长、是否同相）；
3. 再按数据决定在哪儿插、插多深。

**实测数据**（真图 112 宽、连发 4 帧、出端恒 ready）：

| 节点 | node0 入口 | node1 BLC | node2 DPC | node3 AWB | node4~8（Demosaic 之后） |
|---|---|---|---|---|---|
| 最长连续 stall | **684 拍**（1 段） | 684 | 3 | 3 | **0** |

**解读**：外零反压时**只有入口会 stall**，且它来自"帧末造行期"——4 个含行缓存的级
（DPC / Demosaic / 降噪 / 锐化）的造行期在帧边界**级联**（前一级造行 → 挡上游 → 下一级还没轮到造行），
入口被压的总时长 ≈ 各级 `K·W+K` 之和 ≈ **6·W** 拍（W=112 → 684，实测与估算吻合）。

**决策**：
- **入端弹性 FIFO 深度 ≥ ~6·W**（W=640 → 4096 字）才能把"不可反压的源（CSI-2 RX）"与造行期解耦 →
  这正是 `blc_axis_adapter` 的 `ENTRY_FIFO_EN/FIFO_DEPTH` 的用途，集成时开。
- **Demosaic 之后的级间不必加 FIFO**：外零反压时它们 stall 恒为 0；真反压时逐级"冻结+保持"零丢数，
  深度加在级间没有收益。**出端 FIFO 才是平滑"VDMA 忙"突发的地方**（与 M5.1 出端结论一致）。

> **公示结论**：这不是"省资源"，而是**有数据支撑的架构判断**——"先量后加，别凭感觉堆 FIFO"。

## 4. ★ 时序收敛实战：功能 0 误差 ≠ 时序能过（M3 遗留问题在集成时暴露）

整链 TB 两模式**一次全过**（逐级位级 0 误差），但整链 OOC 综合（150MHz 顶层 `isp_chain_top`）：

| 版本 | WNS | LOGIC_LEVELS | 失败端点 |
|---|---|---|---|
| 集成初版 | **−0.939ns ❌** | 26 | 10 个，**全在 `u_dpc/u_dpc/dout_reg[*]`** |

**定位**：最差路径 `u_dpc/u_lb/lc_r_reg[5] → u_dpc/u_dpc/dout_reg[0]`，7.596ns（logic 2.371 / route 5.225），
26 级。**这不是"反压跨 8 级"的路径**——那一族（`u_out_adp/u_fifo/wptr → u_dpc/u_lb/.../empty_r`）
实测 **MET +1.9ns**。真正的瓶颈是 **M3 的 DPC 级内部**：行缓存 pad mux（`sel_row/sel_col` + 9:1 mux，
**组合**）与核内极值树/比较**挤在同一拍**。

**为什么 M3 会有这个问题**：M3 交付**早于** M5.1 立的"每级 RTL 交付前跑一次 OOC 预检"铁律；
M5.1 之后降噪/锐化/CCM 都按"窗口寄存器 + 核内拆流水"重建了，**DPC/Demosaic 没回头补**。
整链集成 = 第一次让"旧 M3 级"和"新 M5.1 级"同处一个顶层，问题立刻暴露。

**修法**（= M5.1 同款，最小改动）：在 `dpc_stage` 的**行缓存→核之间插一级窗口寄存器** `win_q`
（连同相位 `ph_q`、valid `wv_q`），把那条长组合路径切成两拍；不改共用的 `line_buffer_fifo_nxn`
（保护 M1/M3 占用不变式）。`dpc_stage` 处理延迟 **1 → 2**，sof/eol/相位对齐链**同步改为 2 拍**
（对齐链深度必须 = `LAT_WIN + LAT_CORE`，漏一级/多一级就错位）。

**结果**：WNS **+1.589ns ✅**，最差路径变为**核自身**（`win_q → dout_reg`，17 级），
占用 LUT 9340 / FF 4181 / DSP48 46 / RAMB 12。

**回归验证**（改 DPC 必须重跑其所有下游/上游用户）：
- M3 链 TB（`tb_bayer_dpc_demosaic`，默认 / MHC / IMG 三模式）→ 全 **[PASS]**
- BLC_DPC 顺序实验 TB（`tb_blc_dpc`，SWAP×IMG 四变体）→ 全 **[PASS]**（含相位一致性检查）
- 整链 TB 两模式 + 独立复算 → 全 **[PASS]**

> **这条经验可复用**：① 只看单模块 OOC 会漏，**必须按最终顶层跑一次**；
> ② 关键路径的**归属**（哪一级/哪条链）比"WNS 多少"更重要——报告里的 Source/Destination 直接告诉你要改哪；
> ③ 改一个被多处复用的级，**回归面 = 它的所有上下游使用者**。

## 5. 各段 bypass 语义（整链里别混用）

| 段 | bypass 实现 | 切换时机 | 原因 |
|---|---|---|---|
| 降噪 | 排空点切换（`axis_stream_fifo` 变延迟） | **帧级** | 处理路径含行缓存（上万拍），两路延迟差 W+1 像素量级 |
| 锐化 | 排空点切换 | **帧级** | 同上 |
| CCM | 等延迟旁路（打 2 拍） | 可**任意拍** | 无行缓存，两路 LAT 严格相等 |
| Gamma | 等延迟旁路（打 1 拍） | 可**任意拍** | 无行缓存；★ bypass 只关曲线不关位宽（`(v+2)>>2`） |
| BLC/DPC/Demosaic/AWB | **无 bypass** | — | 不是可选算法（黑电平/坏点/去马赛克/增益都是链的骨架） |

> 整链 TB 三种场景 `bp_*` 全为 0：本 TB 的目标是"整链接线 + 端到端位级正确 + 反压"；
> 各段 bypass 已在各自模块 TB 单独验证（链只是把端口直连，无额外逻辑）。

## 6. 验证体系（三层判据）

1. **TB 自检记分板**（`tb_isp_chain.v`）：末端逐位比对期望 + `tkeep≡111`/`tuser`/`tlast` 契约 +
   AXIS 稳定性断言 + 收发计数一致 + **stall 测量** + 超时兜底。
2. **Python 独立第二判据**（`verify_isp_chain.py`）：**不复用 TB 期望/生成器落盘**，自己从 `chain_in_*`
   重算整链**逐级**输出，与 RTL 逐级落盘比对（img：s1~s8 全 0 误差；small：末端 0 误差）。
3. **图像质量**：① **逐级插桩 PSNR**（每级 vs 理想输入同级输出）定位"哪一级把噪声压掉/放大"；
   ② **端到端 PSNR** + 两条基线（DPC/降噪全关、仅降噪关）量化整链价值；③ 6 格对比图。

**逐级 PSNR**（真图）：BLC 24.54 → **DPC 26.16**（修坏点 +1.6dB）→ AWB 26.16（恒等）→
Demosaic 28.39 → **降噪 31.16（峰值，+2.8dB）** → CCM 27.16（预期下降：矩阵放噪）→
Gamma 27.59 → 锐化 26.77。

**端到端**：全关 22.05 → 仅降噪关 23.00 → **整链 26.77 dB**。

## 7. 数据构造（真图 IMG 模式）

与 M4/M5 各模块**同源**，保证横向可比：
- 源：`Demosaic/input.hex` → Bayer 采样 → `min(v<<1,1023)`（低增益暗场景，留 OB headroom）
- `raw_ideal = min(clean + OB[phase], 1023)`（**无噪声无坏点的理想靶子输入**）
- `raw = clamp(raw_ideal + 高斯噪声 σ=48(10bit))` + 注入 **60 个传感级缺陷**（亮点 1023 / 死点 0 各半）
- 两个输入都跑整链 → `exp`（TB 自检 golden）与 `ideal`（PSNR 靶子）

> σ=48（10bit）≈ 8bit 的 12，是"能明显看到噪声、又不至于淹没有效信号"的量级。

## 8. 与后续阶段的接口

- **M6（AWB 真实现）**：替换 `awb_stub`，保持"Bayer 简流 + 1 拍延迟 + 同样 4 个 gain 端口"；
  把分相位统计接到顶层 `awb_stat_*`（`awb_stub` 现恒 0）。顶层端口已就位，无需改动。
- **集成（上板）**：两端 `axis_stream_fifo` 换官方 `AXI4-Stream Data FIFO IP`（同名同义）；
  跨时钟域 CDC 与 VDMA/CSI-2 的时钟在此层解决（本工程单级仿真同频）。
- **入端 FIFO 深度**：按 §3，`ENTRY_FIFO_DEPTH ≥ ~6·W`（W=640 → 4096）。
