核心答疑：计划够不够？你真正的起点在哪？

Q1"行缓存 → CSC/缩放 → 边缘检测 → ISP 核心，这些够了吗？能满足就业需求吗？"

基本够，但漏了两块关键拼图。我拉了 2025-2026 年图像 FPGA 岗位 JD 反复出现的关键词，除了你列的那些，还必须有：

① DDR 帧缓冲（ping-pong 双缓冲）——大恒图像、科易光电、津亚电子的 JD 里都明确写"基于 DDR3/4 的图像帧存设计"[1][2]。没有帧缓冲，多路视频切换、画中画、帧率转换都做不了。

② Zynq / Vitis 裸机协同（AXI-Lite 配置 + AXI-DMA 搬数据）——联影、中科飞测的 JD 反复出现 Zynq / AXI / MicroBlaze[3][4]。纯 PL 侧的图像处理不够，面试官会问"你怎么和 PS 通信"。

修正后的完整技能树是：行缓存 → CSC/缩放/滤波/边缘 → ISP → DDR 帧缓冲 → MIPI 采集 → HDMI 输出 → Zynq 协同。比原计划多了 DDR 帧缓冲和 Zynq 协同两块。

Q2"我简历里的 CSC、双线性插值都是用 IP 的 API 实现的，实际上不懂原理。这影响大吗？"

影响非常大，但这恰恰是你的机会。面试官看到简历上有 CSC 和缩放，一定会追问："YCbCr→RGB 的转换矩阵怎么推导的？""双线性插值的四个权重怎么算？"如果你答"我调的 IP"，直接露馅。

但好消息是：CSC 和缩放的原理并不难。CSC 本质是一个 3×3 矩阵乘加（Y = 0.299R + 0.587G + 0.114B），双线性插值是四个像素按距离加权求和。手写 RTL 各约 50-100 行，一个晚上就能跑通。计划里这两块必须从原理手写，不能再调 IP。

这也是为什么原计划的"W1-W2 打基础"改为"W1 行缓存 → W2 手写 CSC + 缩放（从零写，不用 IP）"——你的"图像处理经验"实质是"IP 配置经验"，得从原理补起，否则面试一问就穿。

为什么"上板出图"是面试王牌

面试官见过太多"只跑过仿真"的候选人。你拿出一个真实上板、从 Sensor 到显示器出图的完整系统，能讲清每个模块的输入输出、资源占用、时序——这比任何简历包装都有说服力。医疗影像/半导体检测岗位的面试官最看重的就是"你能不能把算法真正变成硬件跑起来"。
