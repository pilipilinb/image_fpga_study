直方图均衡状态机（FSM）梳理

6 个状态各自干什么 · 状态之间怎么跳 · 谁数拍子谁记帧 · 和 ping-pong 怎么配合 （配套工程：histogram_tutorial/histeq_core.v，状态机约 30 行代码）

1. 全貌：一个主循环，6 个状态

ST_PRE开机清零 → ST_WAIT等新帧 → ST_STAT统计+映射 → ST_DRAIN排空 2 拍 → ST_CDF计数表→CDF 表 → ST_CLEAR映射表清零 → ST_WAIT等下一帧 → ST_STAT……循环

三句话总结：

  • 上电只走一次：ST_PRE（清垃圾）→ ST_WAIT；
  • 每帧走一圈：ST_WAIT → ST_STAT（收像素）→ ST_DRAIN → ST_CDF → ST_CLEAR → 回 ST_WAIT；
  • 过帧边界时角色互换（统计表/映射表对调），靠 frame_cnt 最低位实现。

2. 每个状态具体在干什么

ST_PRE —— 开机清零（只走一次）

耗时：256 拍 为什么存在：BRAM 上电内容不定

开机后第一件事：把"统计表"（此时 frame_cnt=0，即 ram0）256 个格子全部写 0。 因为 BRAM 没有复位引脚，上电内容是垃圾（仿真里是 x，真实芯片是随机值）， 而统计表必须从 0 开始数——只能靠写口逐格写 0 清零。 如果跳过这步：帧 0 统计时没写过的格子全是 x，CDF 前缀和 x 一加全表全脏（实测坑 1）。

跳转：clr_cnt 扫到 255（写完全部格子）→ ST_WAIT。

ST_WAIT —— 等新帧的第一颗像素

耗时：帧间空白期 跳走条件：y_en 拉高（新帧第一像素来了）

什么都不干，就是等。像素计数 pix_cnt 归零（为下一帧数数做准备）。 当 y_en 从 0 跳 1（第一颗有效像素），立即进 ST_STAT， 且这一拍 pix_cnt 置 1（第一颗像素算第 1 个）。

ST_STAT —— 统计期（一帧的大头：11536 拍）

耗时：一帧像素数 同时干两件事：B 数数、A 查表

两条流水线并行跑：

  • 统计：每来一颗像素，把"上一颗像素"的灰度计数 +1 写回统计表（双口错拍 RMW）；
  • 映射：每来一颗像素，读映射表 CDF[y]，乘 K 右移 S，输出均衡值 J（帧 0 除外，frame_cnt=0 时禁输出）。

同时有个"帧满检测"：pix_cnt 数到 N-1（=11535）就停，等 y_en 拉低（帧末空白）→ frame_done=1 → 帧干完了，frame_cnt +1，跳 ST_DRAIN。 

// 帧满 = 数到 N-1 且这一拍没有新像素（空白确认）
wire frame_full = (pix_cnt == N - 1);
wire frame_done = frame_full && !y_en;
...
if (frame_done) frame_cnt <= frame_cnt + 1'b1;   // 帧数 +1（角色互换的种子）

ST_DRAIN —— 帧末排空（2~3 拍）

耗时：2 拍（drain_cnt 数到 2） 为什么存在：流水的尾巴不能丢

帧结束的瞬间，最后几颗像素的映射结果还在输出流水里（读口晚 1 拍 + 输出寄存 1 拍 = 还在流水里 2 拍）。如果立刻把读口抢去做 CDF 扫描，最后一颗像素的 J 就丢了（实测坑 3）。 所以停 2 拍：端口分派保持 ST_STAT 的样子（映射继续吐），但 y_en 已拉低、没有新像素进来。

跳转：drain_cnt 数到 2 → ST_CDF。

ST_CDF —— 统计表改造成映射表（257 拍）

耗时：257 拍 = 256 格写回 + 首拍空转 跳走条件：cdf_cnt 扫到 256

把"刚统计完的计数表"原地改造成"CDF 表"（前缀和）： 读口扫格子 0..255，累加器 acc 逐格累加，写口把"累加和"写回上一格。 扫完一块表 = 每个格子从"出现次数"变成"累计出现次数"。 跳转：cdf_cnt 到 256（257 拍后）→ ST_CLEAR。

ST_CLEAR —— 映射表清零（256 拍）

耗时：256 拍 为什么必须清：下一帧它要当统计表

把"刚用完的映射表"全部格子写 0。因为下一帧它就要当统计表，计数必须从 0 起算； 而 BRAM 不能复位，只能写入清零。 跳转：clr_cnt 扫到 255 → ST_WAIT（等下一帧，角色已互换）。

4. 谁在数什么：计数器和状态机的关系

信号归哪个状态管干什么位宽
state / state_nxt全局当前状态 / 下一拍状态3bit（6 态）
frame_cntST_STAT 的 frame_done 沿已完成的帧数；最低位 = 角色互换开关；≥1 = 允许输出2bit
pix_cntST_STAT / ST_WAIT数本帧像素，数到 N-1 停（帧满判定）15bit
drain_cntST_DRAIN数 2 拍排空2bit
cdf_cntST_CDF扫 0..256（257 拍），既是读地址又是完成计数9bit
clr_cntST_CLEAR / ST_PRE扫 0..255（256 拍），写地址 + 完成计数8bit
accST_CDF前缀和累加器（顺带在 CLEAR/PRE 复位）14bit
设计套路：每个"等待多久"的状态都配一个计数器，计数器数到顶 = 状态跳走。 CDF 用 cdf_cnt（既是扫描地址又是完成计数），CLEAR 用 clr_cnt，DRAIN 用 drain_cnt—— 一个计数器干两件事，不用额外写"等待 N 拍"的逻辑。

5. 三个理解锚点（面试讲状态机就讲这三点）

锚点一句话解释
为什么有 ST_DRAIN？ 输出流水还剩 2 拍尾巴，状态切换不能抢走读口——"流水的尾巴最容易被状态机吃掉"
为什么 CDF 是 257 拍？ 256 格写回 + 首拍空转（读口晚 1 拍，第一拍没有"上一格"可写）
角色什么时候换？ frame_cnt 在"帧结束沿"（进 DRAIN 时）+1，所以空白期要用 cdf_sel = frame_cnt[0]^1 回退一帧，否则清错表（实测坑 4）
