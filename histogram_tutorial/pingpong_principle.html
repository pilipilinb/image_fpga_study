双 BRAM Ping-Pong 架构

为什么直方图均衡要"两块表轮流用" · 核心就 3 行代码怎么读懂 · 一帧的完整循环 · 和 DDR 帧存双缓冲是同一个思想（配套工程：histogram_tutorial/histeq_core.v）

1. 先想清楚：这种算法需要"两张表"

直方图均衡每一帧要做两件先后接替的事：

表干什么什么时候可用
统计表 h数"每个灰度值出现了几次"，边收像素边 +1整帧收完才能用
映射表 CDF像素来了查表，把灰度映射成均衡后的值统计表改造完后才能用

问题来了：统计表在"被写"的时候，映射表在"被读"——两件事同时发生，一张表做不到。 因为统计期间表在不停地改（每拍 +1），这时候拿它去查映射，查到的永远是半成品； 而且两件事之间还有一段"空白期"要把统计表改造成映射表（CDF 前缀和，用 257 拍）， 改造期间这张表既不能统计也不能映射。

结论：既然一张表忙不过来（写了就不能读、改造了就不能用）， 就准备两块一模一样的表，轮流干：A 统计时 B 映射，下一帧 B 统计、A 映射——这就是 ping-pong。

2. 大白话类比：两个前台窗口

生活版：银行两个窗口

窗口 A 在给今天的第一批客户办业务（统计），窗口 B 在给昨天的客户查档案（映射）。 下班后 A 把今天的记录整理成册（CDF），B 把昨天的档案清空归档（清零）。 第二天两人换班——B 办业务、A 查档案。谁也不会一边办业务一边查档案。

硬件版：双缓冲（Double Buffering）

写缓冲区和读缓冲区各一份，写满一份后"交换指针"继续写另一份。 读者永远只读"写完了的"那一份，不会看到写到一半的数据——这就是为什么视频里 DDR 帧存要 ping-pong、显示器要双缓冲，防止画面撕裂。

关键词是"角色互换"：不是把数据搬来搬去，而是一块表在"统计态"和"映射态"之间 来回切换身份，切换的时机是帧边界。

3. 工程里的核心代码：怎么实现"轮流"

整个 ping-pong 的调度逻辑浓缩成 3 行代码，其余全是外围的数据通路。逐行看：

3.1 帧计数器 frame_cnt —— "轮"到谁了

// 已经统计完的帧数：帧 0 结束时 =1，帧 1 结束时 =2……
reg [1:0] frame_cnt;
...
// 每一帧干完（frame_done 拉高）就 +1
if (frame_done) frame_cnt <= frame_cnt + 1'b1;

frame_cnt 的最低一位（bit0）每帧翻转一次：0 → 1 → 0 → 1…… 这就是"轮到谁"的天然信号，拿它选表，连计数器都不用额外写。

3.2 stat_is_ram1 —— 本帧统计用哪块表（核心第 1 行）

// ★ 本帧的"统计表"是不是 ram1？（1=是，0=不是，那就是 ram0）
wire stat_is_ram1 = frame_cnt[0];
frame_cnt最低位统计表映射表正在发生
0（帧 0）0ram0ram1（用不上）帧 0 只统计，无输出
1（帧 1）1ram1ram0帧 1 统计 ram1、用帧 0 的 CDF 映射
2（帧 2）0ram0ram1又换回来，循环

逻辑就是这么简单：统计表 = 帧号的奇偶，另一块自动是映射表。 帧 0/2/4 统计 ram0，帧 1/3/5 统计 ram1。

3.3 cdf_sel —— 空白期"按刚结束的帧"回退一帧（核心第 2 行）

// ★ 帧间空白期（CDF/CLEAR）该操作哪块表？= frame_cnt 最低位取反
wire cdf_sel = frame_cnt[0] ^ 1'b1;

这一行最容易被问倒，它是个 off-by-one（差一错误）的修复。原因：

  • frame_cnt 在"帧结束那一拍"就立刻 +1 了（翻成下一帧的编号）；
  • 但空白期要处理的还是刚结束那一帧的表——给"帧 0 的统计表"做 CDF、给"帧 0 的映射表"清零；
  • 所以角色必须按上一帧算，最低位取反（^1）就是回退一帧。
时刻frame_cntstat_is_ram1（会选错）cdf_sel（正确）操作
帧 0 刚结束11 → 给 ram1 做 CDF ✗0 → 给 ram0 做 CDF ✓CDF 转换帧 0 的统计表 ram0
帧 1 刚结束20 → 给 ram0 做 CDF ✗1 → 给 ram1 做 CDF ✓CDF 转换帧 1 的统计表 ram1
实测坑：初版直接用了 stat_is_ram1，结果帧 0 结束后把"刚统计好的真表"清零了、 把"上电垃圾表"做成了 CDF——帧 1 输出全 0。这就是"角色切换时机必须和谁在用这张表对齐"。

3.4 两块表怎么声明和连接（核心第 3 行附近）

// 两块一模一样的 BRAM：ram0 / ram1，各 256 格（地址 0~255 = 灰度值）
reg [13:0] ram0 [0:255];
reg [13:0] ram1 [0:255];
// 每块都有独立写口（wena/waddr/wdata）和读口（raddr/rdata）——简单双口
// 统计需要同一拍"读当前像素的格 + 写回上一像素的格"，两个地址，单端口做不到

"双口"和"双块"是两个独立的概念，别混：

  • 双口：一块 RAM 内部有读写两个端口（地址独立），解决"同一拍读写两个不同地址"；
  • 双块（ping-pong）：两块 RAM 轮流当不同角色，解决"写中的表不能读、改造中的表不能用"。

4. 一帧的完整循环：A/B 分别在干嘛

以"帧 N+1"为例（帧 N 结束后：A 是 CDF 表、B 是清完 0 的空表）：
阶段耗时ram0（A）ram1（B）
帧 N+1 有效像素11536 拍映射：每拍读 CDF[y] → 输出 J统计：每拍给 y_d1 的计数 +1
帧末 DRAIN2 拍保持（等最后像素吐完）保持
空白期 CDF257 拍闲置从"计数表"改造成"CDF 表"
空白期 CLEAR256 拍全部格子写 0（下下帧当统计表）闲置
WAIT等像素下一帧到来，角色互换（A 统计、B 映射）

注意两条规律：

  • 当前帧统计表：读写双口最忙（读当前像素的计数 / 写上一像素的计数 +1）；
  • 当前帧映射表：只读不写——映射期写口整帧闲置，映射表是"成品"，不许改。

5. 三个最容易被面试官问倒的点

问题答案（一句话）对应修复
为什么空白期角色要取反？ 帧计数在"帧结束"沿已 +1，空白期处理的是"上一帧"的表 cdf_sel = frame_cnt[0]^1
为什么映射表只读不写？ 映射表是上一帧"改造完成"的成品，写它就把成品弄脏了 分派里映射表 wena=0
为什么清零用"写 0"而不是复位？ BRAM 阵列没有复位引脚，只能靠写入清零 CLEAR/PRE 阶段扫 256 格写 0

6. 举一反三：这套思想和后面每个大模块都是亲戚

场景ping-pong 在哪规模
本工程直方图均衡统计表 / 映射表轮流256 格 BRAM
AE / 3A 统计（ISP）帧级统计表轮流（曝光/白平衡统计）小表
DDR 帧存双缓冲写帧 A 读帧 B，帧边界交换整帧 DDR
显示器双缓冲防画面撕裂的读写在两帧缓冲间切换整帧

面试表达："ping-pong 解决的是'生产者要写、消费者要读同一份数据'的冲突—— 用两份数据 + 角色互换，让读写永远打不到同一份。小到 256 格的 BRAM 统计表， 大到 DDR 里整帧图像的双缓冲，都是同一个套路，差别只在"角色切换"的粒度 （这里按帧换，DDR 那里也按帧换）。"
