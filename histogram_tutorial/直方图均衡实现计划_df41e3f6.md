# 直方图均衡实现计划（W2 帧级处理架构）

> **输出目录约束**：所有产物（RTL/TB/脚本/测试数据/仿真日志/对比图/文档）一律存放于 `d:/FPGA_proj/image_fpga_test/histogram_tutorial/` 路径下，不跨目录引用。

## 需求确认（用户流程 5 步）
1. CSC 提取灰度图（复用 `rgb_to_ycbcr_3stage.v`，取 Y 通道，BT.601 带 +16 offset——均衡自动把 16..235 区间拉伸到 0..255，这正是卖点）
2. 统计直方图：read-modify-write（读 h(k) → +1 → 写回）
3. 计算 CDF
4. CDF LUT 映射
5. 输出图像 J（定点化，按图像尺寸移位，误差可接受）
- 双 BRAM ping-pong 帧级架构（W2 核心思想）：**帧 N 统计写 BRAM-A → v-blank 转 CDF → 帧 N+1 查表输出，同时统计写 BRAM-B → 循环**

## 顶层架构（输出延迟 1 帧：帧 0 统计无输出，帧 1 起输出）

```
din[23:0]/din_valid ──► rgb_to_ycbcr_3stage（复用，取 Y + o_data_en，4 拍）
                            │ y / y_en
                            ▼
                      histeq_core（双 BRAM ping-pong）
                            │ 统计 RMW（读 h(k)+1 写回）或 映射查表（读 cdf）
                            ▼
                      o_j[7:0] + o_valid（帧 N+1 起输出，valid 链 2 拍）
```

### 帧时序（ping-pong 角色表）

| 阶段 | BRAM-A | BRAM-B | 输入流 |
|---|---|---|---|
| 帧 N 有效像素 | 统计 h（RMW） | 保持 CDF_{N-1}（供映射） | 每拍 1 像素 |
| 帧 N 后 v-blank（约 640 拍） | **A 原地转 CDF_N**（257 拍） | **B 清零**（256 拍） | 空 |
| 帧 N+1 有效像素 | 映射查表 J = f(CDF_N)（只读） | 统计 h（RMW，从 0 开始） | 每拍 1 像素 |

- 每帧 v-blank 固定做两件事：**本帧统计表 → CDF**（供下一帧映射）+ **上帧映射表 → 清零**（供下一帧统计）。角色每帧互换，v-blank 内两块表各就各位。
- **帧边界判定（关键设计）**：输入流没有 vsync 线，core 用"长 blanking 计数"判定帧边界——`y_en` 连续为低 ≥ `FRAME_GAP_MIN=320` 拍 → 判定一帧结束，进入 v-blank 处理。行间气泡仅 1~3 拍、TB 帧间空 640 拍，阈值卡在两者之间不误判；真实视频 blanking（1080p ≈ 99000 拍）远大于阈值。
- **帧 0 无映射表**：o_valid 由帧号门控（帧 0 禁能输出，BRAM 上电垃圾不可见），TB 期望从帧 1 开始收数。
- **为什么 v-blank 要 640 拍**：CDF 前缀和 256 读 + 1 尾写 = 257 拍；清零 256 拍（BRAM 不可复位，工程铁律——帧统计必须从 0 开始，只能写入清零）；两者 + 余量 ≈ 600，TB 给 640。

## 关键设计细节

### 1. 统计 RMW（简单双端口 BRAM：写口/读口独立地址，每拍完成 1 个 bin 更新）

**为什么必须双口（review 修正）**：RMW 需要同拍"读当前像素的 bin" + "写回上一像素的 bin"，两个不同地址同时操作，单端口 BRAM 一个地址口做不到。BRAM 用 1 写 1 读简单双口（Xilinx block RAM 原生支持，可推断）。

```verilog
// 写口：地址 = 像素地址打 1 拍（addr_d1），数据 = 读口同步输出 + 1
// 读口：地址 = 当前像素 Y；同步读延迟 1 拍 → h_rd 是"上一拍地址"读出的值
// review 关键：写数据直接用 h_rd + 1（h_rd 天然晚 1 拍对应 addr_d1），
// 不要再打一拍——地址晚 1 拍、数据晚 2 拍会错位
always @(posedge clk or negedge rst_n) begin
    addr_d1 <= y;          // 写地址 = 当前像素晚 1 拍
    we_d1   <= y_en;       // 写使能同步打拍（首拍不写，避免垃圾 +1）
end
assign waddr = addr_d1;
assign wdata = h_rd + 1'b1;   // h_rd = 上一拍读出的 h(addr_d1)
assign wena  = we_d1;
```
- 双 BRAM 用 `(* ram_style="block" *)` 推断，阵列不可复位；帧首 0 状态由 v-blank 清零遍保证

### 2. CDF 原地前缀和（双口错拍流水，257 拍）
```verilog
// 读口：地址 k = 0..255 顺序扫（h[k] 同步读出，晚 1 拍）
// 写口：地址 = 读地址打 1 拍（k-1），数据 = acc（打拍后的累加和）
// 时序：拍 t 边沿 h_rd <= h[t]；同时写 addr=k-1 数据 Σh[0..k-1]（由上一拍组合得出）
// → 读完 256 个 bin 后还有 1 拍尾写（addr=255 写 Σh[0..255]），共 257 拍
// acc 位宽 = $clog2(N+1)，最大 = N（总像素数）
```
- 与统计 RMW 同一双口套路，只是"写数据 = 前缀和"而不是"+1"；清零遍同样双口顺序写 0（256 拍）

### 3. 映射 + 定点化（用户要求：按图像尺寸移位）
```verilog
// J = (cdf × K) >> S，K 由图像尺寸编译期推导（localparam 常数除法，综合折叠成常数乘法）
localparam S = 14;                                  // 可配，默认 14
localparam N = IMG_W * IMG_H;
localparam K = (255 << S) / N;                      // 例：112×103 → K=362（9bit）
localparam KW = $clog2(K + 1);                      // K 位宽
// 映射期：读口读 cdf[Y]（1 拍）→ 组合 cdf×K>>S + 饱和 min(255) → 输出寄存 1 拍
// valid 链 = CSC 4 拍 + core 2 拍（读 1 + 输出寄存 1），帧 0 输出由帧号门控
```
- 误差来源：K 向下取整（±1 LSB，实测 N=11536 时 J_max = 254 而非 255）——用户已声明可接受
- **J 是像素值不是幅值，保留饱和 min(255)**：K 取整可能让大分辨率下 (cdf*K)>>S 略超 255（与 sobel 幅值不饱和的取舍相反，这里输出是图像像素必须钳位）
- 参考模型必须用同一公式 `J = (cdf*K)>>S` + 同一饱和（全等比对协议，延续 sobel 工程经验）

### 4. 位宽推导
| 信号 | 位宽 | 说明 |
|---|---|---|
| h(k)/CDF/acc | `$clog2(N+1)` bit（112×103 → 14bit） | 单 bin 计数最大 = 总像素数 N |
| K | `$clog2(K+1)`（S=14、N=11536 → 9bit） | (255<<S)/N 的商 |
| J | 8bit | (cdf×K)>>S 后饱和 min(255) |
| FRAME_GAP_MIN | 9bit（值 320） | 长 blanking 帧边界判定阈值 |

## 风险与坑（预判）
- **单端口 BRAM 做不了流式 RMW**：每像素需同时读/写两个不同地址，必须简单双口（写口/读口独立地址）；单端口"2 拍 RMW"无法流式，除非降速
- **写数据别多打一拍**：h_rd 已是延迟 1 拍的同步读输出，直接 `h_rd+1` 与 `addr_d1` 配对；再多寄存一级就错位
- **帧边界阈值要卡对**：FRAME_GAP_MIN=320 必须大于最大行间气泡（1~3 拍）且小于帧间空白（TB 640 拍）；若真实输入流 v-blank 不足（隔行视频/短 blanking），需降阈值或改用 vsync/帧起始信号
- **CDF 有尾拍**：256 读 + 1 尾写 = 257 拍，v-blank 预算按 640 算充足（257+256=513 < 640），但 FSM 状态跳转不能少算这 1 拍
- **帧 0 无 CDF**：映射期输出必须门控（帧号寄存器），否则读到的 BRAM 是上电垃圾；参考模型从帧 1 起算
- **K 向下取整**：J_max 可能 254 而非 255（N=11536 实测），TB/Python 期望按 K 截断结果计算，别按理想公式算导致假 FAIL
- **CSC 复用历史坑**：异步复位同步释放，上电先等 16 拍再喂数据（sobel 工程实测记录，勿再踩）

## 执行记录（2026-08-27 完成后追加）

### 与计划的偏差（均有依据）
1. **帧边界判定改用像素计数法**：计划用"长空白 ≥320 拍"阈值，执行时改为"数满 H×W 有效像素 + 遇空白确认"——不依赖 blanking 长度，行间气泡（1~3 拍）天然免疫，省掉 FRAME_GAP_MIN 参数的调参风险
2. **新增 ST_DRAIN 排空状态（2 拍）**：帧末最后像素的映射 valid 流水（2 拍）未吐完时帧计数已 +1，映射表选择翻转导致最后像素输出错误（实测 catch）——加排空状态 + 角色回退（cdf_sel）修复
3. **新增 ST_PRE 上电清零状态（256 拍）**：BRAM 上电内容不定（仿真 x），帧 0 只写"出现过的灰度"，未写 bin 保留 x 污染 CDF（实测帧 1 输出全 x）——上电先清首帧统计表
4. **TB 等 PRE 完成再喂数据**：PRE 需 256 拍，TB 复位后 16 拍就喂会丢帧 0 全部像素导致全局错位 1 帧（实测 out_cnt 只有 12/24）
5. **统计 RMW 读口必须 write-first 语义**：连续相同灰度像素的 h+1 依赖"同拍同地址写后读可见"（Xilinx 简单双口 BRAM 硬件语义）；iverilog 默认 read-first 会让第二个同灰度像素的 +1 互相覆盖（实测 Σh=10761 vs 期望 11536，丢 775）——读口按 write-first 建模
