# 直方图均衡（双 BRAM ping-pong 帧级处理，W2）

RGB888 输入 → CSC 灰度化（复用 3stage）→ 逐帧直方图统计 → v-blank 期转 CDF →
下一帧查表映射输出 J。**核心是 W2 的帧级处理架构**：输出延迟 1 帧、双 BRAM 角色
每帧互换、统计/映射两张表在帧间空白期各就各位。

## 模块与接口

| 文件 | 说明 |
|------|------|
| `rgb_to_ycbcr_3stage.v` | 复用 CSC 3stage（BT.601，Y = 0.183R+0.614G+0.062B+16，系数×256：47/157/16） |
| `histeq_core.v` | ★ 核心：简单双口 BRAM×2 + FSM（PRE→STAT→DRAIN→CDF→CLEAR→WAIT）+ RMW 统计/前缀和/清零/映射四模式 + K/S 定点化 |
| `top_histeq.v` | 顶层：CSC + core，`din[23:0]/din_valid → o_j[7:0]/o_valid`，参数 IMG_W/IMG_H/S |
| `tb_histeq.v` | 自检 TB（3 帧同图：帧0 统计、帧1/帧2 输出，参考模型按帧重算全等比对 + VCD） |
| `verify_histeq.py` | numpy 独立重算 + 直方图对比 + 低对比度拉伸演示图 |
| `直方图均衡实现计划_df41e3f6.md` | 实施计划（含 review 修正与执行记录） |

数据流：

```
din[23:0]/din_valid ──► rgb_to_ycbcr_3stage（RGB→Y 灰度，4 拍流水）
                            │ y / y_en
                            ▼
                      histeq_core（双 BRAM ping-pong）
                            │ 帧 N 统计 h / 帧 N+1 查 CDF 映射
                            ▼
                      o_j[7:0] + o_valid（输出延迟 1 帧，帧 1 起有效）
```

## 直方图均衡是干嘛的（大白话）

**一句话：把"灰蒙蒙"的图变清晰——像素灰度原来挤在一小段区间，均衡后摊开到 0~255 全范围，暗的更暗、亮的更亮，原来看不清的细节拉开了。**

**为什么会有灰蒙蒙的图**：相机曝光不足、逆光、雾天、夜景、医学 X 光片、红外图，这些场景下画面所有像素的灰度都挤在很小的范围（比如都挤在 60~140）。问题不是"图里有 256 级灰度但丢了"，而是"256 级灰度只用了 65 级"——暗部和亮部之间没有层次，肉眼自然分不清细节。

**均衡做了什么**：统计整帧直方图 → 算出累积分布 CDF → 用 CDF 当映射表，把"像素少的灰度区间拉宽、像素多的区间保持"。效果 = 灰阶利用效率最大化：

- 低对比度输入（Y 只分布在 60~140）：输出摊开到 **J 0~254**（本工程实测，见 `low_contrast_demo.png`）
- 逆光人像的暗部细节、雾天远景的轮廓、X 光片的组织层次——全是被"拉开灰度"救回来的

**打个比方**：一队人全挤在走廊中间（灰度区间 60~140），谁也看不清谁；均衡让他们按顺序均匀站满整个大厅（0~255），间距拉开了，每个人的轮廓都清楚了。

**什么场景收益小**：本来就正常曝光、动态范围接近全幅的图（比如本工程的 `input.hex`，CSC 后 Y 已是 16~235 近全动态），拉开空间不大，甚至因为输出只有 256 级而出现量化级别合并——这不是 bug，是均衡的特性，真实 ISP 里对这类图通常不下均衡（或用 CLAHE 分块局部处理）。

**顺带一提**：本工程输入是 CSC 的 Y（BT.601 带 +16 offset，范围 16~235，本来就比 0~255 窄约 14%），均衡后自动把这段也拉伸回 0~255——"窄动态输入 → 全动态输出"正是均衡的看家本领。

## 帧级处理架构（W2 核心思想）

| 阶段 | BRAM-A | BRAM-B | 模块状态 |
|---|---|---|---|
| 上电 | 清零（PRE，256 拍） | 闲着 | 等第一帧（WAIT） |
| 帧 N 有效像素 | 统计 h（RMW 写 h+1） | 查表输出 J=f(CDF_{N-1}) | STAT |
| 帧 N 末（2 拍） | 保持（映射流水排空） | 保持 | DRAIN |
| 帧 N 后空白（640 拍） | 原地转 CDF_N（257 拍） | 清零（256 拍，供下帧统计） | CDF → CLEAR |
| 循环 | 角色互换（frame_cnt[0] 翻转） | | WAIT |

- **输出延迟 1 帧**：均衡需要"先看完一整帧才能算变换表"——帧 N 统计、v-blank 转 CDF、帧 N+1 才用，这是帧级处理与像素级/窗口级的本质区别
- **帧边界判定**：像素计数法（数满 H×W 且遇空白），不依赖 blanking 长度阈值，行间气泡（1~3 拍）天然免疫
- **v-blank 预算**：CDF 257 + 清零 256 = 513 拍，TB 给 640；真实 1080p v-blank ≈ 99000 拍远够

## 逐拍拆解：BRAM-A/B 的读口、写口每一拍在干什么

先记住两个端口的行为（读口和写口节奏不一样）：
- **读口**：这一拍把地址送上，**下一拍**格子里的数才出现在 rdata 上（晚 1 拍，BRAM 同步读的特性）
- **写口**：wena=1 的这一拍，时钟边沿把 wdata 存进 waddr 指向的格子

下面按"帧 N+1"的一整轮走一遍（帧 N 结束后：A 是 CDF 表、B 是清完 0 的空表）。

### 帧 N+1 有效像素期（11536 拍）：B 连续数数 + A 连续查表

| 端口 | 地址指向 | 这一拍做什么 |
|---|---|---|
| B 读口（统计表） | 当前像素灰度 y（如 227） | 读出 h[227]（灰度 227 已出现的次数） |
| B 写口（统计表） | 上一拍像素灰度 y_d1（如 226） | 把 h[226]+1 写回 226 格 |
| A 读口（映射表） | 当前像素灰度 y（227） | 读出 CDF[227] → 乘 K 右移 S 饱和 → 输出 J |
| A 写口（映射表） | — | 整帧闲置（只读） |

要点：读口管当前像素、写口管上一拍像素——两个地址同拍各干各的，单端口做不到，这就是必须双口的原因。每拍给**上一个像素**入账，当前像素的账下一拍入；首拍无"上一像素"，写口被使能挡住。

**为什么读口管当前、写口管上一拍（不是读口快，是写口必须等读口的数据）：**

- 拍 t（灰度 226 的像素来了）：读口地址 = 226（这拍"预约"读出 h[226]）；时钟边沿，h[226] 才出现在 rdata 上
- 拍 t+1（灰度 227 的像素来了）：读口地址转到 227（为下下拍预约）；写口这时才拿到 rdata = h[226]，把它 +1 写回 226 格——**226 的账在这一拍入**

结论：写口永远在写"读口一拍之前预约的那笔账"。读口选地址是"当拍"，写口落账是"下一拍"，两者差的 1 拍 = BRAM 同步读的固有延迟——同一拍没法"读 226 又写 226"，因为写口算 h+1 需要 rdata，而 rdata 是这一拍边沿才读出来的，写口采样不到。

### 帧末空白期：CDF 转换（257 拍）+ 清零（256 拍）

**CDF**：把 B 从"计数表"改成"CDF 表"，读口扫 0..255，写口写"上一格的累计总和"：

| 拍 | cdf_cnt | 读口在读 | 写口在写（cdf_cnt-1 号格） | 写的内容 |
|---|---|---|---|---|
| 拍0 | 0 | h[0]（晚1拍才出来） | 不写（没有"上一格"可写） | — |
| 拍1 | 1 | h[1] | 格子 0 | h[0]（=Σh[0..0]） |
| 拍2 | 2 | h[2] | 格子 1 | h[0]+h[1]（=Σh[0..1]） |
| ... | ... | ... | ... | ... |
| 拍255 | 255 | h[255] | 格子 254 | Σh[0..254] |
| 拍256 | 256 | — | 格子 255 | Σh[0..255]（最后补的一格） |

257 = 256 格写回 + 首拍空转（读口晚 1 拍，第一拍没有"上一格"可写）。A 闲置。

**清零**：A 写口扫 0..255 每拍写 0（256 拍），两个读口闲置。为什么必须清：下一帧 A 要当统计表，计数必须从 0 起算；BRAM 无复位引脚，只能写入清零（实测坑 1）。

### DRAIN（2 拍）+ WAIT

DRAIN 的 2 拍里四个端口保持有效像素期的分派（但 y_en 已拉低、无新像素），让最后几个像素的 J 从输出流水平稳吐完（实测坑 3）。WAIT 等 y_en 重新拉高，下一帧开始，A/B 角色互换（A 统计、B 映射）。

### 端口占用速查表

| 阶段 | A 读口 | A 写口 | B 读口 | B 写口 |
|---|---|---|---|---|
| 帧 N+1 有效像素 | 读 y → 输出 J（映射） | 闲置 | 读 y → 供 +1（统计） | 写 y 上一拍 +1 |
| CDF 转换（257 拍） | 闲置 | 闲置 | 扫 0..255 | 写上一格的前缀和 |
| 清零（256 拍） | 闲置 | 扫 0..255 写 0 | 闲置 | 闲置 |

一句话规律：**"当前帧统计表"的读写双口都在忙（读当前像素、写上一像素 / 读扫描格、写上一格）；"当前帧映射表"只读不写；空白期两块轮流被改造和清零。**

## 关键设计细节

**统计 RMW（简单双口 BRAM）**：每拍 1 像素，读口读当前像素的 h(Y)，
写口写回上一像素的 h+1（两个不同地址同拍操作，单端口做不到）。
写数据 = 读口同步输出 +1（天然晚 1 拍对齐写地址），不再多打一拍。

**CDF 原地前缀和（257 拍）**：读口扫 k=0..255，累加器 acc += h[k]，
写口写回地址 k、数据 Σh[0..k]（256 读 + 1 尾写 = 257 拍）。

**映射定点化（按图像尺寸移位）**：`J = (CDF[Y] × K) >> S`，
`K = (255<<S) / N` 编译期 localparam 除法（综合折叠成常数乘法，无除法器）。

| 信号 | 位宽 | 说明 |
|---|---|---|
| h/CDF/acc | `$clog2(N+1)`（112×103 → 14bit） | 单 bin 计数最大 = 像素总数 |
| K | `$clog2(K+1)`（S=14 → 9bit，K=362） | (255<<14)/N 向下取整 |
| J | 8bit | (cdf×K)>>S + 饱和 min(255) |

## 踩坑记录（本次实测全过程，面试按"现象→定位→修复"三段讲）

> 这四个坑都是仿真实测抓出来的，每个都带了可复现的数值证据。面试时挑 2 个讲透（write-first 和角色回退最有料），按"先讲现象、再讲怎么定位、最后讲怎么修"的节奏，不用背，理解后用自己的话讲。

### 坑 1：BRAM 上电脏数据 → 帧 1 输出全是 X（上电清零 PRE 不可省）

**【现象】** 停止仿真时打印 `[FAIL] simulation timeout`，日志里大量 `got x exp 192`——输出里出现 X 值，仿真直接坏掉。定位到输出 x 来自映射查表：`rdata0=x`。

**【定位】** 查 BRAM 内容：Xilinx block RAM 上电内容不定（仿真里是 x，真实芯片是随机值）。帧 0 统计只写"图像里出现过的灰度"对应的 bin，**没出现过的 bin 从未被写入、保留上电 x**。帧 0 结束后 CDF 转换要扫描全部 256 个 bin 做前缀和——`acc = acc + x` 一碰上没写过的 bin，整个 CDF 表全被污染成 x，帧 1 映射查表自然全 x。

**【修复】** 新增 ST_PRE 状态：上电后先把"首帧统计表"256 个 bin 全部写 0（256 拍，一次性），再等第一帧输入。后续每帧的 CDF 转换会写满全部 256 个地址，表不会再有脏数据；但模拟一定要做——这是 BRAM 阵列不可复位（工程铁律）的直接后果：**不能靠复位清零，只能靠写入清零**。

**【面试表述】** "BRAM 没有复位 pin，上电内容不定。直方图统计只写出现过的灰度，没写过的 bin 是垃圾；我加了一个上电清零状态，写满 256 个 bin 再开始工作——这其实是'BRAM 阵列不可复位，清零只能靠写'这条铁律的实战案例。"

### 坑 2：read-first 偷走统计计数 → Σh 少 775（必须 write-first）

**【现象】** 错误从"全对"变成"每个像素差一点"：`got 193 exp 206`（系统性偏小）。打印 RTL 统计表和 Python 参考对比：`Σh RTL=10761 TB=11536`——**一帧 11536 个像素只统计进 10761 个，丢了 775 个 +1**。单 bin 看：`bin227 RTL=870 TB=1017`，差 147。

**【定位】** 数据链推理 + 波形确认：统计 RMW 是"读 h(Y) → +1 → 写回"，读口和写口错 1 拍配对。**当连续两个像素灰度相同**（比如 Y=227, Y=227）时，写口写回 bin227 的数据，恰好擦掉了上一次统计——因为是在**同一拍**发生"读旧值 + 写新值"，而 iverilog 的简单双口 BRAM 读口在写口同地址写时返回的是**写之前的旧值**（read-first/先读后写语义）：
- 拍 t：读 h(227)=0
- 拍 t+1：写回 h(227)+1=1（同拍读口若再读 227，拿到的还是旧的 0）
- 拍 t+2：下一个同灰度像素的写回 = 0+1=1 —— **把 t+1 写的 1 覆盖成 1，这次 +1 丢了**

连续同灰度段里只有第一个像素真的 +1，后面的全被覆盖。图像里 227 这个灰度集中出现（1017 个像素），所以损失集中在它身上（丢 147）。

**【修复】** 读口建模改成 **write-first 语义**：`if (wena && raddr==waddr) rdata <= wdata; else rdata <= ram[raddr];`——同拍同地址写入时，读口输出 = 写入值。这与 Xilinx 简单双口 BRAM 的硬件行为一致（写口优先，读口能拿到本拍写入的数据）。修复后 `Σh RTL=11536 TB=11536` 完全对齐。

**【面试表述】** "流式 RMW 统计有个隐藏坑：连续相同灰度像素的 +1 会被 read-first 的读口覆盖。Xilinx 简单双口 BRAM 真实硬件是 write-first（写口优先），但仿真器默认 read-first；我按硬件语义建模读口后，统计表和参考模型逐位一致。这个坑本质是'仿真模型必须和硬件语义对齐'——视频处理 IP 协同里经常出现。"

### 坑 3：帧末最后像素被状态机"吃"掉（新增 ST_DRAIN 排空状态）

**【现象】** 所有像素全对，只有**帧的最后一个像素**错：`px#23071(102,111): got 22 exp 192`，打印内部信号 `state=5 st=1 fc=3`——输出该像素时状态机已经切到了 CDF 阶段，映射表读口地址已被 CDF 扫描占用，读出的值从 CDF[Y] 变成了别的。

**【定位】** 时序账：帧末最后一像素的有效沿进入映射 valid 链（读 1 拍 + 输出 1 拍 = **2 拍后才吐出去**）。但帧满检测在下一拍就拉高 frame_done，状态机立刻切 CDF 去扫描 256 个 bin——**流水还没排空，状态已经翻篇**，这 2 拍里映射读口被 CDF 复用，最后像素输出错误。
另外一个细节：帧计数 frame_cnt 在进 DRAIN 沿已 +1，映射表选择（哪块 BRAM 是映射表）也随之翻转，最后像素查的是下一帧的表，雪上加霜。

**【修复】** 两处：
1. 状态机加 **ST_DRAIN（排空态）**：frame_done 后先停 2 拍（DRAIN 期间保持统计态的分派逻辑，映射 valid 链自然吐完），再进 CDF；
2. 映射表选择在 DRAIN 期**回退用"刚结束帧"的角色**（`map_sel = (state==ST_DRAIN) ? cdf_sel : stat_is_ram1`），不能跟着 frame_cnt 翻。

**【面试表述】** "流水的尾巴最容易被状态机吃掉：帧末最后一个像素的 valid 还在 2 拍流水里，帧计数已经+1、状态已切走。我加了一个 2 拍的排空状态，让输出流水先清空再进帧间处理。凡是'流水输出 + 状态切换'的交界，都要数清楚 valid 链还剩几拍。"

### 坑 4：CDF/CLEAR 清错表 → 帧 1 输出全 0（角色回退 cdf_sel）

**【现象】** 修好坑 1 后，帧 1 输出恒为 0（`got 0 exp 219`），但统计表 Σh=11536 全对。打印发现：`rdata0=0 rdata1=x stat=1 fc=1`——**帧 0 统计结束后，统计表被清零了，垃圾表却被做了前缀和**。

**【定位】** 帧计数 `frame_cnt` 在"帧完成沿"（进 CDF 的瞬间）就 +1。而 CDF/CLEAR 阶段用 `stat_is_ram1 = frame_cnt[0]` 决定操作哪块 RAM——帧 0 结束时 fc 已从 0 变 1，角色翻转：
- 想做的事：CDF 转换帧 0 的统计表（ram0）、清零帧 0 的映射表（ram1）
- 实际做的：**CDF 转换了 ram1（垃圾表）、清零了 ram0（刚统计完的真表）**——等于把统计结果清了，把垃圾做成了 CDF

**【修复】** 引入**角色回退信号** `cdf_sel = frame_cnt[0]^1`：帧间处理期（CDF/CLEAR）用"刚结束帧"的角色而不是"下一帧"的角色。帧 0 末 fc=1 → cdf_sel=0 → CDF 操作 ram0（帧 0 统计表）✓、清零 ram1 ✓。

**【面试表述】** "帧计数在'帧完成'边沿自增，CDF 转换发生在自增之后——角色已经翻到下一帧，用新角色去处理旧表就会清错表。我让帧间处理期固定使用'刚结束帧'的角色（frame_cnt[0] 取反），映射期才用新角色。这是 ping-pong 架构里最经典的 off-by-one：**角色切换的时机必须和谁在用这张表对齐**。"

## 面试讲点

1. **为什么均衡要延迟 1 帧**：变换表 = 整帧统计的 CDF，映射任何像素都要先看完这帧——"帧级处理"和"像素级（CSC）/窗口级（滤波）"的本质区别
2. **为什么双 BRAM**：统计表和映射表角色每帧互换，统计期另一块表在服务映射——两块表缺一不可
3. **RMW 为什么必须双口**：每拍 1 像素流式统计，读当前 h(Y) 与写回上一像素 h+1 是两个不同地址的同拍操作
4. **write-first 语义**：连续同灰度像素的 +1 依赖写后读可见——简单双口 BRAM 硬件原生支持，仿真器要对着写（read-first 会丢计数）
5. **K/S 定点化**：K=(255<<S)/N 编译期算好，综合成常数乘法；误差 = K 向下取整 ±1 LSB
6. **这套架构的复用**：AE 自动曝光统计、白平衡灰世界统计、3A 全是"帧级统计 + LUT 落地"的变体；DDR 帧存 ping-pong 是同一思想放大到整帧
7. **均衡的局限**：正常对比度的图收益有限（输入 Y 16..235 已近全动态，量化级别反而合并）；低对比度图效果显著；要求更多输出电平时用 CLAHE 分块或更高输出精度
