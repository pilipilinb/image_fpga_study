# Bayer 去马赛克实现计划（Demosaic，双线性版）

## 背景与目标

按 Demosaic/伪代码.txt 的**双线性插值版**实现 Bayer 去马赛克：输入单通道 8bit Bayer 流 → 5×5 窗口 → 相位判定（R/Gr/Gb/B）→ 邻域平均插值 → RGB888 输出。本轮**不含 DPC**（坏点校正），伪代码中的 MHC 版（带细节项）留后续。

**关键决策（用户已确认）**：
1. **Bayer 排列 = RGGB**（行0: R G R G…；行1: G B G B…）
2. **5×5 窗口复用 `line_buffer_nxn.v`**（N=5，工程核心可复用模板），顶层自建行列计数补相位信号

## 相位判定（RGGB 四相位表）

```
(row 偶, col 偶) = R      (row 偶, col 奇) = Gr
(row 奇, col 偶) = Gb     (row 奇, col 奇) = B
```

**对齐要点（审查补强）**：line_buffer_nxn 的窗口右下角 = 当前像素，窗口中心 = 当前像素偏移 (-2,-2)；**偏移是偶数，不改变坐标奇偶** → **中心相位 = 窗口右下角像素的相位**。

但注意：**窗口 valid 出现的那一拍，顶层行列计数已经领先窗口 L 拍**（L = adly 对齐链延迟 + 横向移位窗级数）。因此相位不能取"当前计数"，必须**取 din_valid 时刻的坐标奇偶并打拍 L 级**（即窗口对应那个像素到达时的相位）：

```
相位（组合，当前像素坐标奇偶）──► 打拍 L 级 ──► 与 matrix_valid 同拍
```

L 值的确定：先按 line_buffer_nxn 的"等待拍数 = (N-1) − 出生偏移"公式与移位窗级数推导，再用 TB 全等比对锁定（若错位 1 拍则相位全错、TB 会立刻爆大量 MISMATCH）。

**win_flat → W[i][j] 映射（写死，直接可编码）**：

```
line_buffer_nxn 语义：win_flat[(行*N + 列)*DW +: DW]，行0列0=左下角，右下角=当前像素
伪代码 W[i][j] 语义：行向下增大（W[0] 最上一行），W[2][2] 为中心
映射式：W[i][j] = win_flat[((N-1-i)*N + j)*DW +: DW]      // N=5 → ((4-i)*5+j)*8
```

## 双线性去马赛克公式（伪代码，全 2 的幂移位 → 0 乘法器）

| 相位 | R | G | B |
|---|---|---|---|
| **R** | W22（直通） | (W12+W32+W21+W23)>>2（十字 4 G） | (W11+W13+W31+W33)>>2（对角 4 B） |
| **B** | (W11+W13+W31+W33)>>2（对角 4 R） | 同上 | W22（直通） |
| **Gr** | (W21+W23)>>1（左右 2 R） | W22（直通） | (W12+W32)>>1（上下 2 B） |
| **Gb** | (W12+W32)>>1（上下 2 R） | W22（直通） | (W21+W23)>>1（左右 2 B） |

- 位宽：4 个 8bit 和 = 1020 < 2^10 → 10bit；2 个和 = 510 < 2^9 → 9bit；>>2 / >>1 后 8bit（最大恰 255），饱和为防御保留
- **舍入口径（审查补强）**：伪代码是**纯截断**（>>2 / >>1 **不加 +2 / +1**）——与本工程其他模块的 "+8 半进位" 风格不同；本工程**严格按伪代码截断**，以保证与 Python 参考位级一致（若后期想改四舍五入，需同步改参考模型）
- 注意：伪代码用 5×5 窗口，但**双线性版实际只消费中心 3×3 邻域**（W11..W33）——5×5 是为后续 DPC/MHC 预留，计划照做（窗口全输出，双线性只用其中 9 个）

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| **相位与窗口 valid 错拍**（最容易错） | 相位由"当前像素"组合 + 按窗口延迟打拍；TB 逐像素全等比对会立刻暴露（错 1 拍相位全错）；若对不上先扫延迟级数 |
| line_buffer_nxn 的 win_flat 排列语义 | 其注释明确 `win_flat[(row*N+col)*DW]`，行 0 列 0 = 左下角、右下角 = 当前像素 → 映射 W[4-i][j] 需在顶层注释写清并 TB 验证 |
| 边界：5×5 窗口需 2 圈边缘 | crop 2 圈输出 (W-4)×(H-4)（工程惯例）；pad 版留后续 |
| Bayer 采样使"输出 vs 原图"PSNR 天然不高 | 主验证用**同算法位级全等**（RTL vs Python 参考 0 误差）；与原图的 PSNR 仅作参考量（CFA 采样本身有损） |
| 单通道 8bit 输入 vs 工程以往 24bit 惯例 | 顶层/核接口按 8bit 单通道设计（DW=8），输出才打包 RGB888 |

## 被否决的替代方案

1. **新写 5×5 行缓存**：重复造轮子；line_buffer_nxn 已是参数化模板（N=5 直接可用），只需顶层补相位计数
2. **给 line_buffer_nxn 补坐标输出端口**：会改动共享模块、需回归其他工程；相位可由顶层计数推出（中心奇偶 = 当前像素奇偶），无需改模板
3. **直接上 MHC 版**（伪代码另一版，带细节项）：用户明确"双线性先用"；MHC 版依赖 5×5 更完整的邻域语义，适合在双线性版验证通过后增量做
4. **bg/bg 等其他 Bayer 排列**：用户确认 RGGB；如需扩展，相位表与 make_bayer 加参数即可（不阻塞本轮）
