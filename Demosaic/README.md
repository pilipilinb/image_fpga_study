## 项目简介

相机传感器每个感光点前面只有一个颜色滤镜（**CFA，Color Filter Array**），所以**每个像素只知道 R 或 G 或 B 中的一个值**——这就是 Bayer RAW 图。要得到彩色图片，就得用周围邻居"猜"出缺的两个通道，这个过程叫**去马赛克（Demosaic）**。

本工程做的：把 Bayer RAW 逐像素流式灌进来，攒出 5×5 窗口，看窗口中心是哪种颜色（相位），用邻居平均把 RGB 补齐。

- **5×5 窗口**：双线性算法实际只用中心 3×3 的邻居；做成 5×5 是为了后续 DPC（坏点校正）/MHC 版留余量
- **0 乘法器**：所有平均都是 2 的幂（4 个求平均 = >>2，2 个求平均 = >>1）——只有加减和移位
- **位级可验证**：与 Python 参考模型用同一套整数公式（含截断口径），实测逐像素 0 误差

## 原理：Bayer 阵列与四相位

最常用的 RGGB 排列（本工程用的）：

```
行0: R G R G R G ...      ← 偶数行：R 和 G 交替
行1: G B G B G B ...      ← 奇数行：G 和 B 交替
行2: R G R G R G ...
```

看一个像素的（行号奇偶, 列号奇偶）就知道它是什么颜色——这就是"相位"：

| 相位 | 位置 | 它有的颜色 | 缺的颜色在哪 |
|---|---|---|---|
| **R** | (偶, 偶) | R | G 在上下左右（十字 4 格）、B 在四个斜角 |
| **Gr** | (偶, 奇) | G | R 在左右、B 在上下 |
| **Gb** | (奇, 偶) | G | B 在左右、R 在上下 |
| **B** | (奇, 奇) | B | G 在十字 4 格、R 在四个斜角 |

## 双线性去马赛克公式

（照 Demosaic/伪代码.txt 的"双线性插值版"，`W[行][列]` 是 5×5 窗口，`W[2][2]` 是中心）

| 中心相位 | R 输出 | G 输出 | B 输出 |
|---|---|---|---|
| **R** | W22（直通） | (W12+W32+W21+W23)>>2（十字 4 个 G 平均） | (W11+W13+W31+W33)>>2（斜角 4 个 B 平均） |
| **B** | (W11+W13+W31+W33)>>2（斜角 4 个 R） | (W12+W32+W21+W23)>>2 | W22（直通） |
| **Gr** | (W21+W23)>>1（左右 2 个 R） | W22（直通） | (W12+W32)>>1（上下 2 个 B） |
| **Gb** | (W12+W32)>>1（上下 2 个 R） | W22（直通） | (W21+W23)>>1（左右 2 个 B） |

两点说明：
- **>> 后面不加舍入位**：伪代码就是直接截断（>>2、>>1 不加 +2/+1）——本工程严格照做，这样和 Python 参考能逐位对上
- **位宽**：4 个 8bit 相加最大 1020 < 2^10；2 个相加最大 510 < 2^9；移位后回到 8bit

## MHC 版（对比双线性，实测 +3.18 dB）

**一句话区别**：双线性只是“邻居求平均”，画面会发糊；MHC 在平均的基础上多减一项“远端同色像素”，把中心的细节量（高通）加回去——均值 + 锐化。

公式（伪代码.txt 的 MHC 版；`far4` = 离中心 2 格的十字 4 个像素，RGGB 下它们是同色）：

| 中心相位 | R 输出 | G 输出 | B 输出 |
|---|---|---|---|
| **R** | W22（直通） | ( 4·W22 + 2·十字4G − far4 ) >> 3 | ( 4·W22 + 2·对角4B − far4 ) >> 3 |
| **B** | ( 4·W22 + 2·对角4R − far4 ) >> 3 | ( 4·W22 + 2·十字4G − far4 ) >> 3 | W22（直通） |
| **Gr** | ( 2·W22 + 2·左右2R − 左右远2 ) >> 2 | W22（直通） | ( 2·W22 + 2·上下2B − 上下远2 ) >> 2 |
| **Gb** | ( 2·W22 + 2·上下2R − 上下远2 ) >> 2 | W22（直通） | ( 2·W22 + 2·左右2B − 左右远2 ) >> 2 |

**实现要点（与双线性的差别）**：
- 权重和仍是 2 的幂（R/B 相位 4+8−4=8 → >>3；G 相位 2+4−2=4 → >>2）→ **仍然 0 乘法器**
- **会出现负数和超 255**：减项在平坦/暗处可能更大（结果为负），加项在强边缘会超 255（如 3060>>3=382）
  → 实现上**正项、负项分开算**，只当“正 > 负”才相减，负的钳 0、结果超 255 钳 255（同 CSC 的“正负分开”做法）
- 接口与双线性核**完全一致**（win_flat + phase + valid）——顶层 `MHC` 参数换核，链路不改

**两版实测对比（同一张 Bayer 图，108×99）**：

| 指标 | 双线性 | MHC |
|---|---|---|
| vs 原图 PSNR | 26.05 dB | **29.23 dB（+3.18 dB）** |
| 两版互差 | — | PSNR 27.31 dB，94.2% 像素不同，平均绝对差 5.72 LSB，最大差 92 LSB（都在边缘处） |

结论：**MHC 更接近原图**（锐度回来了）；两版差异集中在边缘/细节区（平坦区几乎一样）——看图：[demosaic_bl_vs_mhc.png](demosaic_bl_vs_mhc.png)（原图 | 双线性 | MHC | 差异×4）。

## 架构与流水

```
din[7:0] ──► line_buffer_nxn（N=5，攒出 5×5 窗口）──► win_flat（25×8bit 打包）
                                                          │
行/列计数器 ──► 相位（看行列奇偶）──► 打 5 拍 ────────────►├─► demosaic_bilinear（按相位补 RGB）
                                                          ▼
                                              o_r/o_g/o_b + o_valid
```

**相位为什么要打 5 拍**（这是本工程的关键数字，靠 TB 扫描确定）：

| 延迟来源 | 拍数 |
|---|---|
| line_buffer_nxn 的行对齐链（valid_d[N-1]） | 4（= N-1） |
| matrix_valid 本身又寄存了一拍 | +1 |
| **合计：相位链要打** | **5** |

- 相位链必须**每拍都移**（不能用 din_valid 门控）：窗口那边的延迟链是"纯拍数延迟"（气泡拍也照样往前走），相位链要和它同构才能在输入有气泡时也对齐
- 窗口中心 = 右下角往回 2 行 2 列，**2 是偶数 → 奇偶不变** → 直接用"右下角像素的相位"当中心相位

## 调试记录（踩过的坑）

| # | 坑 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | **TB 参考拼接位宽** | 全错，且期望值只有 B 通道对（如 0000F4） | `{a, b, c}` 里 `(g3+g4)>>1` 是 **integer（32bit）表达式**，拼接变 72bit 赋给 24bit 只剩低 24 位 | 先把三通道各自截成 8bit（`reg [7:0] rr,gg,bb`）再拼接 |
| 2 | **相位延迟级数** | 前几个窗口对、之后成片错位 | 窗口延迟 = adly 链 4 拍 **+ matrix_valid 寄存 1 拍** = 5；相位链打 4 拍就差 1 个像素 → 列奇偶反转 → 相位全错 | 相位链参数化 PH_D，TB 扫 3/4/5/6/7 → **只有 5 PASS** |
| 3 | **相位链加 din_valid 门控**（错误修复） | 错误数从 21384 降到 6281 但仍错 | 窗口延迟链是**纯拍数延迟**（气泡拍也走），门控后两者在气泡处错位 | 相位链**每拍都移**（与窗口链同构），去掉门控 |
| 4 | **line_buffer_nxn 源码注释有误** | 按注释"行0列0=左下角"写映射 → 全错 | 实测（递增序列）证明是"行0列0=左上角"，win_flat[24]=右下角=当前像素，与伪代码 W[i][j] 同向 | 按实测映射 `W[i][j]=win_flat[(i*N+j)*DW]`，并在 tb_nxn_n5.v 注明 |
| 5 | **行计数器帧末不回绕**（DPC 工程暴露） | 单帧/两帧测试看不出来（纯色帧掩盖），DPC 三帧测试报 537 个 MISMATCH | `row_cnt` 到 IMG_H-1 后继续加 → 第二帧行号奇偶全反 → 相位错 | 行号帧末回绕到 0（本工程已同步修复，两版回归 PASS）；教训：**多帧测试才能暴露单帧掩盖的 bug** |

**经验小结**：
- **延迟对齐要"同构"**：跨模块对齐时，两条链的推进规则（纯拍延迟 vs 有效拍驱动）必须一致，否则一遇气泡就错位
- **不确定的延迟就扫参**：PH_D 用编译宏扫一遍比纯推理快且可靠（实测最重要）
- **模板用前先回归**：N=5 是未验证前提（原来只验过 N=3/N=4），先花 10 分钟回归省几小时误判

## 面试要点

1. **Bayer 与相位**："传感器每点只有一个颜色，RGGB 排列下看行列奇偶就知道中心是什么色——R/Gr/Gb/B 四种相位对应四套补色公式。"
2. **双线性的本质**："缺的颜色用最近的同类像素平均：R/B 相位十字取 G、斜角取另一个色；G 相位左右/上下各取一个。全是 2 的幂平均，只有加减和移位，0 乘法器。"
3. **5×5 窗口 vs 只用 3×3**："双线性只要 3×3，但工程上做 5×5 是为 DPC（坏点校正）和 MHC（带细节增强的插值）留余量——接口不用改。"
4. **相位对齐**："窗口比输入晚 5 拍（N-1 对齐链 + matrix_valid 寄存 1 拍），相位链必须同构地打 5 拍、且每拍都移——这是本项目最容易错的地方。"
5. **验证策略**：“Bayer 采样本身有损，'输出 vs 原图'的 PSNR 只能当参考；正确性判据是**与 Python 参考逐位全等**（同整数公式 0 误差）。”
6. **双线性 vs MHC（实测）**：“双线性只是邻域平均，边缘会糊；MHC 多减一项远端同色像素（把中心的细节量加回去），实测比双线性 **+3.18 dB**。代价是多用 5×5 窗口的外圈像素，且必须处理负数和超 255（正负分开 + 饱和）。”

## 使用方式

```powershell
# 1. 步骤 0：N=5 窗口模板回归（已验证通过，可跳过）
iverilog -I . -o tb_n5.vvp tb_nxn_n5.v; vvp tb_n5.vvp > sim_n5.txt

# 2. 生成 Bayer 输入 + Python 参考 + 对比图
python make_bayer.py

# 3. 跑 RTL 仿真（含真图 + 纯色两帧）
iverilog -I . -o tb.vvp tb_demosaic.v; vvp tb.vvp > sim_log.txt

# 4. 独立校验（RTL vs Python 参考全等）+ 对比图（双线性版）
python verify_demosaic.py

# 5. MHC 版：换编译宏就行（输出到 output_mhc.coe）
iverilog -DMHC -I . -o tb_mhc.vvp tb_demosaic.v; vvp tb_mhc.vvp > sim_mhc.txt

# 6. 两版对比（PSNR 差异 + 差异图）
python compare_versions.py

# 相位延迟扫参（可选）：-DPH3 / -DPH4 / 默认 PH5 / -DPH6 / -DPH7
iverilog -DPH4 -I . -o tb.vvp tb_demosaic.v
```

## 已知限制与后续

- **输出裁掉两圈**：(W-4)×(H-4)——5×5 窗口中心需要完整邻居；需要全尺寸可做 pad 版（边缘复制）
- **暂不含 DPC**：坏点校正待后续（5×5 窗口已备好）
- **MHC 版已实现**（与双线性接口相同，`-DMHC` 切换）；两者差异集中在边缘/细节区（实测 +3.18 dB）
- **Bayer 排列固定 RGGB**：换 BGGR/GRBG/GBRG 只需改相位表与 `make_bayer.py` 的采样规则
- **模板注释待修**：line_buffer_nxn.v 里“行0列0=左下角”应改为“左上角”（共享模块，改动需回归其自带 TB）
