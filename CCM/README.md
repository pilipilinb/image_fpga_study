# CCM —— M4-2 色彩校正矩阵（线性 RGB 域，10bit）

ISP 链第六级（M4 第二模块）：**色彩校正矩阵**（Color Correction Matrix）。输入 = M4-1 降噪出的线性 RGB 10bit 简流（`in_data[29:0]`），输出同格式。算法来源 [伪代码.c](伪代码.c)（用户提供），定点化方案与架构决策见 [CCM实现计划.md](CCM实现计划.md)。

## 伪代码核对（5 处修正 + 1 处工业补强）

| # | 伪代码 | 问题 | 本实现 |
|---|---|---|---|
| 1 | `clamp(..., 0, 255)` | **8bit 与链路契约冲突**（线性 RGB 域全程 10bit，缩减在 Gamma 出口） | `clamp(..., 0, 1023)`，输出 3×10bit |
| 2 | `>>>` | Python 无 `>>>`（Java/JS 写法）；Verilog 里 `>>>` 才是**算术**右移且需 `signed` | Python 用 `>>`；RTL 用 `>>>` + signed |
| 3 | "acc 是 25bit 有符号" | 那是**按 8bit 输入**算的（3×8192×255≈2^22.9）；10bit 输入上界 3×32768×1023≈**2^26.6** → 溢出 | **28bit 有符号**（证明见计划 §2.3） |
| 4 | `round(M·2^FRAC)` | Python `round()` 是**银行家舍入**，与运行时 `+2^(F-1) 再 >>F`（round-half-up）**不自洽** | 系数用 `floor(x·2^F+0.5)`，与运行时同规则 |
| 5 | （实施计划）"负系数钳 0" | 易误读为"把矩阵负系数改成 0"——那 CCM 就废了（**负系数正是通道解耦的本钱**） | 真实含义 = **结果钳 0**（clamp 下界） |
| ➕ | — | 行和量化残差 → 灰阶带 1/4096 直流偏色 | **残差补对角项** ⇒ 行和精确 = 4096 ⇒ 灰阶逐位保持 |

## 参数（10bit 域）

| 量 | 值 | 说明 |
|---|---|---|
| 系数定点 | **Q5.12**（FRAC=12） | 分辨率 1/4096 ≈ 0.024% |
| 定点系数 | `[[7046,-2540,-410],[-983,5898,-819],[205,-2089,5980]]` | 行和均 = 4096（第 0 行含 +1 残差补偿） |
| 系数位宽 MW | 16bit 有符号 | 覆盖 \|M\| ≤ 8.0 |
| 乘积位宽 PW | 27bit 有符号 | MW+DW+1 |
| 累加器 AW | **28bit 有符号** | 上界 3×2^15×1023 < 2^26.6 ✓ |
| 流水 | **LAT = 2** | T0 组合乘加 → T1 寄存 acc → T2 舍入/移位/饱和 |
| 资源 | **9 个 16×11 乘法器**（DSP48）；**无 BRAM、无行缓存** | 全链唯一必须用 DSP 的一级 |
| bypass | **等延迟旁路**（2 拍链 + 出口 mux） | 可任意拍切换 |

## 验证结果

| 判据 | 结果 |
|---|---|
| 协议 TB（16×12，6 场景：A 满速 2 帧 / B 汇随机 50% / C 长拉低 / D 双向随机 / E bypass 帧间×3 / F **帧内热切换**） | **[PASS]** fire 1728 = 收 1728，0 误差，稳定性断言零违例 |
| 真图 TB（112×103，M3 链出图） | **[PASS]** 11536/11536 |
| 色卡 TB（96×64，24 块拼接） | **[PASS]** 6144/6144 |
| Python 独立第二判据：真图位级比对 | **全等 0 误差**（11536 像素） |
| **灰阶保持**（CCM 的核心判据） | 穷举 v=0..1023 **全部逐位不变**；RTL 真图上 262 个灰像素**全部保持** |
| **ΔE76**（24 色卡，用 RTL 输出算） | 校正前 **12.14**（最大 40.67）→ 校正后 **0.12**（最大 0.58）；灰阶 6 块 ≈ 0 |

**读法**：ΔE 均值降至 0.12（≈ 视觉不可辨），残余来自定点量化（Q5.12）与越界裁剪；灰阶块 ≈ 0 是"行和精确 = 4096"的直接证据。

## 设计要点

1. **定点化三件事**：① 系数 `floor(x·2^F+0.5)` 与运行时 `+2^(F-1)>>F` **同一套 round-half-up 规则**（否则 golden 与 RTL 不一致）；② 加数和被加数**都必须有符号**，否则 Verilog 按无符号做算术移位、负数全错；③ **饱和不可省**——减法出负、增益溢出，clamp 是唯一兜底。
2. **行和 = 1 的工程价值**：保中性色；定点化后把残差补到对角项（|系数|最大 → 相对误差最小）⇒ 行和精确 = 2^FRAC ⇒ 灰阶输出**逐位**不变（消直流偏置，多级链上尤其重要）。
3. **LAT=2 的取舍**：T0 组合（9 乘 + 加树）→ T1 寄存 acc → T2 舍入/移位/饱和。乘加是关键路径，独立成一拍利于时序；宽松时钟下可压成 LAT=1。
4. **bypass 实现方式由"处理路径延迟"决定**（★ 架构边界对比点）：
   - CCM 逐像素级、无行缓存、LAT=2 → **等延迟旁路**（旁路链打 2 拍），两路延迟严格相等 ⇒ **可任意拍切换**（连帧中间切换都对）
   - 对比降噪：处理路径含行缓存（延迟 `K·W+K + 3` ≈ 上万拍）→ 只能"排空点切换"
5. **与白平衡的关系（面试高频）**：WB 是**对角阵**修色温、CCM 是**满阵**修串色；WB 必须在 CCM **之前**（`WB·CCM ≠ CCM·WB`）。链路里 WB（M6）插在 Bayer 域，CCM 在线性 RGB 域，次序天然正确。
6. **系数可配**：本模块用 `$readmemh` 静态表；集成阶段换 AXI-Lite 动态写表（内容换、结构不动）。

## 踩坑记录（三条）

1. **TB 稳定性断言用错了拍**：写成"当拍 `out_valid && !out_ready` ⇒ 数据必须保持"，结果报 183 个假违规。**正确判据是"上一拍 valid=1 且 ready=0（stall）⇒ 本拍（若仍 valid）字段不变"**——`stall` 是**上一拍**握手的结果，用当拍 ready 判会把"刚被消费后换新值"误判为违规。
2. **复用 TB 模板时文件名约定没对齐**：Python 生成 `ccm_img_out.hex`，而 TB（抄自降噪）读 `exp_img.hex` → `$readmemh` 读不到、期望全 0 → 11536 全错。**教训**：跨语言的文件名约定属于接口，复用模板时先对齐。
3. **三个模式共用一个 dump 文件名**：small/IMG/CHART 都写 `ccm_out.txt`，互相覆盖 → verify 拿到错数据集。改成按模式区分（`ccm_out.txt` / `ccm_out_img.txt` / `ccm_out_chart.txt`）。

## 面试点清单

1. **CCM 干什么**：把 sensor 的光谱响应校正到标准色空间（3×3 满阵）
2. **为什么必须有负系数**：正对角阵只能做增益（= 白平衡）；只有负的非对角项才能"扣掉别的通道串进来的分量"——**负系数是 CCM 的标志**
3. **WB vs CCM**：对角阵修色温 / 满阵修串色；WB 必须在 CCM 之前（矩阵不可交换）
4. **为什么必须饱和**：减法出负、增益溢出，clamp 是唯一兜底
5. **定点化**：Q5.12 + round-half-up；系数与运行时同一套舍入规则
6. **行和 = 1 的定点实现**：残差补对角项 ⇒ 灰阶逐位保持（消直流偏置）
7. **全链唯一用 DSP 的一级**：9 个 16×11 乘法，预算与复用方式
8. **bypass 的两种实现与边界**：延迟差小 → 等延迟旁路（可热切换）；含行缓存 → 排空点切换
9. **ΔE 量化**：24 色卡 12.14 → 0.12，残余 = 定点量化 + 越界裁剪
