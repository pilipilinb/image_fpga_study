## 三、核心设计题（先想透，再写代码）

### 3.1 PL 还是 PS：分工与理由

| 功能 | PL（FPGA） | PS（MicroBlaze） | 为什么这么分 |
|---|---|---|---|
| 逐像素统计累加 | ✅ | — | 1 pixel/clock 的活只有硬件干得过来；旁挂累加，不占数据通路 |
| shadow 快照 / 帧号 / 中断 | ✅ | — | 帧边界的"原子搬家"是硬件一拍的事，软件做必然引入等待 |
| 逐像素增益应用（乘+round+饱和） | ✅ | — | 同上，像素级流水 |
| 均值、灰世界增益、限幅、Q2.8 打包 | — | ✅ | 帧级任务（每帧一次、微秒级）；**除法器不上 FPGA**；算法改动用 C 写，RTL 一行不改（换白点法/加权灰世界都行） |
| 读写寄存器 | 提供寄存器 | ✅ `Xil_In32/Xil_Out32` | 控制面走 AXI-Lite（项目既定方向） |
| 闭环调度 | 发 irq / 维护帧号 | ✅ ISR 或轮询 | 软件超时/卡死最坏只让增益晚几帧生效，**数据流永不受影响** |

一句话：**数据面全在 PL（旁挂统计 + 逐像素乘法），控制面全在 PS（帧级除法 + 决策）**——这就是工业 3A 的标准形态，也是面试叙事点（"软核负责灵活性，PL 负责吞吐"）。

**统计 tap 放哪**：放在 DPC 出 = `awb_gain` 入（与占位同一位置）。理由：
1. DPC 用绝对阈值 THR 判缺陷，必须在**原始 RAW 域**完成（不受增益漂移影响——既有计划结论）；
2. 先修掉坏点再统计，亮/暗坏点（1023/0）不会污染统计；
3. 统计与增益应用解耦（开环）：灰世界是"比值"运算，统计原始域即可，不需要叠加自身增益，不会振荡。

### 3.2 "软核交互的时候 FPGA 在干什么"：逐时刻时间线 + 断流分析

**不会断流。** 先给结论，再看时间线。以连续流（无消隐）为例，帧号用 N：

| 时刻 | PL 在干什么 | PS 在干什么 |
|---|---|---|
| 帧 N 像素流期间 | ① 统计累加器随 **fire 拍**加 1 次（旁挂，不占拍、不握手）；② 增益用 active 寄存器值乘 | 可能在读帧 N-1 的快照、算增益、写 gain 写口（**走 AXI，与像素域物理隔离**） |
| 帧 N+1 首拍（SOF fire） | **一拍内原子完成 4 件事**：shadow ← work（帧 N 全量）；work ← 本拍像素（重启）；frame_cnt+1；gain 采样（active ← 写口值，且**本拍首像素的组合选源直接取写口**——首像素即用新值）。同拍数据照常流过乘法通路 | 无感（PL 拍内自转） |
| 帧 N+1 期间 | 继续统计帧 N+1；增益用刚采样的值 | 收到 irq / 轮询到帧号变化 → 读 4 个 shadow（Xil_In32×4）→ 整数除法算增益 → 写 4 个写口（Xil_Out32×4），全程 µs 级 |
| 帧 N+2 首拍（SOF fire） | gain 采样把 PS 写好的值搬进 active → **帧 N+2 起启用新增益** | 空闲/等下一轮 |

**四条"不断流"的机制**（缺一条都可能引入 stall，我们全做好了）：
1. **统计是旁挂**（tap）：不插入数据通路、不增加拍数、不参与握手——数据流的 `valid/ready` 与它无关；
2. **读的是冻结快照**：shadow 组在 SOF 拍一拍摄替换（原子），PS 读多久都不影响像素流；
3. **写与生效分离**：PS 写"写口"永不阻塞；生效由 PL 在帧边界自动做（下一节 3.4 详述）；
4. **控制面/数据面物理隔离**：AXI 走系统时钟域、像素走流水时钟域，最坏情况只是"增益晚一/几帧生效"，**吞吐永远 1 pixel/clock**。

反面教材（我们不这么设计）：让软核直接修改"生效寄存器"且硬件等待软核写完、或把统计放进数据通路做握手——那才会 stall。

### 3.3 闭环延迟：为什么是"统计帧 N → 帧 N+2 起生效"

连续流下帧间没有空隙，且 SOF 拍才是"上一帧统计封存 + irq 发出"的时刻：

```
帧 N+1 SOF 拍：帧 N 统计封存 → 发 irq     ──►  PS 只能在帧 N+1 期间算（连续流下它最早此刻才拿到数据）
帧 N+2 SOF 拍：gain 采样                  ──►  帧 N+2 起生效
```

⇒ 精确口径：**"统计帧 N → 计算于帧 N+1 → 帧 N+2 起生效"**（中间隔一个计算帧是必然的，因为 gain 采样点只能是帧边界，否则帧内两段用不同增益）。
30fps 下多一帧 = 33ms，对 AWB 收敛完全无感。

> **对既有计划的修正**：实施计划 M6 节与 M5.3 文档里写的"统计第 N 帧、增益第 N+1 帧生效"是直方图那种 **PL 内部闭环**的口径（软件不参与）。软核闭环下真实节拍 = **N+2**，本文件以 N+2 为验收口径；全局 README §7、实施计划 §八b、FpgaIspChain 两处文档承诺已同步修正（见 §6 清单）。
> **面试加分点**：如果未来把"计算"也硬件化（PL 小 FSM + 迭代除法），可缩回 N+1——"软核换灵活性、硬件换一帧延迟"的 trade-off 值得讲。

### 3.4 增益更新的原子性：inactive → active 帧边界采样

- PS/顶层写口（`awb_gain_00..11` 端口）叫 **inactive**；像素实际用的是 **active** 寄存器；**两者复位默认 = 2^GF（1.0）**——保证复位后天然恒等（M5.3 回归不受影响）；
- 每个 **SOF fire 拍**执行 `active <= inactive`（4 路**整组一拍摄采样**——软核没写就等于采旧值）；
- **★ 采样与首像素同拍生效（评审实锤，必做）**：乘法组合选源 = `in_sof ? 写口 : active`。SOF 拍本身是本帧第 1 个像素（相位 00），若照"先采样后使用"写，首像素会拿到**上一帧的 active** ⇒ 帧内恒定被破坏、逐帧位级验收直接失败。SOF 拍 stall（未 fire）时 `in_sof` 与数据一起保持，解除后仍是同一拍语义，无错拍风险；
- 好处：① 帧内增益恒定（**从首像素起**，不会一帧内一半新一半旧）；② **不依赖软核时序**——早写早生效、晚写自动滑到下一个帧边界，绝不产生坏帧；
- 仿真阶段由 TB 直接驱动端口模拟"软核写"；上板阶段这 4 个寄存器由 AXI-Lite 从机驱动（数值语义不变）。
- 与项目铁律一致："**帧级参数（bypass / 强度 k / 增益）改动必须落在排空点**"——这里排空点就是 SOF。

### 3.5 交互机制选型：AXI-Lite vs AXI-GPIO vs 替代方案

先把事实摆平：**在 MicroBlaze 体系里，AXI-GPIO 和自研 AXI-Lite 在软件侧确实"差不多"**——两者都是挂 AXI 互联的从机、都占一段地址、都用 `Xil_In32/Out32(基地址+偏移, ...)` 访问。你理解的 BD 流程完全正确：

```
BD：MicroBlaze → M_AXI → SmartConnect → ↑从机：自研 AXI-Lite IP（或 AXI-GPIO）
Address Editor：给从机分配一段地址（如 0x44A0_0000，4KB）
→ 导出 XSA → Vitis BSP 生成 xparameters.h（BASEADDR 宏）→ C 里 Xil_In/Out32 按偏移读写
```

差别不在软件，而在"**寄存器语义与数量**"：

| 维度 | AXI-GPIO | **自研 AXI-Lite 寄存器文件（推荐）** |
|---|---|---|
| 寄存器 | IP 固定（每通道 1 个 DATA + 方向寄存器） | 想要几个要几个（本需求 **11 条** 32bit） |
| 数量 | 1/2/4 通道，10 个值要 3 个 IP + 位域拼接 | 一个 IP 一段地址全装下 |
| 帧语义（shadow 快照 / 帧边界采样 / 帧号 / irq） | **一个都没有**，要另写 PL glue 逻辑 | 和像素逻辑做在一起，天然一体 |
| 扩展 | 每加一组参数加一个 IP | 寄存器表加一行 |
| 终局形态 | 过渡工具 | **本项目最终的"ISP 自定义 IP + AXI-Lite 控制面"模板**（BLC 偏置/DPC 阈值/CCM 系数后续并进来） |

**结论：上板就用自研 AXI-Lite 从机**。理由一句话：软件工作量一样的前提下，它把语义做进硬件、可扩展、也是"自研 ISP 替换官方 Sensor Demosaic IP"的既定终局。

**"有更简单的方法吗？"——按场景给三个答案：**
1. **仿真阶段最简**：完全绕开总线——TB 里用一段 `always` 写"行为模型软核"（看帧号 → 读 stat 端口 → 整数除法 → 写 gain 端口）。这就是 Step 3，先闭环再总线，**是本计划的主路径**；
2. **上板最简（能跑）**：AXI-GPIO 拼接线——能通，但语义弱、要拼 3 个 IP、PL glue 一点没省，只适合"一小时内先看见灯亮"；
3. **上板正规（推荐）**：自研 AXI-Lite 从机（写通道 + 读通道各一个小状态机 + 寄存器 bank，≈150~200 行 RTL），Vivado 新建 IP 时可直接用向导模板改。它本身还是很好的 AXI 握手学习点（面试可讲 AW/W/B/AR/R 五通道时序）。
   - 中断可选：`awb_irq` → AXI INTC 或直接进 MicroBlaze 中断引脚；**首版推荐轮询**（每 ms 读一次帧号寄存器，简单可靠、不碰 INTC 配置），中断留作优化项。

**寄存器映射草案**（Step 4 定稿；地址宽度可裁到最小）：

| 偏移 | 名称 | 读/写 | 说明 |
|---|---|---|---|
| 0x00 | AWB_STAT_00 | R | R 相位累加和（shadow，帧 N） |
| 0x04 | AWB_STAT_01 | R | Gr 相位累加和 |
| 0x08 | AWB_STAT_10 | R | Gb 相位累加和 |
| 0x0C | AWB_STAT_11 | R | B 相位累加和 |
| 0x10 | AWB_FRAME_CNT | R | **快照组帧号**：与该组 4 个 stat **同拍原子更新**（既判断"有没有新数据"，也是"读前读后校验"的判据） |
| 0x14 | AWB_GAIN_00 | R/W | Q2.8 增益写口（inactive） |
| 0x18 | AWB_GAIN_01 | R/W | 同上 |
| 0x1C | AWB_GAIN_10 | R/W | 同上 |
| 0x20 | AWB_GAIN_11 | R/W | 同上 |
| 0x24 | AWB_CTRL | R/W | 使能 / irq 使能 / 软复位（保留） |
| 0x28 | AWB_STATUS | R | 只读状态（帧有效等，保留） |

**VIO 与 AXI-Lite 的定位分工（上板调试策略，用户提问补充）**：

顶层那些配置端口（`ob_00..11` / `bp_*` / `sharpen_k`）**可以**用 VIO 输出探头驱动，AWB 的 `awb_gain_*` / `awb_stat_*` 则**必须**走 AXI-Lite——分界线在于"**软核能不能访问**"：

| | VIO（Virtual I/O） | AXI-Lite 寄存器文件 |
|---|---|---|
| 谁能改/读 | 只有 PC 端 Hardware Manager（**人手动**） | **MicroBlaze 软件**（`Xil_In32/Out32`）+ 人（可选） |
| 地址空间 | 无（JTAG 调试域） | 有（软核可寻址） |
| 能做软核闭环 | ❌（软核根本访问不到 VIO） | ✅（唯一选择） |
| 帧边界语义 | 无（手动改随时可能落在帧中） | 有（硬件在 SOF 拍采样，帧内恒定） |
| 适用 | **调试期手动试参数**：ob 标定值/K 值/bp 组合试效果；awb_stat、帧号、irq **数值观测**（比 ILA 省资源，ILA 抓波形、VIO 看数值） | **正式控制路径**：AWB gain/stat（硬需求）；后续所有帧级参数逐步并入 |

⇒ 实用策略：上板先在 VIO 下把 ob 标定值 / k / bp 组合手动试好（VIO 保留作调试旁路）；
**AWB 的 gain/stat 从第一天就走 AXI-Lite**——因为闭环要求软核读写，VIO 做不到；
其余参数（ob/bp/k/THR 等）在 P3 集成时按同一张寄存器表模板逐步并入。
注意：`bp_*`/`sharpen_k` 是**帧级参数**（改动要落在排空点），VIO 手动改没有这层保护——调试可以、正式必须经寄存器 + 帧边界采样。

### 3.6 抗风险清单（仿真/上板都要防的点）

| 风险 | 处理 |
|---|---|
| **反压期重复统计** | 统计只在 **fire 拍**（`in_valid && in_ready`）累加——stall 期数据冻结但 valid 保持，按 valid 累加会把同一像素数很多次 |
| **SOF 拍像素被"清零"吞掉（统计级）** | SOF 拍语义 = `shadow ← work` 且 `work ← 本拍像素`（不是清零）——每帧第一个像素必须进新组 |
| **SOF 拍首像素用旧增益（增益级）** | 组合选源 = `in_sof ? 写口 : active`——采样与首像素同拍生效（见 3.4）；否则每帧首像素"半新半旧"，位级验收必失败 |
| **复位语义（新模块必须定义）** | `active`/写口复位 = `2^GF`（1.0 恒等）；`work/shadow 累加器、快照组 fc、live fc` 复位 = 0；`irq` 复位 = 0。TB 增补"运行中复位→释放→重收"场景（统计从头计、增益回 1.0、无 X） |
| **读数"半新半旧"** | 两级措施：① 硬件——**快照组（4 stat + fc）同拍原子更新**（先决条件）；上板时**整组经同一 toggle 同步**到 AXI 域（组内永远一致）；② 软件——读 fc → 读 4 个 stat → 再读 fc，前后不等 ⇒ 读一半时组被替换 ⇒ 重读（30fps 下窗口充裕） |
| **首帧无效数据** | 复位后第一次 swap 出的 shadow 是初值 0 ⇒ 软件规则："`fc ≥ 2` 才使用，且读到的统计对应帧 `fc-1`"，irq 照发（软件忽略） |
| **除零（近黑帧）** | `max(mean, 1)` 保护；增益限幅兜底 |
| **增益超版权限** | Q2.8 上限 3.996 ⇒ 软核 clamp 到 `[128, 1023]`（≈[0.5, 4.0]，差 0.1% 无实际影响）；**从机寄存器侧再做一次硬 clamp**（防非法写值 0/越界产生黑帧） |
| **上板 CDC（AXI 钟 ≠ 像素钟）· 双向** | ① 写方向（AXI→像素，增益）："**数据不动、标志同步**"——**4 个 gain 写完后提交一次 toggle**（不逐寄存器翻转），toggle 在像素域打 2 拍同步后生效（检测到变化时数据已稳定 ≥2 个像素钟），在 SOF 拍搬迁。② 读方向（像素→AXI，统计）：快照组（4 stat + fc）经**同一 toggle 整组**同步进 AXI 域可读组；irq 同理。仿真同钟两向都退化直连 |
| **统计位宽溢出** | 最坏 1920×1080：每相位 518400 像素 × 1023 ≈ 2^29 ⇒ **32bit 累加器足够** |
| **时序（OOC）** | 统计加法器是旁挂路径；gain 乘法 stub 已验证。交付前照规矩跑 `synth_ooc_timing.tcl` 整链复检，确保 WNS 不低于 +1.589ns 基线 |

## 四、AWB 伪代码审查（用户提供版本，逐条分析）

**总判定：架构骨架正确（工业 3A 的标准形态），但要按本项目的"域 / 位宽 / 接口约定"做 7 处修正。**

| # | 伪代码原文 | 判定 | 修正 / 说明 |
|---|---|---|---|
| 1 | 三个累加器 `accumulate_R/G/B`、RGB 域 | ✏ 改 | 本项目在 **Bayer 域四相位**（R/Gr/Gb/B），要 **4 组**累加器、按 `(row&1,col&1)` 相位分发（硬件已有 `in_phase` 直接可用） |
| 2 | `pixel_cnt` 单计数 | ✏ 改 | Bayer 下四相位各占 1/4（RGGB、宽高为偶）；**软核直接用编译期常量 `W·H/4`** 作计数，顶层 4 个 stat 端口不装计数（分辨率板上固定；如需奇数宽再扩端口） |
| 3 | "SOF 到来：四值搬进 shadow，原组清零" | ✏ 改 | 方向对（乒乓/影子），但**"清零"漏了 SOF 拍本身的像素**——正确语义：`shadow ← work`（上一帧全量）**且** `work ← 本拍像素`；否则每帧吞 1 个像素 |
| 4 | "软核读 shadow 不掐时间，不会读到一半被新数据改写" | ❌ 不严谨 | **存在极小概率的"半新半旧"窗口**（读第 2 个寄存器时恰逢 swap）。修正：**快照组（4 stat + fc）同拍原子更新**（先决条件）+ 软件读 fc→stat→fc 校验重读（3.6）；上板时整组经同一 toggle 同步到 AXI 域 |
| 5 | `gain = clip(G_mean/R_mean, 0.5, 4.0)`，Q4.12@16bit | ✏ 改 | ① 本项目顶层已定 **Q2.8@10bit**（1.0=256）——按 `+2^7 >> 8`、饱和 1023 实现；上限 4.0 编码成 1023（=3.996≈4.0）；② **除零保护** `max(mean,1)`；③ 推荐四增益全算：参考 `G_ref=(mean_Gr+mean_Gb)/2`，`gain_i = clip((G_ref<<8)/max(mean_i,1), 128, 1023)`（充分利用四相位自由度，也正好回应 BLC_DPC 实验里 Gr/Gb 黑电平差 116 LSB 的遗留问题） |
| 6 | `product += (1<<11); result = product >> 12; if >255: 255` | ✔ 对但按位宽缩放 | 四舍五入+饱和的写法正确（round-half-up）。按本项目：`10bit × 10bit = 20bit`，`+2^7 >> 8`，饱和阈值 **1023**（不是 255）。stub 里已是这个结构，直接用 |
| 7 | 缺项 | ➕ 补 | ① 增益**帧边界生效机制**（软核写写口、硬件 SOF 采样，且**首像素与采样同拍用新值**——伪代码没有，是保证帧内一致的关键）；② **首帧有效标志/帧号**；③ 反压期"fire 口径"（见 3.6）；④ 使能/限幅可配（AWB_CTRL）；⑤ 复位语义（见 3.6） |

**适配后的本项目版本（三段伪代码，施工直接照抄）**：

```text
---- PL · awb_stat.v（旁挂统计，0 拍透传）----
每 fire 拍： case(phase): 00..11 各自 sum_p += in_data
SOF fire 拍： shadow_00..11 <= sum_00..11       # 上一帧全量（原子搬家）
              sum_p         <= (p==本拍相位) ? in_data : 0   # 新组从本拍像素重启
              frame_cnt<=frame_cnt+1;  irq<=1  # 1 拍脉冲
（注意：非 SOF 拍是 sum_p += in_data；SOF 拍是"整组换新+含本拍像素"）

---- PS · 软核任务（轮询或 ISR，每帧一次）----
fc = Xil_In32(AWB_FRAME_CNT);  if (fc<2 || fc==last_fc) return;   # 无新帧/首帧无效
s00=.., s01=.., s10=.., s11=..                 # Xil_In32 ×4；再读 fc 一致才采用
m00=s00/CNT; m01=s01/CNT; m10=s10/CNT; m11=s11/CNT;   # CNT=W*H/4 常量
mg=(m01+m10)>>1;
g00=clamp((mg<<8)/max(m00,1),128,1023);  ... g11=...
Xil_Out32(AWB_GAIN_00,g00); ... x4           # 写写口（inactive）
last_fc=fc;

---- PL · awb_gain.v（逐像素应用，1 拍流水，stub 增强版）----
寄存器： active_00..11（复位 = 2^GF = 1.0）；写口 wr_00..11（inactive，来自端口/从机）
每 SOF fire 拍： active_00..11 <= wr_00..11   # 帧边界采样（整组原子，一拍全搬）
每像素： gain_now = in_sof ? wr_phase : active_phase   # ★ SOF 首像素直接用新值
         prod=in*gain_now; out=(prod+2^7)>>8; 饱和到 [0,1023]
```

## 七、M6 验收标准（汇总）

1. **统计级**：透传位级 0 误差；四相位统计 vs Python 独立复算 0 误差；反压期不重复计数；帧号/中断正确；
2. **增益级**：位级 0 误差（Python 同公式）；写口 → 帧边界采样生效逐拍正确（**含首像素用新值**）；
3. **闭环**：**统计帧 N → 帧 N+2 起生效**逐帧位级吻合；软核迟响应容错演练通过；
4. **整链回归**：M5.3 全部 TB 重跑 PASS（恒等性保持）；真增益图像模式 PSNR + 对比图；
5. **时序**：整链 OOC 复检不低于 +1.589ns/17 级基线；
6. **上板（P3）**：软核闭环实拍收敛，色偏消除。

## 八、假设与暂不定项

1. 统计口径假设：**完整帧 + 宽高为偶 + RGGB** ⇒ 四相位像素数相等（=W·H/4，软核用常量）；如需奇数宽支持，扩 `stat_cnt` 端口；
2. 首版**不做**：帧间增益平滑（ramp）、分区域统计（中心窗）、每 N 帧统计降频——都列入"可选优化"，RTL 结构预留（都在软核/寄存器侧，加时不改流水）；
3. CDC：仿真同钟**退化直连**；上板若 AXI 钟 ≠ 像素钟，按 3.6 的"数据不动、标志同步"**双向**补（写：增益组提交 toggle；读：快照组整组同步），留集成阶段；
4. 中断：首版轮询为主，irq 端口照做（硬件成本≈0），INTC 配置留优化项；
5. `awb_stub.v` 保留不删（历史对照），最终以 `awb_top` 为链路实体。
