# line_buffer_nxn 对齐原理、难点与要点速查

> 本文档配套代码：`line_buffer_nxn.v`｜时序图：`line_buffer_nxn_alignment.svg`｜Testbench：`tb_line_buffer_nxn.v`

---

## 一、整体架构（一句话）

```
N-1 块 BRAM 级联做行延迟 + 对齐延迟链 (adly) + N×N 横向移位寄存器 → 输出 N×N 窗口
```

**输入**：逐行光栅扫描像素流（`din` + `din_valid`，可带气泡）  
**输出**：以当前像素为右下角的 N×N 窗口（`win_flat` + `matrix_valid`），边缘 crop 不出窗

---

## 二、对齐原理——这是本模板的核心

### 2.1 问题描述

一个像素 `P(r,c)` 在 T 拍进入 `din`。我们希望在第 T+(N-1) 拍时，窗口的一列能同时包含：

| 窗口行 | 期望的数据 | 从哪里来 |
|--------|-----------|---------|
| 底行 i=N-1 | P(r,c) 当前行 | `pix_d[N-1]` |
| 中间行 i | P(r-(N-1-i), c) 上若干行 | BRAM 读出 |
| 顶行 i=0 | P(r-(N-1), c) 最深行 | 最后一块 BRAM 读出 |

**难点**：不同行的数据"出生"时刻不同，但窗口采样是同一拍，必须让它们"等齐"。

### 2.2 对齐规律（核心公式）

```
BRAM 第 m 块（m=1..N-1）：
   使能时刻 = T+(m-1)   →  读出时刻 = T+m
   读出数据 = P(r-m, c)
   需要等待 = (N-1) - m 拍

当前像素 din：
   出生时刻 = T
   需要等待 = (N-1) 拍
```

### 2.3 具体实现映射

```
【等待拍数 = (N-1) − 出生偏移】

窗口行 i     | 出生偏移 | 等待拍数 | 最终寄存器
-------------|---------|---------|---------------------------
底 i=N-1     | 0       | N-1     | pix_d[N-1]（打 N-1 拍）
中间行 i     | N-1-i   | i       | adly[N-1-i][i]（打 i 拍）
顶 i=0       | N-1     | 0       | stream[N-1]（无需等待）
```

### 2.4 以 N=4 为例（对照时序图）

参见 `line_buffer_nxn_alignment.svg`，核心观察：

| 窗口行 | 数据 | 出生拍 | 出生寄存器 | 等待拍数 | 对齐后喂给窗口 |
|-------|------|--------|-----------|---------|-------------|
| 行3 底 | P(r,c) | T | `din` | 3 拍 | `pix_d[3]` |
| 行2 | P(r-1,c) | T+1 | `stream[1]` (BRAM1) | 2 拍 | `adly[1][2]` |
| 行1 | P(r-2,c) | T+2 | `stream[2]` (BRAM2) | 1 拍 | `adly[2][1]` |
| 行0 顶 | P(r-3,c) | T+3 | `stream[3]` (BRAM3) | 0 拍 | `stream[3]` 直接用 |

**三句话概括**：
1. 每行数据的"★出生"时刻由它在第几块 BRAM 决定：底行 T 拍出生，往上每层晚 1 拍。
2. 窗口只在 T+(N-1) 拍采样，出生早的行要用 `adly`/`pix_d` 一级级等待到那一拍。
3. **等待拍数 = (N-1) − 出生偏移**：出生越早等越久，出生最晚的顶行不用等。

## 三、模块内部六个块详解

### 块1：行/列计数器
- 追踪当前输入像素 `(row, col)` 坐标
- 每行末自动换行，每帧末自动重置

### 块2：流水对齐链 `valid_d` / `col_d` / `row_d` / `pix_d`
- `s=0`：组合直通，直接接输入
- `s=1..N-1`：逐级打拍，`valid_d[s]` 每拍都更新（追踪 valid），**数据寄存器仅在 `valid_d[s-1]` 有效时才更新**
- 关键理解：`pix_d[N-1]` 就是当前像素等了 N-1 拍后的版本，对齐到窗口采样拍

### 块3：N-1 块 BRAM 级联
- **BRAM 第 1 块**：写 `din`，读出旧值 = `P(r-1, c)`，即上一行
- **BRAM 第 m 块（m≥2）**：写 `stream[m-1]`（上一块 BRAM 的读出），读出旧值 = `P(r-m, c)`，即上 m 行
- 关键：`read-first` 模式——先读旧值再写新值，天然实现一行延迟
- 复位策略：BRAM 阵列无复位 pin → **读输出寄存器用同步复位**（`if(!rst_n)` 在 `posedge clk` 内），保证 BRAM 推断

### 块4：对齐延迟链 `adly`
- `adly[m][k]` = `stream[m]`（BRAM 第 m 块读出）再打 k 拍
- 索引公式：`adly_flat[(m-1)*(N-1) + (k-1)]`
- 使能：`valid_d[m+k-1]`——因为 `stream[m]` 在 `valid_d[m]` 有效，顺延 k 拍
- 第一拍 k=1 取 `stream[m]`，后续拍 k>1 取上一级 `adly[m][k-1]`

### 块5：组装当前列 `win_col[i]`
```
win_col[N-1] = pix_d[N-1]                              // 底行 = 当前像素打了 N-1 拍
win_col[0]   = stream_flat[(N-2)*DW +: DW]             // 顶行 = 最后一块 BRAM，无需等待
win_col[wi]  = adly_flat[(N-2-wi)*(N-1) + (wi-1)]     // 中间行 wi=1..N-2
```

### 块6：N×N 窗口横向移位
- `valid_d[N-1]` 每来一次，窗口左移一列，新列从右侧（j=N-1）进入
- `matrix_valid` 门控：`row_d[N-1] >= N-1 && col_d[N-1] >= N-1`——屏蔽帧头 N-1 行、行头 N-1 列

## 四、难点与易错点

### 难点1：BRAM 级联的时序理解 ★★★

```
T 拍：din = P(r,c)  →  BRAM1 写 P(r,c) → 读旧值 P(r-1,c) 在 T+1 拍出
T+1 拍：stream[1] = P(r-1,c)  →  BRAM2 写 P(r-1,c) → 读旧值 P(r-2,c) 在 T+2 拍出
T+2 拍：stream[2] = P(r-2,c)  →  BRAM3 写 P(r-2,c) → 读旧值 P(r-3,c) 在 T+3 拍出
T+3 拍：stream[3] = P(r-3,c)  →  窗口采样！
```

每块 BRAM **引入 1 拍流水延迟**，这就是为什么 BRAM 第 m 块在 T+m 拍才出数。

### 难点2：adly 索引的泛化公式

代码里 `adly_flat` 是一维数组，但逻辑上是二维的 `adly[m][k]`：

| 参数 | 含义 | 取值范围 |
|------|------|---------|
| m | BRAM 编号 | 1..N-1 |
| k | 额外打拍数 | 1..N-1-m |
| 一维索引 | `(m-1)*(N-1)+(k-1)` | 0..(N-1)²-1 |

**组装窗口时的逆向索引**（块5）：
```
win_col[wi] = adly_flat[(N-2-wi)*(N-1) + (wi-1)]
```
- 对于窗口行 wi（1..N-2），对应 BRAM 编号 `m = N-1-wi`，需要打 `k = wi` 拍
- `(N-2-wi)` 就是 `(m-1)`，`(wi-1)` 就是 `(k-1)`

### 难点3：BRAM 无法复位

- BRAM 的原语（`RAMB36E1` 等）没有全局复位 pin
- 代码中通过 `if(!rst_n) rd <= 0` 在 `posedge clk` 内做同步复位——**只复位读输出寄存器，不复位 RAM 阵列**
- 上电后前 N-1 行数据是脏的，但 `matrix_valid` 门控 `row>=N-1` 自然屏蔽了脏数据

### 难点4：valid 与数据寄存器的分离控制

```
valid_d[s]  <= valid_d[s-1];              // 每拍都更新（追踪 valid 流）
pix_d[s]    <= pix_d[s-1];                // 仅当 valid_d[s-1] 有效时更新
```

- valid 链是**自由运行的**（每拍传递），即使数据无效也要传递 valid 状态
- 数据链是**门控的**（只在 valid 时更新），节省功耗且避免脏数据传播
- 气泡期间数据寄存器保持旧值，但 valid 链正确传递 0

### 难点5：dout 引脚的缺失

本模块刻意没有 `dout` 引脚，因为：
- 行缓存输出的是 N×N 窗口，不是单个像素
- 下游算法（CSC/缩放/卷积）直接消费 `win_flat` 和 `matrix_valid`

## 五、参数化验证

Testbench 同时例化 N=3 和 N=4 两个 DUT，共享同一激励：

| 参数 | N=3 | N=4 |
|------|-----|-----|
| 测试图 | 8×6 两帧 | 8×6 两帧 |
| 期望窗口数/帧 | (8-2)×(6-2)=24 | (8-3)×(6-3)=15 |
| 总期望 | 48 | 30 |
| 验证方式 | 逐窗口比对像素值 | 逐窗口比对像素值 |

**验证通过条件**：引用模型（三维数组 `img[row][col]`）与实际 DUT 输出完全一致。

## 六、复习要点清单

- [ ] 对齐原理：为什么 BRAM m 块要等 (N-1-m) 拍？当前像素为什么等 N-1 拍？
- [ ] BRAM 级联级数 = N-1，每块 BRAM 深度 = IMG_W，宽度 = DW
- [ ] `adly_flat` 索引计算：`(m-1)*(N-1)+(k-1)` 与反向索引 `(N-2-wi)*(N-1)+(wi-1)`
- [ ] `win_col` 组装：底行=`pix_d[N-1]`，顶行=`stream[N-1]`，中间行=`adly[N-1-wi][wi]`
- [ ] BRAM 复位策略：阵列不可复位，读输出寄存器同步复位
- [ ] valid 链与数据链分离控制：valid 自由运行，数据门控更新
- [ ] `matrix_valid` 门控条件：`row_d[N-1]>=N-1 && col_d[N-1]>=N-1`
- [ ] 窗口左移机制：新列从右侧进入，旧列逐级左移
- [ ] 公式：等待拍数 = (N-1) − 出生偏移
