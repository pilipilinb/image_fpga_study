# line_buffer_3x3_pad.v 难点详解（学习笔记）

> 配套文件：`line_buffer_3x3_pad.v`（DUT）、`tb_line_buffer_3x3_pad.v`（自检TB，96窗口0错误）
> 配套图：`rflush_timing.svg`（行尾补拍）、`bflush_timing.svg`（帧尾补行）

---

## 0. 术语表（先记定义，后面不再解释）

| 术语 | 定义 | 在本模块的对应物 |
|---|---|---|
| padding（填充） | 边缘像素缺邻居，编值凑数让它也能出窗口 | 整个 `_pad` 版的目的 |
| replicate（复制填充） | 缺的邻居用最近的真实像素顶替 | 上/左 mux + 右/下重复移入 |
| blanking（消隐） | 视频流里行与行（h-blank）、帧与帧（v-blank）之间 valid=0 的空闲拍 | 模块要求：行后≥1拍、帧后≥W+8拍 |
| flush（补拍/排空） | 输入停了但还欠着输出，额外补拍把它做完 | rflush（每行欠1拍）、bflush（每帧欠1行） |
| pend / fire | 记账（立flag"欠一拍"）/ 还账（空拍时执行，清flag） | `rflush_pend` / `rflush_fire` |

## 1. 全局架构：4 级流水

```text
din ──┬──────────────► stage1 打拍 ──────────► stage2 打拍 ──┐
      │ 写                (din_d1,col_d1)        (din_d2 = 底行)│
      ▼                                                        ▼
 line1 BRAM ── line1_rd ──┬── 打拍 line1_d1（= 中行）──────► 块8 窗口移位链 ──► 块9 输出mux+寄存
      （上一行）           │ 写                                 ▲    (win11..33)      (w11..w33)
                          ▼                                    │
                     line2 BRAM ── line2_rd（= 顶行）───────────┘
                       （上两行）
```

- 总延迟 4 拍：stage1 + stage2 + 窗口移位（stage3）+ 输出 mux 寄存（stage4）
- 与原版 `line_buffer_3x3.v` 的差别：多了 stage4（放 padding mux），多了 flush 控制（块7）

## 2. 难点① 窗口中心"慢一行慢一列"（全模块最重要的一件事）

当 `din_d2` 正在送**行 r、列 c** 的像素时，窗口三行的身份：

```text
w11 w12 w13  ← line2_rd  = 行 r-2   （顶行）
w21 w22 w23  ← line1_d1  = 行 r-1   （中行）★ 窗口中心在这一行
w31 w32 w33  ← din_d2    = 行 r     （底行，最新）
```

**本拍完成的窗口中心 = (row_d2 - 1, col_d2 - 1)**。行 r 的像素只是窗口底边，
它自己当中心的窗口要等行 r+1 输入时才凑齐（那时它才升为中行）。

由此派生出代码里所有"看着奇怪"的数字：

| 代码 | 翻译 |
|---|---|
| `crow_saved <= row_d2 - 1'b1` | 行尾欠的账属于"本行正在产的窗口"，中心行就是 row_d2-1 |
| `row_d2 >= 1` 才记账/发射 | row_d2==0 时中心=行-1，不存在，第一行不产窗也不欠账 |
| `at_top_in = (row_d2 == 1)` | row_d2==1 产的是中心行0的窗口，正是需要顶边复制的那批 |
| `crow_saved == IMG_H-2` 触发帧尾 | 最后输入行 H-1 产的窗口中心是 H-2，这笔账还完=正常数据全走完 |

## 3. 难点② 为什么欠拍？一道算术题

W=4 时逐拍数窗口（padding 后每行要出 4 个窗口，中心=列0/1/2/3）：

| 拍 | 移入的列 | 窗口右三列 | 本拍完成的窗口中心 |
|---|---|---|---|
| 列0 进 | 0 | (×,×,0) | 无——窗口没填满 |
| 列1 进 | 1 | (×,0,1) | **列0**（左边缘 mux 白嫖这拍） |
| 列2 进 | 2 | (0,1,2) | 列1 |
| 列3 进 | 3 | (1,2,3) | 列2 ← **数据进完，才出3个窗！** |
| 补拍 | 3 再推一次 | (2,3,3) | **列3** ★ 欠的就是它 |

> **算术题**：每行要 W 个窗口，W 个输入拍里第一拍出不了窗 → 只出 W-1 个 → 永远欠 1 个。
> 欠的不是"没处理的数据"（原料全在寄存器里），是"没生成的窗口"——移位链每移一次才出一个窗。

行方向同理：H 个输入行只能产 H-1 行窗口（第一行不产窗），欠一整行 → bflush。

## 4. 难点③ 四边分治（各边成本不对称）

| 边 | 缺什么 | 策略 | 代价 | 代码位置 |
|---|---|---|---|---|
| 上（中心行0） | 顶行数据 | 数据已在窗口里（中行），输出级 mux 复制 | 免费 | 块9 `at_top_r ? win2x : win1x` |
| 左（中心列0） | 左列数据 | 同上（中列），输出级 mux 复制 | 免费 | 块9 `at_left_r ? 中列 : 左列` |
| 右（中心列W-1） | 列W不存在 | 行尾补1拍，最右列重复移入 | 每行1拍，需h-blank | 块7 rflush + 块8 `win13/23/33` 回灌 |
| 下（中心行H-1） | 行H不存在 | 帧尾补一整行，只读BRAM回放 | 每帧W+1拍，需v-blank | 块7 bflush + 块8 `mid_in=bot_in=line1_rd` |

**为什么上/左免费、右/下要补拍**：上/左缺的数据"早就到了"（选一下就行）；
右/下缺的数据"永远不来"（时间轴上在未来），只能自己造拍子。

## 5. 难点④ rflush：记账-还账（配合 rflush_timing.svg 看）

```text
          C0        C1          C2          C3     C4
valid_d2  ──1──────1──────────0(h-blank)───0──────1(下一行)──
col_d2      2      3=W-1行末    ×           ×      0
rflush_pend 0      0     ┌─────1─────┐     0      0
rflush_fire 0      0     │     1     │     0      0
窗口右三列  …,0,1   0,1,2  │   1,2,3   │  ★2,3,3   …
                          └─ 空拍还账 ─┘
```

三步逻辑（块7上半）：

1. **记账**：`valid_d2 && col_d2==W-1 && row_d2>=1` → `rflush_pend<=1`，同时 `crow_saved` 存中心行号
   （为什么要存：还账那拍 row_d2 可能已经变了，不能现算）
2. **还账**：`rflush_fire = pend && !valid_d2 && !bflush_dv` → 只能趁空拍。
   fire 时窗口移位链把 `win13/23/33` **原样再推入一次** → 右三列 (1,2,3)→(2,3,3)，列3出现两次=复制
3. **清账**：fire 后 `pend<=0`

**为什么必须趁空拍**：下一行数据一到就会移位冲掉窗口，补拍必须抢在它前面 → 依赖 h-blank ≥1 拍。

## 6. 难点⑤ bflush：迷你回放机（配合 bflush_timing.svg 看）

**本质：模块自己给自己灌一行假输入**。帧尾最后两行数据还躺在 BRAM 里
（line1_ram=行H-1，line2_ram=行H-2，主通路运行完的自然遗产），
bflush 从列0到列W-1 回放一遍，喂给同一条窗口移位链。

四个信号 = 主通路四个角色的"替身"：

| 主通路（真输入） | bflush（假输入） | 角色 |
|---|---|---|
| `din_valid` | `bf_active` | "有活干"——发读地址的开关 |
| `col_cnt` | `fcol` | "第几列"——读地址 |
| `valid_d2` | `bflush_dv` | "数据到货"——触发窗口移位 |
| `col_d2` | `bcol_d` | "到货列号"——贴在数据上的标签 |

逐拍表（W=4，H=4）：

| 拍 | 信号状态 | 发生的事 |
|---|---|---|
| T0 | `rflush_fire=1, crow_saved=H-2` | 最后正常行还完账 → `bf_start=1` |
| T1 | `bf_active=1, fcol=0` | 给两块 BRAM 下单：列0（只读不写） |
| T2 | `fcol=1`；`dv=1, bcol_d=0`，货=列0 | 列0进窗口（没满不出窗）；下单列1 |
| T3 | `fcol=2`；`dv=1, bcol_d=1` | **窗口(H-1,0)完成**（左mux）；下单列2 |
| T4 | `fcol=3`；`dv=1, bcol_d=2` | 窗口(H-1,1)完成；地址发完 |
| T5 | `bf_active=0`；`dv=1, bcol_d=3` | 窗口(H-1,2)完成；`bcol_d==W-1`→又记账`crow_saved=H-1` |
| T6 | `dv=0, rflush_fire=1` | 还账 → **右下角(H-1,W-1)完成**，收工 |

关键细节：

- **`dv`/`bcol_d` 为什么存在**：BRAM 老规矩"这拍给地址下拍出数"，到货铃和列号标签必须
  跟数据同步晚一拍。这是本工程**第三次**出现"读潜伏→打拍对齐"套路（前两次：col_d1、col_d2）
- **下边缘复制在哪**：块8 `mid_in = bot_in = line1_rd`——中行、底行接同一个行H-1，用两次即复制
- **帧尾探测**：不看 row_cnt（早回零了），看 `crow_saved==H-2`——"最后一笔正常账的落款"
- **收尾合龙**：回放行自己的行末又欠一拍，还是交给 rflush 干（右下角）

## 7. 难点⑥ blanking 依赖（物理极限，不是实现缺陷）

每行 W 个输入拍要产 W 个窗口 + 每帧还要多产一行 → **输出拍数 > 输入拍数**。
输入若一拍不停，单时钟域下物理上不可能补拍（速率不守恒）。

出路（业界四条路线）：

| 路线 | 做法 | 场景 |
|---|---|---|
| ① blanking 里补（本模块） | 借视频流自带空闲拍 | 相机直通实时流水线（MIPI/HDMI 不落内存） |
| ② AXI-Stream 反压 | tready 摁住上游一拍，想补就补 | SoC 模块化 IP，最通用（HLS 生成的就是这套） |
| ③ 帧存随机访问 | 图先落 DDR，地址钳位法 padding | 非实时/复杂算法 |
| ④ crop 不补 | 输出少一圈（原版做法） | 大量实际产品，3x3 少一圈看不出来 |

**补 0（zero padding）不能省掉 flush**：欠拍是窗口数量的算术问题，跟补什么值无关；
补 0 只把 mux 输入换成常数（省约5行），控制通路一行不少。且补 0 会在边缘制造假梯度
（Sobel 检出假边缘），ISP 用 replicate，CNN 才用 zero。

## 8. 关键数字咬合表（改任何一个，链条就断）

| 数字 | 位置 | 含义 | 与谁咬合 |
|---|---|---|---|
| `row_d2 >= 1` | 块7记账 / 块8发射 | 第一行不产窗不欠账 | 两处必须一致 |
| `row_d2 - 1` | crow_saved | 窗口中心慢一行 | 块8中心坐标 (row_d2-1, col_d2-1) |
| `row_d2 == 1` | at_top_in | 中心行0的窗口需顶边复制 | "慢一行"推论 |
| `crow_saved == H-2` | bf_start | 最后输入行产的中心行是 H-2 | crow_saved 存的是-1后的值 |
| `bcol_d >= 1` | 块8发射 | 回放行第一拍（列0进）不出窗 | 与正常拍 col_d2>=1 同构 |
| `bcol_d == W-1` | 块7记账 | 回放行自己的行末 | 与正常行 col_d2==W-1 同构 |

## 9. 自测题（全部秒答 = 通关）

1. `din_d2` 送行 r 列 c 时，本拍完成的窗口中心坐标是？（答：(r-1, c-1)）
2. 为什么 rflush 必须等空拍？（答：下一行数据会移位冲掉窗口，须抢先；空拍来自 h-blank）
3. bflush 时中行和底行为什么接同一个 `line1_rd`？（答：行 H-1 用两次 = 下边缘复制）
4. 如果 BRAM 换成读无延迟的分布式 RAM，`bflush_dv`/`bcol_d` 还需要吗？
   （答：不需要，`bf_active`/`fcol` 可直接当 dv/列号——打拍只为对齐读潜伏）
5. 补 0 能不能省掉 rflush/bflush？（答：不能，欠拍是窗口数量算术问题，与填充值无关）
6. 帧尾怎么知道"一帧结束了"？（答：`crow_saved==H-2` 的账还完——不看 row_cnt 因为它已回零）
