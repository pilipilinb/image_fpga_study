# 三种行缓存方案对比速查（复习检索卡）

> 覆盖本工程三份实现：
> | 文件 | 一句话定位 |
> |---|---|
> | `line_buffer_3x3.v` | 手写 BRAM 基础版：crop 输出，最省资源，面试手写首选 |
> | `line_buffer_3x3_pad.v` | 手写 BRAM + replicate padding 版：全尺寸输出，含 flush 机制 |
> | `fifo_line_buffer3x3.v` | FIFO IP 级联版：三行对齐输出（非完整窗口），开发最快 |

## 1. 一览表（快速定位用哪个）

| 维度 | line_buffer_3x3 | line_buffer_3x3_pad | fifo_line_buffer3x3 |
|---|---|---|---|
| 存储载体 | 2 块推断 BRAM（ram_style） | 2 块推断 BRAM | 3 个 Xilinx FIFO IP |
| 输出 | 3x3 窗口，(H-2)×(W-2) 个 | 3x3 窗口，**H×W 个**（每像素一个） | **三行对齐数据流**（dout_r0/1/2），窗口成型要另加移位链 |
| 边缘处理 | crop（少一圈） | replicate padding（四边补齐） | 无（mat_flag 只标"第4行起有效"） |
| 输入流要求 | 无（任意气泡均可） | **h-blank≥1拍，v-blank≥W+8拍** | 无特殊要求，但 FIFO 须 FWFT 模式 |
| 流水延迟 | 3 拍 | 4 拍 | 取决于 FIFO 配置 |
| 资源 | 最省 | 最省+少量控制逻辑 | 略费（多一行存储+空满/计数×3） |
| 可移植性 | 纯 RTL 跨平台 | 纯 RTL 跨平台 | 绑定厂商 FIFO IP |
| 开发量 | 中（要推打拍对齐） | 大（对齐+flush） | 小（调 IP+generate） |
| 验证状态 | ✅ 48 窗口 0 错误 | ✅ 96 窗口 0 错误 | ⚠️ 无 TB（且有代码风格问题） |
| 配套 TB | tb_line_buffer_3x3.v | tb_line_buffer_3x3_pad.v | 无 |

## 2. 三者的共同本质（先记相同点）

1. **行缓存 = 行延迟器**：N×N 窗口只需 N-1 条行缓存；当前行 + 缓存的 N-1 行同列对齐后竖排成窗口列。
2. **同列对齐是核心目标**：BRAM 版靠 read-first + 打拍链锁死；FIFO 版靠"深度=行宽、写满即读、读写 lockstep"结构锁死。手段不同，目标相同。
3. **BRAM 复位铁律都适用**：存储阵列不可复位（FIFO 内部也是 BRAM）；输出寄存器只能同步复位；复位前的 x 靠 valid 门控屏蔽。
4. **都必须仿真验证**：BRAM 版的坑在代码里（打拍漏一级错一列），FIFO 版的坑在 IP 配置里（FWFT 选错每级斜 1 像素）——后者 review 看不见，更隐蔽。

## 3. 各版本速览

### 3.1 line_buffer_3x3.v（基础版）

```text
din ─┬─► [BRAM1 read-first] ─ line1_rd ─► 打拍 line1_d1 ─┐
     │        └────────────────写─► [BRAM2] ─ line2_rd ─────────────────┤
     └─► din_d1 ──────────────────────────────► din_d2 ────────────────────────────────┴─► 3 组横向移位 → 3x3 窗口
```

- **关键机制**：read-first 同址读写（读旧值=上一行，写新值=当前行，一个端口完成行交换）
- **对齐口诀**：BRAM 读晚 1 拍 → din/col/valid 全打拍跟上；line2 整级用 stage1 的地址/使能（col_d1/valid_d1）
- **门控**：`matrix_valid = valid_d2 && row_d2>=2 && col_d2>=2`（屏蔽帧头两行/行头两列/上电脏数据）
- **踩过的坑**（demo.v 复盘）：① bram2 读错 RAM/地址；② line1_rd 没再打拍直接喂窗口（错一列）；③ matrix_valid 没门控；④ 边界 `>` 应为 `>=`
- **何时选**：资源紧张、面试手写、下游能接受少一圈

### 3.2 line_buffer_3x3_pad.v（padding 版）

基础版 + 四边分治 + flush（详见《line_buffer_3x3_pad_难点详解.md》）：

- 上/左边：输出级 mux 复制（免费）；右边：行尾补 1 拍；下边：帧尾回放一行 BRAM
- **核心账本**：每行 W 拍只能出 W-1 窗 → 欠 1 拍（rflush）；每帧 H 行只能出 H-1 行窗 → 欠一行（bflush）
- **依赖 blanking**：无空拍则物理上无法补（输出拍数>输入拍数）
- **何时选**：下游算法要求全尺寸输出（如级联滤波不能逐级缩水）、输入是标准视频时序
- **升级方向**：改 AXI4-Stream 反压接口，摆脱 blanking 依赖 → 通用 IP

### 3.3 fifo_line_buffer3x3.v（FIFO 版）

```text
din ─► [FIFO0 深度=W] ─ dout_r[0] ─► [FIFO1] ─ dout_r[1] ─► [FIFO2] ─ dout_r[2]
        写满480即读        晚1行           晚2行                晚3行
        valid_out[0] ────► valid_in[1] ──► …（写满才放行下一级，多米诺启动）
```

- **关键机制**：FIFO 深度=行宽 → 天然一行延迟；`rd_en = (cnt==W) && valid_in` 读写同拍 lockstep，水位恒定
- **generate for 本质**：编译期展开成 3 个并行实例（不是运行时循环），`if(i==0)` 只决定接线方式
- **三个隐患**：
  1. **必须 FWFT 模式**——标准模式读潜伏 1 拍，valid 级联当拍传但数据晚到，每级斜 1 像素
  2. **尾行 flush 难做**——`rd_en` 与 `valid_in` 绑死，输入停则最后两行永远读不出
  3. 代码风格：`always @(*)` 内用 `<=`（组合逻辑应用阻塞 `=`，或改 wire+assign）；`~(i==0)` 应为 `else`
- **注意**：该文件只输出**三行对齐数据**，3x3 窗口的横向移位链还要自己加
- **何时选**：快速原型、跨时钟域行缓存（异步 FIFO 现成）、团队熟 IP 流程

## 4. 决策树（复习时 10 秒定方案）

```text
需要 3x3 窗口？
├─ 下游可接受少一圈（绝大多数场景）
│    └─► line_buffer_3x3.v（crop，最简单）           ← 默认首选
├─ 必须全尺寸输出
│    ├─ 输入是标准视频时序（有 blanking）
│    │    └─► line_buffer_3x3_pad.v
│    ├─ 输入连续无空拍
│    │    └─► 改 AXI-Stream 反压版（待实现）或上游预填充
│    └─ 图像已在 DDR
│         └─► 帧存随机访问 + 地址钳位
└─ 只要三行对齐流 / 要跨时钟域 / 赶时间出原型
     └─► fifo_line_buffer3x3.v 思路（记得 FWFT）
```

## 5. 面试速答卡

| 问题 | 30 秒答案 |
|---|---|
| 3x3 窗口怎么生成？ | N-1 条行缓存 + 当前行同列对齐，3 组横向移位寄存器出窗口；BRAM read-first 或 FIFO 深度=行宽两种载体 |
| BRAM 版最容易错哪？ | 读潜伏对齐：line2 要用打拍后的地址 col_d1；line1_rd 要再打一拍才能进窗口——错一处偏一列 |
| FIFO 版最容易错哪？ | 读模式：必须 FWFT；标准模式 valid 级联当拍传、数据晚一拍到，每级斜 1 像素，代码 review 看不出来 |
| 行缓存怎么复位？ | 阵列不可复位（物理无该管脚，加了推断失败退化成 FF）；输出寄存器同步复位；x 靠 valid 门控屏蔽 |
| 边缘怎么处理？ | 四条路：crop（最常用）/ blanking 里补拍 / AXI 反压 / 帧存地址钳位。补 0 不能省 flush（窗口数量算术问题），且会造假梯度，ISP 用 replicate，CNN 用 zero |
| 为什么 padding 要补拍？ | 每行 W 拍第一拍出不了窗，只出 W-1 个，永远欠 1 个；行方向同理欠一行——速率不守恒，须借空拍 |
| FIFO 和 BRAM 版怎么选？ | 资源/移植性/随机访问选 BRAM 手写；开发速度/跨时钟域选 FIFO；坑的位置不同：一个在代码里一个在 IP 配置里 |
