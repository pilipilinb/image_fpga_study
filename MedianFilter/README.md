## 项目简介

中值滤波：3×3 窗口 9 个像素**排序取中间值**（第 5 大/小）作为输出。

- **非线性**：输出不满足叠加性（均值/高斯是线性的）——这是三类滤波的关键分野
- **椒盐噪声（脉冲 0/255）最优**：窗口内极值点少于 5 个时，中值必为真实像素，脉冲**直接剔除**；均值/高斯会把极值"抹开"成灰斑
- **保边缘**：中值不产生模糊（线性滤波的共性弱点），适合边缘检测前处理

工程化要点：**找中值 ≠ 全排序**——9 输入全排序要几十个比较器，行排序三部曲只要 **19 个比较器**，零乘法器/加法器（纯比较器网络）。

## 原理：为什么中值滤波是椒盐噪声的天敌

| 噪声类型 | 均值/高斯（线性加权） | 中值（排序取中） |
|---|---|---|
| **椒盐噪声** | 极值被抹开成灰斑，整片发脏 | **极值直接出局**（窗口内 <5 个极值时中值必为真实像素） |
| 高斯噪声 | 加权平均最优（针对性匹配） | 排序丢弃了数值信息，效果一般 |
| 边缘 | 会模糊 | **不模糊** |

一句话：**"择中"天然免疫极端值**——这就是排序相对于加权的本质优势所在。

## 实现核心：行排序三部曲（19 比较器）

### 三步结构

```
① 每行 sort3（3 比较器/行 ×3 = 9）→ r_max, r_mid, r_min
② 提取 3 候选（7 比较器）：
     cand1 = max(三行 min)   ← 行最小值中的最大值（2 比较）
     cand2 = mid(三行 mid)   ← 行中间值的中间值（3 比较）
     cand3 = min(三行 max)   ← 行最大值中的最小值（2 比较）
③ 中值 = mid(cand1, cand2, cand3)（3 比较）
总 9 + 7 + 3 = 19 比较器
```

sort3 网络（3 输入全排序 → hi/mid/lo，3 比较器）：

```
cmp1: a vs b → ab_min, ab_max
cmp2: ab_max vs c → t_max, t_min     （hi = t_max = 三数最大）
cmp3: ab_min vs t_min → 小者=lo，大者=mid
```

### 反例：为什么 cand2 不能省（本工程踩过的坑）

初版曾把 cand2 误简化为"中间行的 mid"（声称省 3 比较器得 16 比较器），被反例推翻：

```
窗口 {{5,2,8},{4,9,1},{7,3,6}}
→ 行排序：min 列 {2,1,3}、mid 列 {5,4,6}、max 列 {8,9,7}
→ 真中值 = 5（全排序第 5 个）

中行 mid = 4  → mid(3,4,7) = 4 ❌（错了）
三行 mid 中值 = 5 → mid(3,5,7) = 5 ✅
```

**三行 mid 的中值（3 比较器）不可省**——"看起来对称就能省"是错误直觉。验证排序网络正确性最直接的方法：反例 + TB 用完全独立的参考模型（本工程用计数法取第 5 小，与比较网络不同源）全等比对。

## 架构与流水

```
din[23:0]/din_valid ──► line_buffer_3x3（DW=24，crop）──► w11..w33（24bit）
                          ├─ R[23:16] → median_3x3_8b（R 核）
                          ├─ G[15:8]  → median_3x3_8b（G 核）
                          └─ B[7:0]   → median_3x3_8b（B 核）
                          │ 同一 matrix_valid 驱动三核 → o_r/o_g/o_b + o_valid
```

流水 2 级（valid 链 LAT=2 严格对齐）：

```
级1（组合）：三行 sort3（9 比较器）
级2（组合）：cand1/cand2/cand3 提取（7 比较器）+ 最终取中（3 比较器）
输出：median 组合结果打 2 级寄存（d1 → dout）与 LAT=2 链同步
```

**对齐关键（本工程踩过的坑）**：median 是组合结果，只打 1 级寄存会让输出比 valid 链早 1 拍——valid_out 拉高时 dout 已被刷新成下一个窗口（实测整幅错位 1 列）。必须与 valid 链级数严格一致（MeanFilter 的 LAT 教训的变体）。

### 去噪对比实验（椒盐主场 / 高斯对照）

**三滤波器双噪声同图对比**：[median_3way_compare.png](median_3way_compare.png)（3×3 网格：行=均值/高斯/中值，列=原图/椒盐/高斯；每幅图下方自动标注 PSNR，生成脚本 `compare_grid.py`）

同一份噪声图过三个滤波器（σ=40 高斯 / p=0.10 椒盐）：

| 滤波器 | 椒盐去噪（噪声 13.96 dB） | 高斯去噪（噪声 17.56 dB） |
|---|---|---|
| 均值 | 20.53 dB（+6.57） | 22.14 dB（+4.58） |
| 高斯 | 20.44 dB（+6.48） | **22.50 dB（+4.94）** |
| **中值** | **26.18 dB（+12.22）** | 22.01 dB（+4.45） |

**交叉验证完美**：

- 椒盐场景：中值碾压（26.18 vs ~20.5，**+5.7 dB**）——脉冲噪声被直接剔除
- 高斯场景：均值/高斯略优（22.14/22.50 vs 22.01），中值如实垫底——排序丢弃数值信息
- 这就是面试知识点："**中值滤波只对脉冲噪声最优，线性滤波适合高斯噪声**"

对比图：[median_salt_compare.png](median_salt_compare.png)（椒盐单滤波）· [median_gaussian_compare.png](median_gaussian_compare.png)（高斯单滤波）；均值/高斯两目录各有同款椒盐对比图。

## 调试记录（踩坑与修复）

| # | 问题 | 现象 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | **排序网络误省比较器** | 16 比较器版反例输出 4（真值 5） | cand2 误简化为"中行 mid"，三行 mid 的中值不可省 | 19 比较器正确形态 + 反例记录（详见[实现核心](#实现核心行排序三部曲19-比较器)） |
| 2 | **valid 链与数据通路错位 1 拍** | 全帧错位 1 列（小图 got 18 vs 期望 17），TB 全等比对秒抓 | 组合 median 只打 1 级寄存，valid 链却 2 级——valid_out 拉高时 dout 已是下一窗口 | 输出打 2 级（median→d1→dout）与 LAT=2 链同步（详见[架构与流水](#架构与流水)）——MeanFilter LAT 坑的变体，教训：**组合输出的寄存级数必须与 valid 链级数严格一致** |
| 3 | **PSNR 数据混搭** | "中值高斯去噪 26.18dB"实为椒盐成绩 | output.coe 同名文件被后续 -DSALT 实验覆盖，compare 误读 | 每跑完一个实验立即 `Copy-Item output.coe output_<实验>.coe` 归档；本工程用 output_salt_median.coe 等 6 份独立文件 |
| 4 | **拼图脚本 crop 对齐错位** | 6 项 PSNR 全虚低（10.9dB 级） | center 构造写 `range(2, H-1)`，少一行一列且错位（与 MeanFilter 初版 10.94dB 同坑） | 改为 `range(2, H)` + 注释写明窗口中心映射；校验脚本 verify_grid.py 锁定 6 个已知值 |
| 5 | **PowerShell 重定向坑** | `vvp > /dev/null` 报 D:\dev\null 不存在且 **vvp 未执行**，output.coe 还是旧结果 | PowerShell 不支持 /dev/null（解析失败导致命令不运行），且 `> $null 2>&1` 会把 vvp 找不到的错误也吞掉 | 重定向用 `> $null`；先确认 `.vvp` 存在再跑；每次重跑后校验 output.coe 哈希/内容归属性 |
| 6 | **拼图画布宽度漏算行名栏** | 图只显示前两列，第三列（高斯列）被裁掉约 60px（用户看图发现） | `canvas_w = M + col_w*3 + M` 漏加行名栏 `x0 = M+78`，子图从 x0=94 起排 | `canvas_w = x0 + col_w*3 + M`（452px）；教训：**布局尺寸要从实际起始坐标起算，生成后人工看图确认无裁剪** |

教训小结：**同名输出文件要立即归档、脚本对齐逻辑要写注释并用已知值校验、仿真恢复现场前先确认编译产物存在**。前三项都是"能自检能秒抓"的坑——TB 全等比对、PSNR 已知值回归，是这套验证链能快速定位每个坑的原因。

## 面试要点

### 1. 找中值 ≠ 全排序（19 比较器）

"9 像素全排序要几十个比较器，中值只要第 5 个顺序统计量——行排序三部曲 19 个比较器搞定：三行 sort3（9）→ 三列候选提取（7）→ 三数取中（3）。"

### 2. sort3 网络

"3 输入全排序 3 个比较器：先两两比，再与第三个比，最后归位——贪心交换网络。"

### 3. 为什么对椒盐噪声免疫

"窗口内椒盐极值点少于 5 个时，排序后它们全被挤在两端，中值必是真实像素——'择中'天然免疫极端值。均值/高斯是把极值抹开成灰斑，实测椒盐场景中值比它们高 5.7 dB。"

### 4. 中值 vs 线性的适用边界（实测背书）

"中值是脉冲噪声的主场；高斯噪声下中值垫底（22.01 vs 均值 22.14 / 高斯 22.50）——因为排序丢弃了数值信息。选型口诀：脉冲噪声用中值，高斯噪声用加权平均。"

### 5. 排序网络验证方法论

"网络化简必须反例验证 + 参考模型不同源（我用计数法取第 5 小，与比较网络完全独立）——16 比较器错误版就是被反例 {{5,2,8},{4,9,1},{7,3,6}} 推翻的。"

## 使用方式

```powershell
# 1. 编译 + 仿真（iverilog，-I 指向本目录）
iverilog        -I . -o tb.vvp tb_median_filter.v      # 真图（两帧：真图+纯色）
iverilog -DNOISE -I . -o tb_n.vvp tb_median_filter.v   # 高斯噪声图
iverilog -DSALT  -I . -o tb_salt.vvp tb_median_filter.v # 椒盐噪声图
vvp tb.vvp > sim_log.txt

# 2. 椒盐去噪实验（与均值/高斯同场对比）
python noise_add.py --salt 0.10 --out-hex salt_pepper.hex   # 生成椒盐图
vvp tb_salt.vvp > sim_salt.txt                              # 中值滤波
python noise_add.py --compare --out-hex salt_pepper.hex --salt 0.10 --out-coe output_salt_median.coe
# 均值/高斯目录：各自 -DSALT 跑同份 salt_pepper.hex 后同样 compare

# 3. 高斯对照（同一份 noise.hex，与均值/高斯 README 数据可比）
vvp tb_n.vvp > sim_noise.txt
python noise_add.py --compare
```

## 已知限制与后续

- **crop 边界**：输出 (H-2)×(W-2)；全尺寸需求换 pad 版行缓存（MeanFilter 已演示）
- **排序网络位宽固定 8bit**：换 10bit 像素需等比放宽比较器（结构不变，位宽参数化即可）
- **椒盐概率上限**：p>0.5 时窗口多数像素是极值，中值不再是真实像素——去噪实验 p=0.10 是合理区间
- **后续（W4 收尾）**：均值+高斯+中值+CSC+缩放串链路仿真；中值适合作为边缘检测（Sobel）前的预处理
- 与 MeanFilter / GaussianFilter 的三滤波器对比互链完成（各 README 可见椒盐对照数据）
