# Gamma 伽马校正实现计划（M4-3，线性 RGB 域 10bit → 8bit）

> 来源：`伪代码.c`（用户提供）+ M4 链路契约。**本模块是全链位宽缩减的唯一出口**：线性 RGB 域 10bit 进、RGB888 8bit 出——下游 VDMA 的 `tdata[23:0]` 契约由这里给出。

## 一、伪代码核对（结论：思路正确，3 处修正 + 补强）

### ✅ 正确的部分

- **`in 就是地址，1 拍出结果`**：BRAM 同步读 = 1 拍潜伏，地址打进去、下一拍数据出来 —— 与 RTL 实现一致
- **"Gamma 常和位深压缩一起做：10bit 进、8bit 出，一张表把两件事都办了"** —— 这正是本架构的决策：全链中间的量化损失只在此处付一次，且 LUT 内容离线存 `round` 后的值，**折算零硬件成本、零偏置**

### ⚠️ 需修正的 3 处

| # | 伪代码 | 问题 | 本实现 |
|---|---|---|---|
| 1 | `8bit 地址 → 256×8 = 2048 bit → 半个 BRAM18` | **算错**：BRAM18 = 18Kb = **18432 bit**，2048 bit 只占 **11%（≈1/9）**，不是半个。（第 2 行 1024×8=8192bit≈44%≈半个 ✓；第 3 行 4096×8=32768bit≈1.78→2 个 ✓） | 见 §3 资源 |
| 2 | 只算了一张表的容量 | **漏算"三通道要三个并行读口"**：RGB 同拍各查一次，BRAM18 只有 2 个读口 → 需 **3 份副本** | 3×(1024×8) = 24576 bit（打包 1 个 BRAM36 / 2 个 BRAM18） |
| 3 | `x / 255`（8bit 输入） | 本链路输入是 **10bit** | `round(255·(x/1023)^(1/2.2))`，x ∈ [0,1023] |

### ➕ 补强

- **舍入规则**：`floor(x·+0.5)`（round-half-up），与 CCM 的定点化规则统一
- **端点与单调性**：`LUT[0]=0`、`LUT[1023]=255`；gamma 曲线**必须单调不减** —— 由 `verify_gamma.py` 穷举校验（1024 项）
- **bypass 语义**：Gamma 是本级的"位宽缩减出口"，**bypass 只关曲线、不能关位宽**（下游 VDMA 要 8bit）→ bypass = 线性 10→8（`(v+2)>>2`，round-half-up 无偏置）
- **表内容静态化**（用户拍板）：曲线是确定值，直接用 `$readmemh` 加载 .coe，**不走 MicroBlaze/AXI-Lite**。只有"曲线随场景切换"或"上板免重综合调曲线"时才升级成动态写表（BRAM 结构不变，只换内容）

## 二、算法与定点

```
W(x) = 8bit 折 255 的 gamma 编码：LUT[x] = clamp(round(255·(x/1023)^(1/2.2)), 0, 255)   x ∈ [0,1023]
out   = { LUT[R], LUT[G], LUT[B] }          （三通道同拍并行查表）
```

- 10bit → 8bit 是**右移 2 位**的量级，但 gamma 曲线是**非线性**的：暗部斜率大（提亮）、亮部斜率小（压缩）——这正是感知域该做的事
- 表深 1024（10bit 地址全空间），表宽 8bit
- 曲线用纯 2.2 幂（按伪代码）；**变体**：真 sRGB 是"线性段 + 2.4 幂"的分段函数，工程上常按厂商 tuning 曲线微调——表内容一变即可，硬件不动

## 三、架构与流水

```
in(30bit 简流，线性 RGB 10bit) → gamma_core（逐像素，无行缓存）
                                   │  3 份 1024×8 并行 LUT（同拍三查）
                                   │  BRAM 同步读 = 1 拍潜伏 → LAT = 1
                                   ▼
                                 out(24bit 简流，RGB888)  ← ★ 全链位宽缩减在此完成
```

- **LAT = 1**：BRAM 自带输出寄存器，`dout <= {LUT_R[addrR], LUT_G[addrG], LUT_B[addrB]}` 一拍出结果。反压时用 `run_en` 当 BRAM 读使能 → 输出原地保持（**这就是"LAT=1 核当输出寄存器"的正确做法：使能门控，不需要额外 hold 寄存器**）
- **无行缓存**：逐像素 1→1 映射
- **资源**：3×(1024×8) = 24576 bit ≈ **1 个 BRAM36**（或 2 个 BRAM18）；无乘法器、无 DSP
- **反压/冻结**：`stall = out_valid && !out_ready` → `run=0` → BRAM 读停 + 旁路链停 + 输出保持 + `in_ready=0`

## 四、bypass（等延迟，与 CCM 同构）

| | 延迟 | bypass 实现 | 切换 |
|---|---|---|---|
| 降噪（含行缓存） | `K·W+K+3` ≈ 上万拍 | 排空点切换 | 禁热切换 |
| CCM（逐像素 LAT=2） | 2 拍 | 等延迟旁路 | 可任意拍切 |
| **Gamma（逐像素 LAT=1）** | 1 拍 | **等延迟旁路** | **可任意拍切** |

**bypass 语义（重要）**：只关闭 gamma 曲线，**不关闭 10→8 的位宽缩减**（下游契约不可破）。
所以 bypass 路径 = `{ (R+2)>>2, (G+2)>>2, (B+2)>>2 }`（线性 10→8，round-half-up 无偏置），
而**不是**"输入原样输出"（位宽不同，物理上不可能原样）。

## 八、面试点清单

1. **Gamma 干什么**：把线性光信号编码成显示域（感知均匀）——不改变物理信息，改变的是"码值怎么分配动态范围"
2. **为什么在感知域（Gamma 之后）做锐化**：锐化是视觉量；但**噪声也被 gamma 放大**，所以降噪必须在 Gamma 前
3. **为什么用 LUT 不算幂函数**：`x^2.2` 无硬件原语；且**位深压缩顺手完成**（10bit 进 8bit 出，表内容预存 round 值 ⇒ 折算零成本零偏置）
4. **资源换算**：1024×8 = 8192 bit ≈ 半个 BRAM18；**但三通道要三个读口 → 3 份副本**（这是伪代码漏掉的一点）
5. **LAT=1 与反压**：BRAM 自带输出寄存器，用读使能当冻结门控（不需要额外 hold 寄存器）
6. **bypass 的语义边界**：关曲线 ≠ 关位宽（下游契约不可破）→ bypass 走线性 10→8
7. **曲线可配的三条路**：静态 .coe（本实现）/ 多套表切换 / AXI-Lite 动态写表——成本递增，按需求选
8. **sRGB vs 纯 2.2**：真 sRGB 是分段函数（暗部线性 + 2.4 幂），工程上常按 tuning 曲线微调；只换表内容，硬件不动
