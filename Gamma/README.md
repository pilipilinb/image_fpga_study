# Gamma —— M4-3 伽马校正（线性 RGB 10bit → RGB888）

ISP 链第七级（M4 第三模块，**M4 收官**）：**伽马校正**。输入 = M4-2 CCM 出的线性 RGB 10bit 简流（`in_data[29:0]`），输出 **RGB888**（`out_data[23:0]`）。算法来源 [伪代码.c](伪代码.c)，核对结论与架构决策见 [Gamma实现计划.md](Gamma实现计划.md)。

> **★ 本模块是全链位宽缩减的唯一出口**：线性 RGB 域全程 10bit（降噪/CCM 都不降位宽），10→8 的量化统一在 Gamma 出口付一次——LUT 内容离线预存 `round` 后的值，**折算零硬件成本、零偏置**。下游 VDMA 的 `tdata[23:0]` 契约由此处给出。

## 伪代码核对（3 处修正 + 补强）

| # | 伪代码 | 问题 | 本实现 |
|---|---|---|---|
| 1 | `8bit 地址 → 256×8 = 2048 bit → 半个 BRAM18` | **算错**：BRAM18 = 18Kb = 18432 bit，2048 bit 只占 **11%（≈1/9）**。第 2 行（1024×8=8192bit≈44%≈半个 ✓）、第 3 行（4096×8=32768bit→2 个 ✓）是对的 | 见下"资源" |
| 2 | 只算了一张表的容量 | **漏算"三通道要三个并行读口"**：RGB 同拍各查一次，BRAM18 只有 2 个读口 → 必须 **3 份副本** | 3×(1024×8) = 24576 bit |
| 3 | `x / 255`（8bit 输入） | 本链路输入是 **10bit** | `round(255·(x/1023)^(1/2.2))` |
| ➕ | — | `round` 规则 / 端点 / 单调性 / 静态表 | `floor(x+0.5)`；`LUT[0]=0`、`LUT[1023]=255`；穷举校验单调不减；直接 `$readmemh` 静态 .coe（用户拍板：曲线是确定值，**不走 MicroBlaze**） |

## 参数

| 量 | 值 | 说明 |
|---|---|---|
| LUT | **1024×8bit** | 10bit 地址全空间；内容 = `clamp(floor(255·(x/1023)^(1/2.2)+0.5),0,255)` |
| 曲线 | 纯 2.2 幂 | 按伪代码；**变体**：真 sRGB 是"暗部线性 + 2.4 幂"分段函数，工程上按 tuning 曲线微调——只换表内容，硬件不动 |
| 曲线样例 | x=64/256/512/768 → **72/136/186/224** | 对比线性 `>>2`：16/64/128/192 ⇒ **暗部大幅提亮**（感知域该做的事） |
| 资源 | 3×(1024×8) = 24576 bit ≈ **1 个 BRAM36**（或 2 个 BRAM18） | 无乘法器、无 DSP、无行缓存 |
| 流水 | **LAT = 1** | BRAM 自带输出寄存器，一拍出结果 |
| bypass | **等延迟旁路**（1 拍链） | 语义 = 关曲线不关位宽 → 线性 10→8（`min(round(v/4), 255)`，**必须饱和**，见踩坑 1） |

## 设计要点

1. **LAT=1 与反压冻结**：BRAM 自带输出寄存器，`dout <= {LUT_R[aR], LUT_G[aG], LUT_B[aB]}` 一拍出结果；**`run_en` 直接当 BRAM 读使能（EN）** → 冻结时输出原地保持。⇒ 这就是"LAT=1 核当输出寄存器"的正确做法：**有使能就用使能**，不需要额外 hold 寄存器（对比 M3 的 DPC：那里没有 BRAM 使能可用，才必须配 `hold_in`）。
2. **为什么必须 3 份表副本**：RGB 三通道要**同拍**各查一次，而一个 BRAM18 只有 2 个读口（TDP）→ 3 份副本。这是伪代码漏掉的一点，也是"为什么不做成一张 1024×24 的大表"的答案（三个通道地址不同，拼字宽救不了）。
3. **bypass 语义 ≠ CCM/降噪**：Gamma 是位宽缩减出口，下游要 8bit ⇒ **bypass 只能关曲线、不能关位宽**，实现方式是线性 10→8（`min((v+2)>>2, 255)`，**round-half-up + 饱和**），**物理上做不到"输入原样输出"**。
4. **等延迟旁路 ⇒ 可任意拍切换**（LAT=1，两路延迟严格相等）；TB 场景 E（帧间三段不排空）与 F（**帧中间热切换**）都实测通过。三个模块的对照：

   | 模块 | 处理路径延迟 | bypass 实现 | 切换 |
   |---|---|---|---|
   | 降噪 | `K·W+K+3` ≈ 上万拍 | 排空点切换 | 禁热切换 |
   | CCM | 2 拍 | 等延迟旁路 | 可任意拍切 |
   | **Gamma** | **1 拍** | **等延迟旁路** | **可任意拍切** |

5. **表内容静态化（用户拍板）**：曲线是确定值，直接 `$readmemh`。只有"曲线随场景切换（sRGB/2.2/厂商曲线/曝光档）"或"上板免重综合调曲线"才升级成 AXI-Lite 写表——BRAM 结构不变，只换内容。
6. **三级串联验证**：`--img` 模式的数据生成把 **M3 链 → CCM → Gamma** 真串起来（跨模块 import 上游 Python 模块），跑的是真实级联数据，不是孤立测试向量。

## 踩坑记录（四条）

1. **★ bypass 线性转换缺饱和 → 最亮的两个值回绕成黑**（**用户提问挖出来的真 bug**）：`(v + 2) >> 2` 在 `v = 1022/1023` 时得到 **256**，超出 8bit → 直接截位**回绕成 0**（最亮像素变纯黑）。**修法**：算进多留 1 位的临时量，再 `> 255 ? 255 : ...` 饱和。
   **为什么自检 TB 没抓住**：TB 的期望函数 `lin8p()` 里写的是**同一个表达式**、同样赋给 8bit → 两边同错 → 逐位比对"通过"。**这是 golden 与 DUT 共享同一 bug 的经典盲区**。
   **补齐的防线**：TB 增加 **bypass 穷举段**（1024 值落盘 `gamma_out_byp.txt`），`verify_gamma.py` 新增**判据 2b**：用 **Python 独立算** `min((v+2)//4, 255)` 逐项对比 → 现在 1024 值 0 误差。
2. **TB 文件句柄：两个 `initial` 分开 `$fopen` 时，后一个句柄的写入全部丢失**（`gamma_out_byp.txt` 被创建但 **0 字节**，而 `$fwrite` 调用计数是 1024）。**修法**：把两个 `$fopen` 合进**同一个 `initial` 块**（并打印句柄值确认非 0）。定位方式是加 `bw_n` 写计数打印——"文件建了但没内容"要同时看**句柄有效性**和**写入次数**。
3. **iverilog：移位量用无宽度常量时，拼接操作数被判"宽度不定"**：`{ (v0+2)>>2, (v1+2)>>2 }` 直接报 `Concatenation operand has indefinite width`（3 个错、编译失败）。**修法**：先算进定宽 `reg`/`wire` 再拼接。CCM 没踩到是因为那里没有"拼接 + 移位"组合。
4. **伪代码的资源估算要逐行核算**：`256×8 = 2048 bit` 被写成"半个 BRAM18"（实际 11%），且漏了"三通道三个读口 → 3 份副本"。**资源估算要写单位、要和器件原语容量对齐**，否则选型结论会偏。

```powershell
cd Gamma
# 1) 协议 TB（6 场景 + bypass 帧间/帧内切换）

python make_gamma_data.py --img

```

## 面试点清单

1. **Gamma 干什么**：把线性光信号编码成显示域（感知均匀）——不改变物理信息，改变的是"码值怎么分配动态范围"
2. **为什么锐化在 Gamma 之后、降噪在之前**：锐化是视觉量（感知域）；而**噪声会被 gamma 放大**，所以降噪必须在 Gamma 前
3. **为什么用 LUT 不算 `x^2.2`**：无硬件原语（要 exp/log 或 CORDIC）；且**顺手把 10→8 位深压缩办了**（表内容预存 round 值 ⇒ 零成本零偏置）
4. **资源换算**：1024×8 = 8192 bit ≈ 半个 BRAM18；**但三通道要三个读口 → 3 份副本**（24576 bit ≈ 1 个 BRAM36）
5. **LAT=1 的反压**：BRAM 自带输出寄存器，用读使能当冻结门控；**有使能用使能，没有才要 hold_in**（与 DPC 的对照）
6. **bypass 的语义边界**：位宽缩减出口不能"关位宽"（下游契约不可破）→ bypass 走线性 10→8
7. **曲线可配的三条路**：静态 .coe（本实现）/ 多套表切换 / AXI-Lite 动态写表——成本递增，按需求选
8. **sRGB vs 纯 2.2**：真 sRGB 是分段函数（暗部线性 + 2.4 幂），工程上按 tuning 曲线微调；只换表内容，硬件不动
